## 3. Core (A단계)

### 3.1 기록 목록과 분석 캐시 (`RecordLibrary`)

- 목록은 `RecordCatalog.List`(머리·요약만 읽음)로 만들고 **개수 제한 없이** 최신순. 화면은 30줄씩 더 보여 준다.
- 분석은 백그라운드에서 **한 번에 하나**, 화면에 보이는 줄부터 (요청 순서 큐, 보이지 않게 된 요청은 뒤로). 캐시 키는 M5 `RecentRecords`와 같다: (측정 ID, 수명, 끝 사유, `notes.jsonl` 길이). 분석 결과는 파일에 저장하지 않는다(M4 B1).
- 캐시 상한: 분석 결과 요약(등급·문장·끊김 수·최장·첫 메모)은 전부, **전체 분석 결과(회차 판정 포함)는 최근 연 2개만** 둔다 (12시간 기록 하나가 수십 MB).
- 지금 도는 측정은 분석하지 않고 "측정 중"으로 둔다 (열면 측정 화면으로).
- 읽기 실패·손상은 줄에 표시하고 목록 끝에 "읽지 못한 기록 n개"를 둔다. 읽지 못한 폴더도 목록에서 빼지 않는다 (사용자가 폴더를 열어 볼 수 있게).
- `RecentRecords`(홈 3개)는 `RecordLibrary`의 앞 3개를 쓰게 바꾼다 (같은 캐시, 분석 두 번 하지 않음).
- 목록 갱신: 앱 시작, 측정 끝, 메모 고침, 기록 화면 진입 때. 파일 감시는 하지 않는다.

### 3.2 기록 상세 (`RecordView.Detail`)

입력은 `MeasurementRecord` + `AnalysisResult`. 결론(등급·문장·알림 코드 → 쉬운 말), 기간·구성·예상 연결·저장 위치 종류, 무결성 안내(누락 조각, 손상 줄 수, 끝 기록 없음), 통계:

| 줄 | 출처 | 규칙 |
| --- | --- | --- |
| 판정별 끊김 수·최장·평균 (N3) | `VerdictStats` | 최소 길이 기준, 열린 끝 개수는 따로 ("최장 2분 이상") |
| 대상별 손실률·평균·최대 지연·최대 연속 손실·마지막 성공/손실 시각 (N9) | `TargetStats` | 값 없음은 "값 없음"(0 아님), 손실률 옆에 "100번 중 n번" |
| 관측 충족 | `Coverage` | 판정 가능한 회차 / 관측해야 했던 회차 |

끊김 목록은 `Episodes` 순서 그대로. 한 줄: 시작 시각, 길이(최소~최대, 열린 끝은 "~이상"), 판정(혼합이면 "여러 판정"), 구간 후보(없으면 사유). 끊김이 없으면 "이 측정에서는 끊김이 관측되지 않았습니다" + 관측 충족 줄 (근거 없이 좋다고 하지 않음).

### 3.3 구간 상세 (`EpisodeDetail`, M4 B4)

- 앞뒤 **2회차**와 구간 회차의 대상별 응답(성공 n ms / 응답 없음 / 검사 오류 / 공백). 구간이 9회차보다 길면 처음 3·마지막 3회차만 두고 "가운데 n회차 생략".
- 측정 처음·끝에 붙은 구간은 있는 만큼만 (앞 회차 없음 표시). 공백이 끼면 공백 줄을 그대로 둔다 (공백을 정상으로 그리지 않음).
- 시작 회차의 대상별 경로: 유형(유선·무선·기타·경로 없음). **인터페이스 번호·어댑터 이름은 화면에만, 복사에는 넣지 않는다.**
- 링크 근거: 구간 [시작 − 3초, 끝 + 3초]와 겹치는 링크 다운·업, 최대 8건 (넘으면 "외 n건").
- 겹친 증상 표시와 메모.
- 복사 텍스트: 측정 시작 시각, 구간 시각·길이·판정·후보, 대상 **이름과 역할**(주소 없음), 주변 회차 표, 링크 근거 요약. 데모 시나리오 전부에서 주소·어댑터 이름이 없음을 G2로 검사.

### 3.4 두 측정 비교 (`MeasurementComparison`, F6)

| 조건 | 처리 |
| --- | --- |
| 대상 대응 | **역할 + 주소**가 같은 대상끼리 (ID·이름은 구성마다 다를 수 있음). 한쪽에만 있는 대상은 "비교 안 함" 목록으로 |
| 공통 대상 없음 | 대상 표 없이 등급·끊김 수만 비교하고 "공통 대상이 없어 대상별 비교를 하지 않습니다" |
| 측정 주기 다름 | 비교는 하되 "측정 주기가 달라(1초 / 2초) 연속 손실 횟수는 그대로 비교하기 어렵습니다". 연속 손실은 횟수와 함께 경과 시간 범위로 |
| 길이 차이 큼 (짧은 쪽 < 긴 쪽의 1/4) | "측정 길이가 많이 달라 끊김 수를 그대로 비교하기 어렵습니다" + 시간당 끊김 수를 함께 |
| 예상 연결 유형 다름 | 알림만 (유선 vs 무선 비교가 흔한 쓰임) |
| 읽기 상태 | 둘 다 읽혀야 함. 손상은 경고와 함께 비교, 읽지 못함·측정 중은 고를 수 없음 |
| 같은 측정 둘 | 고를 수 없음 |

표 값은 `TargetStats`·`VerdictStats`·`GradeResult` 그대로 (새 계산 없음). "더 좋음/나쁨" 화살표는 손실률·연속 손실·끊김 수에만, 차이가 작으면(손실률 0.5%p 미만, 끊김 수 같음) 표시하지 않는다. 지연은 값만 나란히 (회선·대상이 같아야 의미가 있어 우열을 단정하지 않음).

### 3.5 메모 고치기

- 끝난 측정의 증상 표시마다 메모를 고친다. 쓰기는 M5 `RecordNotes.AppendMemo`(그 측정의 마지막 조각 폴더의 `notes.jsonl`에 덧붙임, 마지막 줄이 이김). 빈 글 = 지움, 200자 넘으면 잘라 저장하고 알림 (M5와 같음).
- 측정 중인 기록은 기록 화면에서 고치지 않는다 (측정 화면의 메모 경로).
- 쓰기 실패는 칸 아래 오류 + 화면 값은 그대로 (저장되지 않은 것을 저장된 것처럼 보이지 않음).
- 다른 위치에서 연 기록도 고칠 수 있다 (그 폴더에 쓰기, 실패면 위와 같음).

### 3.6 진단 기록 목록 (`DiagnosisStore.List`)

- 진단 기록 폴더의 기록을 최신순으로 (손상은 건너뛴 수로). 줄: 결론 머리말, 시각, 측정 중이었으면 "측정 중 진단" 표시.
- 다시 보기: 저장된 검사 판정으로 `Conclude`를 불러 결론 카드·검사 카드를 **읽기 전용**으로 그린다(그 자리 도구·비우기 단추 없음: 지난 결과에 대한 시스템 동작을 권하지 않음). 저장된 결론 번호와 다르면(엔진 버전 차이) 저장된 번호의 머리말을 쓰고 "이 버전에서 다시 만든 결론과 다릅니다"를 붙인다.
- 측정 상세에는 `measurementId`가 그 측정인 진단만 "이 측정 중 진단 n개".

### 3.7 다른 위치의 기록 열기

- 버튼: 폴더 선택 대화상자(WinUI `FolderPicker`, 창 핸들 연결). 시작 인수 `--open-record <폴더>`도 같은 경로 (G3는 인수로).
- 그 폴더(조각 하나)와 같은 측정 ID의 이웃 조각(`id~n`)을 `RecordReader`로 읽는다. 새 형식이 아니면 "NetPulse 기록 형식이 아닙니다" (기존 앱 CSV 읽지 않음).
- 연 기록은 이번 실행 동안 목록 맨 위 "다른 위치" 묶음에 둔다 (설정에 기억하지 않음). 경로는 앱 기록(app-log)에 남기지 않는다 (사용자 경로).

## 4. 앱 (B단계)

### 4.1 기록 화면 배치

```
머리: "기록" + [측정 목록 | 진단 기록] 선택 + [비교] [다른 위치의 기록 열기]
목록: 줄마다 [등급 배지] 시작 시각 · 길이 · 구성 / 한 문장 / 끊김 n번 · 최장 · 첫 메모 / 상태 칩
      → 줄을 누르면 상세 (같은 화면 안, 뒤로 = 목록, 스크롤·선택 유지)
상세: 결론 카드(등급 + 문장 + 관측 충족) │ 통계 카드
      타임라인 카드 (읽기 전용, 확대·이동·처음으로, 증상·링크 마커)
      끊김 목록 카드 (줄 펼침 → 구간 상세 + [상세 복사]) │ 증상 표시와 메모 카드 (고치기)
      이 측정 중 진단 카드 · [기록 폴더 열기]
비교: 목록에서 두 개 고르기 → 비교 표 (공통 대상별, 등급·끊김, 조건 알림)
진단 기록: 줄 → 읽기 전용 결론·검사 카드 (M6 부품 재사용)
```

- 넓으면 상세 카드를 두 열, 150%·좁으면 한 열 (M5 홈과 같은 기준 `Size.HomeTwoColumns`).
- 타임라인을 끊김 줄과 잇는다: 끊김 줄을 고르면 타임라인이 그 구간으로 이동·강조, 타임라인의 띠를 누르면 그 끊김 줄로.
- 비교 고르기: 목록 줄의 선택 상자 둘(키보드 Space), 둘 고르면 [비교] 켜짐. 고를 수 없는 줄(측정 중·읽지 못함)은 선택 상자 꺼짐 + 이유.

### 4.2 들어오는 길

- 탐색 "기록" → 목록. 홈 최근 측정 줄 → 그 기록 상세. 홈 "전체 보기" → 목록.
- 측정 화면 결과 카드 "기록에서 자세히 보기" → 방금 끝난 기록 상세 (M5의 "다음 단계에서" 문구 교체).
- 진단 화면의 "기록 폴더 열기"는 그대로 (M6).

### 4.3 상태표

| 상태 | 목록 | 상세 |

### 4.4 키보드와 화면 읽기

목록은 위·아래 화살표로 줄 이동, Enter로 열기, Space로 비교 선택. 상세의 끊김 줄은 Enter/Space로 펼침. Esc = 뒤로(상세 → 목록). 줄의 화면 읽기 이름: "11월 13일 오후 1시 20분, 60분, 등급 좋음, 끊김 2번, 최장 12초". 타임라인 키보드 조작은 M5와 같다.

### 4.5 부품

기록 줄(선택 상자 + 줄 단추), 끊김 줄(펼침), 비교 표(대상 행 × 두 측정 열, 화살표 아이콘 + 글), 등급 배지(M5 재사용). 색만으로 구별하지 않는다.

## 5. 성능

측정 화면 bench(12시간 기록)에 구간을 더한다. 기준은 M5와 같다(전환 최대 50 ms, 33 ms 초과 2회).

- `records-enter`: 기록 화면 첫 진입 (기록 40개 목록).
- `records-open`: 12시간 기록 상세 열기 (분석은 백그라운드, 프레임만 잼) — 분석 시간은 따로 기록 (M5 기준 95백분위 500 ms를 넘으면 "분석 중" 상태가 보인다는 것을 G5 캡처로).
- `records-timeline`: 상세 타임라인 전체 보기 → 확대 → 이동 10번.
- `records-compare`: 비교 표 열기.

목록 40개 준비는 데모 기록을 시험 준비 단계에서 만든다 (bench 실행 안에서 만들지 않음).

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- `RecordLibrary`: 개수 제한 없음·최신순·조각 묶기, 분석 한 번에 하나, 보이는 줄 우선, 캐시 키(메모 고침 → 다시 분석), 전체 결과 캐시 2개 상한, 측정 중 분석 안 함, 읽지 못한 폴더도 목록에.
- `RecordView`: 통계 줄(값 없음, 열린 끝 "~이상", "100번 중 n번"), 끊김 없음 문장, 무결성 안내 문구.
- `EpisodeDetail`: 앞뒤 2회차, 긴 구간 생략, 처음·끝 구간, 공백 끼임, 링크 근거 ±3초·8건 상한, 겹친 증상, 복사 텍스트에 주소·어댑터 이름 없음(데모 시나리오 전부).
- `MeasurementComparison`: 3.4 표 전부(대상 대응·없음·주기·길이·연결 유형·읽기 상태·같은 측정), 화살표 임계.
- 메모: 고침 → 다시 읽기, 빈 글 지움, 200자, 쓰기 실패.
- `DiagnosisStore.List`: 최신순, 손상 건너뜀 수, `measurementId` 묶기, 다시 보기 결론 = 저장 결론(다르면 안내).

### 7.2 G3 (`M7FlowTests`, 로컬)

1. **기록에서 다시 열기**: 데모 측정 → 중지 → 결과 카드 "자세히 보기" → 상세 값(등급·문장·끊김 목록·통계) = 시험이 기록 파일을 Core로 다시 분석한 값 → 앱 재시작 → 목록에서 같은 기록 → 같은 값.
2. 목록: 준비한 기록 셋(정상·끊김·끝 기록 없음·손상·읽지 못함) → 줄 값과 칩 = 기대값. 30개 넘으면 "더 보기".
3. 끊김 펼침 → 구간 상세 = `EpisodeDetail` → [상세 복사] → 실제 클립보드 = 복사 텍스트 (M6과 같은 보관·복원).
4. 끊김 줄 ↔ 타임라인 이동 (보이는 범위가 그 구간을 포함).
5. 메모 고치기 → 다시 열기·재시작 뒤 고친 글, 빈 글 = 지움.
6. 비교: 두 기록 → 표 = `Compare`. 조건 다른 쌍(대상·주기) → 알림. 측정 중·읽지 못한 줄은 고를 수 없음.
7. 진단 기록: 진단 둘(하나는 측정 중) → 목록 → 다시 보기 = 저장 결론, 측정 상세의 "이 측정 중 진단 1개".
8. `--open-record <폴더>` → 다른 위치 묶음 → 상세 = 다시 분석. 형식이 아닌 폴더 → 오류.
9. 홈 최근 측정 줄 → 그 기록 상세.
10. 키보드만으로: 목록 이동·열기·끊김 펼침·뒤로·비교 선택.

## 9. 대안

- 목록과 상세를 두 열로 나란히(마스터-디테일): 1280×800·150%에서 상세가 좁아 타임라인이 읽히지 않아 한 화면 안 전환으로.
- 분석 결과를 파일로 캐시: M4 B1(읽을 때마다 계산, 분석기 버전이 바뀌면 달라짐)에 어긋나 메모리 캐시만.
- 비교 대상 대응을 ID로: 구성을 고치면 ID가 바뀌어 같은 공유기를 다른 대상으로 봄. 역할 + 주소로.
- 다른 위치 기록을 목록에 기억: 경로를 설정에 남기게 되어 이번 실행 동안만.
