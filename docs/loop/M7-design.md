## 3. Core (A단계)

### 3.1 기록 목록과 분석 (`RecordLibrary`) [1-3, 1-9]

**목록**: `RecordCatalog.List`(머리·요약만 읽음)로 **개수 제한 없이** 최신순. 화면은 30줄씩 더 보여 준다. 같은 측정 ID라도 **출처가 다르면 다른 항목**이다: 알려진 저장 위치(기본·대체)의 조각 묶음 하나, 다른 위치에서 연 것은 그 선택마다 하나 (3.7).

**출처 도장(캐시 키)**: (측정 ID, 출처 종류, **조각 폴더 전체 경로 집합**, 조각마다 `measurement.json`·`summary.json`·회차 파일·이벤트 파일·`notes.jsonl`의 (길이, 마지막 쓰기 시각)). M5 `RecentRecords`의 열쇠(ID·수명·끝 사유·노트 도장)를 이것으로 넓힌다. 새로 고침 때 도장만 다시 재고, 바뀐 항목만 다시 분석한다 (회차 파일 복구·손상 변화·메모 고침을 모두 잡음). 분석 중 도장이 바뀌면 그 결과를 버리고 다시 큐에 넣는다.

**분석 큐**: 백그라운드 작업 **하나**. 우선순위 ① 열린 상세·비교의 기록 ② 화면에 보이는 목록 줄 ③ 나머지(목록 순서). 보이지 않게 된 줄의 요청은 ③으로 내린다. 분석 결과는 파일에 저장하지 않는다 (M4 B1).

**보유 범위(메모리)**: 목록 요약(등급·문장·끊김 수·최장·첫 메모·끝 사유·손상 요약)은 전부 둔다. **원본 기록(회차·이벤트) + 전체 분석 결과**는 "열린 것"만: 상세 1개 또는 비교 2개, 그리고 바로 전에 닫은 것 1개(뒤로 갔다 다시 여는 경우) — 최대 3개. 그 밖은 요약만. 세 번째를 열면 가장 오래 쓰지 않은 것을 놓는다.

**측정 중** 기록은 분석하지 않고 "측정 중"(열면 측정 화면). **읽지 못한** 폴더도 목록에서 빼지 않고 끝에 "읽지 못한 기록 n개" (폴더를 열어 볼 수 있게).

`RecentRecords`(홈 3개)는 `RecordLibrary`의 앞 3개를 쓴다 (같은 캐시). 목록 갱신: 앱 시작, 측정 끝, 메모 고침 완료, 기록 화면 진입. 파일 감시는 하지 않는다.

### 3.2 기록 상세 (`RecordView.Detail`) [1-8, 1-12]

입력은 `MeasurementRecord` + `AnalysisResult`.

- **결론**: 등급 + 한 문장 + 알림 코드 → 쉬운 말, 관측 충족(판정 가능한 회차 / 관측해야 했던 회차).
- **끝 사유와 저장 상태(따로)**: 완료 / 사용자 중지 / 오류 종료 / 끝 기록 없음(비정상 종료일 수도, 요약 쓰기 실패일 수도). 저장 상태: 저장 못 한 회차 수, 봉인 실패.
- **대상 구성**: 기록 머리의 대상(역할·방식·포트·순서), 측정 주기·제한시간, 예상 연결 유형. **과거 구성 이름은 기록에 없으므로 쓰지 않는다** (현재 프로필 이름으로 채우지 않음). 목록 줄은 "대상 3개 · 로컬 1 · 외부 2"처럼 구성으로 요약 [1-8].
- **손상 알림(구별)** [1-12]: 회차 손상(`Damage.Total`과 종류별 수) → "이 측정의 회차 n줄을 읽지 못해 그 회차는 관측하지 못한 것으로 셉니다", 이벤트 손상(`DamagedEvents`) → "경로·링크 근거 n줄을 읽지 못해 끊김 상세의 근거가 빠질 수 있습니다", 메모 손상(`DamagedNotes`, `SymptomMarks`의 무시한 줄) → "메모 n줄을 읽지 못했습니다", 누락 조각(`MissingSegments`), 읽지 못한 파일.
- **통계**:

| 줄 | 출처 | 규칙 |
| --- | --- | --- |
| 판정별 하위 구간 수·최장·평균 (N3) | `VerdictStats` | 최소 길이 기준, 열린 끝 개수 따로. **"끊김 n번"(구간 수)과 "판정별 하위 구간 수"가 다를 수 있음을 한 줄로 설명** (혼합 끊김은 하위 구간 여럿) [1-4] |
| 대상별 손실률·평균·최대 지연·최대 연속 손실·마지막 성공/손실 시각 (N9) | `TargetStats` | 값 없음은 "값 없음"(0 아님), 손실률 옆에 "100번 중 n번" |

- **지연 추세** [1-7]: 대상별 5분 창 중앙값(`LatencyBaseline.WindowMedians`) 선 그래프. 공백·성공 없는 창은 선을 끊는다(이어 그리지 않음). 기준선 없는 대상(성공 20개 미만)은 "값이 적어 추세 없음". 그래프 아래 고정 안내: "지연 상승 판정은 측정 전체 대비 순간 상승만 잡습니다. 측정 동안 서서히 나빠진 것은 이 추세로 보세요." 판정·등급에는 쓰지 않는다.
- **끊김 목록**: `Episodes` 순서. 한 줄: 시작 시각, 길이(최소~최대, 열린 끝은 "~이상"). 하위 구간이 하나면 판정·후보. **둘 이상이면 "여러 판정 (n)"과 하위 구간의 판정 이름들**, 후보는 줄에 쓰지 않고 펼침에서 하위 구간마다 (서로 다른 후보를 하나로 대표하지 않음) [1-4]. 끊김이 없으면 "이 측정에서는 끊김이 관측되지 않았습니다" + 관측 충족 줄 (근거 없이 좋다고 하지 않음).

### 3.3 구간 상세 (`EpisodeDetail`, M4 B4) [1-4, 1-6]

- **하위 구간 목록**(시간순): 판정, 회차 범위, 길이(최소~최대), 후보 또는 후보 없음 사유.
- 앞뒤 **2회차**와 구간 회차의 대상별 응답(성공 n ms / 응답 없음 / 검사 오류 / 공백). 구간이 9회차보다 길면 처음 3·마지막 3회차만 두고 "가운데 n회차 생략". 측정 처음·끝에 붙은 구간은 있는 만큼만. 공백은 공백 줄로 (정상으로 그리지 않음).
- 시작 회차의 대상별 경로 유형(유선·무선·기타·경로 없음). 인터페이스 번호·어댑터 이름은 화면에만.
- 링크 근거: [시작 − 3초, 끝 + 3초]와 겹치는 링크 다운·업, 최대 8건 (넘으면 "외 n건"). 이벤트 손상이 있으면 "근거 일부를 읽지 못함".
- 겹친 증상 표시와 메모 (화면에만).
- **복사 텍스트** [1-6]: 대상은 **역할과 중립 순번**("로컬 대상 1", "외부 대상 2")으로만 쓴다. 사용자가 붙인 대상 이름·주소·어댑터 이름·인터페이스 번호·메모는 넣지 않는다 (이름은 자유 입력이라 주소가 들어갈 수 있음). 포함: 측정 시작 시각, 구간 시각·길이·하위 구간(판정·후보 종류), 주변 회차 표, 링크 근거 개수·방향. 대응표("외부 대상 2 = 화면의 OO")는 화면에만.

### 3.4 두 측정 비교 (`MeasurementComparison`, F6) [1-1, 1-2]

**대상 대응**: 역할 + 주소 + **측정 방식(ICMP / TCP + 포트)**이 모두 같은 대상끼리. 하나라도 다르면 대응하지 않고 "비교 안 함" 목록에 사유와 함께 (예: "같은 주소지만 측정 방식이 다름: ICMP / TCP 443"). 공통 대상이 없으면 대상 표 없이 측정 단위 지표만.

**측정 조건 차이** (표 위 알림, 모두 해당하는 것 전부):

| 조건 | 알림 |
| --- | --- |
| 측정 주기 다름 | "측정 주기가 달라 (1초 / 2초) 연속 손실 횟수를 그대로 비교할 수 없습니다" |
| 제한시간 다름 | "응답 제한시간이 달라 (1초 / 2초) 손실률의 뜻이 다릅니다" |
| 길이 다름 (짧은 쪽이 긴 쪽의 1/2 미만) | "측정 길이가 달라 끊김 수는 시간당으로 봅니다" |
| 관측 충족 부족 (어느 쪽이든 판정 가능 회차가 관측해야 했던 회차의 80% 미만) | "관측하지 못한 시간이 많아 비교가 부정확합니다" |
| 손상·끝 기록 없음 | "한쪽 기록에 읽지 못한 부분이 있습니다" |
| 예상 연결 유형 다름 | "예상 연결 유형이 다릅니다 (유선 / 무선)" (흔한 쓰임이라 알림만) |

**지표별 우열 표시** (화살표 + "더 적음/더 많음" 글. 차이가 임계 안이거나 억제 조건이면 값만):

| 지표 | 비교 단위 | 임계 | 억제 조건 |
| --- | --- | --- | --- |
| 등급 | 등급 순서 | 등급이 다름 | 어느 쪽이든 "관측 부족"·"판단 불가" |
| 끊김 수 | **시간당 끊김 수** (원시 횟수는 값만) | 시간당 0.5번 이상 차이 | 관측 충족 부족, 손상 |
| 최장 끊김 | 최소 길이 | 10초 이상 차이 | 어느 쪽이든 그 최장이 열린 끝, 주기 다름 |

**고를 수 있는 것**: 둘 다 읽힌 기록(손상은 알림과 함께). 읽지 못함·측정 중·같은 기록 둘은 고를 수 없다.

### 3.5 메모 고치기 [1-10]

- 끝난 측정의 증상 표시마다. 쓰기는 M5의 `NotesWriter`(앱에 하나인 **직렬 작업**, 실패 시 1초·3초 재시도, 그다음 유실)를 **측정 화면과 같은 인스턴스**로 쓴다 (MeasurementHost에서 꺼내 공유 서비스로, 동작은 그대로).
- 상태: 고치는 중(초안) → 저장 중 → 저장됨 / 저장 못 함. 저장 못 하면 칸 아래 오류와 초안 유지 + [다시 저장]. 화면 값은 저장 완료 뒤에만 바뀐다.
- 초안 수명: 같은 상세 안에서 다른 메모를 열거나 끊김을 펼쳐도 유지. **뒤로·다른 화면으로 가면** 저장하지 않은 초안은 버리되, 버리기 전 한 줄 알림("저장하지 않은 메모를 버렸습니다"). 창을 닫을 때 저장 중인 쓰기는 M5와 같이 `DrainAsync`로 기다린다 (초안은 저장하지 않음).
- **오래된 완료 무시**: 쓰기 요청마다 (기록 출처, 표시, 요청 번호). 완료가 와도 그 표시의 더 새 요청이 있으면 화면에 반영하지 않는다. 완료 뒤 그 기록의 도장을 다시 재 목록·상세를 갱신 (3.1).
- 빈 글 = 지움, 200자 넘으면 잘라 저장하고 알림 (M5와 같음). 측정 중인 기록은 기록 화면에서 고치지 않는다.
- 다른 위치에서 연 기록도 그 폴더에 쓴다 (권한 없으면 저장 못 함).

### 3.6 진단 기록 다시 보기 (`StoredDiagnosisView`) [1-5]

진단 기록은 검사 판정·대상 슬롯 결과·결론 번호·다른 가능성 번호만 담고 문장·주소는 없다(M4 C4). 그래서 저장 결과 전용 모델을 둔다:

- **저장된 결론**: 저장된 결론 번호의 머리말·무게(`DiagnosisTexts.Head`), 저장된 다른 가능성 번호의 머리말들. 이것이 화면의 주 결론이다.
- **검사 카드**: 저장된 판정·실행 상태·사유 코드. 대상은 **"대상 1·2" 순번**으로만 (현재 설정의 주소를 붙이지 않음: 그때 검사한 주소가 아닐 수 있음).
- **설명 문장과 해볼 것**: 저장된 판정으로 `Conclude`를 다시 불러 **번호가 저장된 번호와 같을 때만** 그 문장·단계를 "그때 결과에 대한 설명"으로 붙인다. 다르면 문장·단계를 붙이지 않고 "저장된 결론과 지금 다시 해석한 결론이 달라 설명을 붙이지 않습니다"만 (원인을 엔진 버전 차이로 단정하지 않음).
- 해볼 것 위에 "지금 상태는 빠른 진단을 다시 돌려 확인하세요" + [빠른 진단 열기]. 그 자리 도구(DNS 비우기·설정 열기)는 없다 (지난 결과에 시스템 동작을 권하지 않음).
- 목록: 최신순, 손상은 건너뛴 수로. 측정 상세에는 `measurementId`가 그 측정인 진단만 "이 측정 중 진단 n개".

### 3.7 다른 위치의 기록 열기 [1-11]

- 버튼: 폴더 선택 대화상자(WinUI `FolderPicker`, 창 핸들 연결). 시작 인수 `--open-record <폴더>`도 같은 경로 (G3는 인수로).
- **조각 찾기**: 고른 폴더의 측정 ID로 ① 고른 폴더의 상위 폴더 ② 알려진 저장 위치(기본·대체)에서 같은 ID 조각(`id`, `id~n`)을 찾는다.
- **일치 검사**: 조각마다 `measurement.json`의 측정 ID·시작 시각·대상 목록·주기·제한시간이 같아야 한 기록으로 묶는다. 다른 조각은 빼고 "머리가 다른 조각 n개를 뺐습니다". 같은 조각 번호가 두 곳에 있으면 **고른 폴더 쪽**을 쓰고 "같은 조각이 두 곳에 있어 고른 쪽을 읽었습니다". 확보한 조각만 읽었으면 누락 조각 안내(기존 `MissingSegments`).
- 새 형식이 아니면 "NetPulse 기록 형식이 아닙니다" (기존 앱 CSV 읽지 않음).
- 연 기록은 이번 실행 동안 목록 맨 위 "다른 위치" 묶음 (설정에 기억하지 않음).
- **폴더 열기 허용 범위**: 이번에 읽은 조각 폴더들 정확히 (상위 폴더 아님). M6 `FolderPolicy`에 실행 중 추가 허용 목록으로.
- **경로를 남기지 않음**: 앱 기록(app-log)·오류 기록·진단 값(`Diag`)에 선택 경로를 쓰지 않는다 ("external"만). 실패 기록에도 없음을 G3에서 검사.

## 4. 앱 (B단계)

### 4.1 기록 화면 배치

```
머리: "기록" + [측정 목록 | 진단 기록] 선택 + [비교] [다른 위치의 기록 열기]
목록: 줄마다 [선택 상자] [등급 배지] 시작 시각 · 길이 · 대상 구성 / 한 문장 / 끊김 n번 · 최장 · 첫 메모 / 상태 칩(끝 사유·무결성)
      → 줄을 누르면 상세 (같은 화면 안, 뒤로 = 목록, 스크롤·선택 유지)
상세: 결론 카드(등급 + 문장 + 관측 충족 + 끝 사유·저장 상태) │ 통계 카드
      손상 알림 배너 (있을 때)
      타임라인 카드 (읽기 전용, 확대·이동·처음으로, 증상·링크 마커)
      지연 추세 카드 (5분 창 중앙값, 안내 한 줄)
      끊김 목록 카드 (줄 펼침 → 구간 상세 + [상세 복사]) │ 증상 표시와 메모 카드 (고치기)

비교: 두 개 고르기 → 조건 알림 → 측정 단위 지표 → 대응 대상 표 → 비교 안 한 대상
```

- 비교 고르기: 목록 줄의 선택 상자 둘(키보드 Space), 둘 고르면 [비교] 켜짐. 고를 수 없는 줄은 선택 상자 꺼짐 + 이유.

### 4.4 키보드와 화면 읽기

목록은 위·아래 화살표로 줄 이동, Enter로 열기, Space로 비교 선택. 상세의 끊김 줄은 Enter/Space로 펼침. Esc = 뒤로(상세 → 목록). 줄의 화면 읽기 이름: "11월 13일 오후 1시 20분, 60분, 등급 좋음, 끊김 2번, 최장 12초". 비교 표의 화살표 칸은 "더 적음"·"더 많음"·"비교 안 함(사유)"을 글로도 읽는다. 타임라인 키보드 조작은 M5와 같다.

## 5. 성능 [1-9]

측정 화면 bench(12시간 기록)에 구간을 더한다. 프레임 기준은 M5와 같다(전환 최대 50 ms, 33 ms 초과 2회).

- `records-enter`: 기록 화면 첫 진입 (기록 40개 목록, 요약 캐시 비어 있음).
- `records-open`: 캐시 없는 12시간 기록 상세 열기 (분석은 백그라운드, 프레임만 잼). 분석 시간은 따로 기록.
- `records-switch`: 상세 연 채 목록으로 → 다른 12시간 기록 → 세 번째 기록 (보유 범위 교체).
- `records-nav-during-analysis`: 상세 분석 중 홈 ↔ 기록 이동.
- `records-timeline`: 상세 타임라인 전체 보기 → 확대 → 이동 10번.
- `records-compare`: 캐시 없는 12시간 기록 둘 비교 열기.
- **메모리**: 각 구간 끝과 최대의 전용 메모리. 기준은 M5와 같은 400 MB를 출발점으로 하고, 12시간 둘 비교 실측값을 보고 이 설계 2라운드 또는 구현 중 결정에서 확정한다 (근거 없이 늘리지 않음).

목록 40개(12시간 2개 포함)는 시험 준비 단계에서 만든다 (bench 실행 안에서 만들지 않음).

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- `RecordLibrary`: 개수 제한 없음·최신순, 출처가 다른 같은 ID는 다른 항목, **도장 변화(회차 파일 복구, 손상 변화, 메모 고침) → 다시 분석**, 분석 중 도장 변경 → 결과 버림, 우선순위(상세·비교 > 보이는 줄 > 나머지), 보유 범위 최대 3개·교체, 측정 중 분석 안 함, 읽지 못한 폴더도 목록에. [1-3, 1-9]
- `RecordView`: 끝 사유와 저장 상태 분리, 대상 구성 요약, 손상 종류별 문장(회차만·근거만·메모만), 통계 줄(값 없음, 열린 끝, "100번 중 n번", 구간 수 ≠ 하위 구간 수 설명), 끊김 없음 문장, 혼합 끊김 줄, 추세(공백 끊김, 기준선 없음). [1-4, 1-7, 1-8, 1-12]
- `EpisodeDetail`: 하위 구간 목록, 앞뒤 2회차, 긴 구간 생략, 처음·끝 구간, 공백 끼임, 링크 근거 ±3초·8건 상한, 겹친 증상. **복사**: 데모 시나리오 전부 + **대상 이름에 주소·어댑터 이름을 넣은 구성**에서도 주소·이름·어댑터 이름·메모 없음. [1-6]
- `MeasurementComparison`: 3.4 대응(방식·포트 다름 → 비교 안 함), 조건 알림 전부, 지표별 임계·억제 전부(1시간 1번 vs 3시간 2번처럼 원시 수와 시간당이 반대인 경우 포함), 고를 수 없는 것. [1-1, 1-2]
- 메모: 직렬 쓰기(측정 화면과 같은 인스턴스), 실패·재시도·유실, 오래된 완료 무시, 빈 글 지움, 200자. [1-10]
- `StoredDiagnosisView`: 저장 번호 = 재해석 번호 → 설명 붙음, 다르면 설명 없음·안내, 대상은 순번(현재 설정 주소 없음), 그 자리 도구 없음. `DiagnosisStore.List`: 최신순, 손상 건너뜀, `measurementId` 묶기. [1-5]
- 다른 위치 조각 찾기: 상위 폴더 + 알려진 위치, 머리 불일치 조각 제외, 같은 번호 중복은 고른 쪽, 형식 아님. [1-11]

### 7.2 G3 (`M7FlowTests`, 로컬)

1. **기록에서 다시 열기**: 데모 측정(끊김 있는 시나리오) → 중지 → 결과 카드 "자세히 보기" → 상세 값(등급·문장·끝 사유·끊김 목록·하위 구간·통계) = 시험이 기록 파일을 Core로 다시 분석한 값 → 앱 재시작 → 목록에서 같은 기록 → 같은 값.
2. 목록: 준비한 기록 셋(정상·끊김·끝 기록 없음·회차 손상·근거 손상·읽지 못함·측정 중, 35개) → 줄 값과 칩 = 기대값, 30개 뒤 "더 보기".
3. 끊김 펼침 → 구간 상세 = `EpisodeDetail` → [상세 복사] → 실제 클립보드 = 복사 텍스트 (M6과 같은 보관·복원).
4. 끊김 줄 ↔ 타임라인 이동 (보이는 범위가 그 구간을 포함).
5. 메모 고치기 → 다시 열기·재시작 뒤 고친 글, 빈 글 = 지움. 쓰기 실패(폴더 읽기 전용) → 칸 오류·초안 유지.
6. 비교: 두 기록 → 표 = `Compare`. 조건 다른 쌍(주기·제한시간·방식) → 알림·억제. 측정 중·읽지 못한 줄은 고를 수 없음.
7. 진단 기록: 진단 둘(하나는 측정 중) → 목록 → 다시 보기 = 저장 결론, 측정 상세 "이 측정 중 진단 1개".
8. `--open-record <폴더>` → 다른 위치 묶음 → 상세 = 다시 분석. 머리 다른 조각 섞임 → 안내. 형식 아님 → 오류. **앱 기록·진단 값에 그 경로가 없음.**
9. 홈 최근 측정 줄 → 그 기록 상세.
10. 키보드만으로: 목록 이동·열기·끊김 펼침·뒤로·비교 선택 (`KeyboardTests`).

## 9. 대안

- 목록과 상세를 두 열로 나란히(마스터-디테일): 1280×800·150%에서 상세가 좁아 타임라인이 읽히지 않아 한 화면 안 전환으로.
- 분석 결과를 파일로 캐시: M4 B1(읽을 때마다 계산)에 어긋나 메모리 캐시만.
- 비교 대상 대응을 ID로: 구성을 고치면 ID가 바뀜. 역할 + 주소 + 방식으로.
- 기록에 구성 이름 필드 추가 [1-8]: 기록 형식 계약을 바꾸고 옛 기록은 어차피 이름이 없어, 대상 구성 요약으로.
- 복사에 사용자 대상 이름 포함 [1-6]: 자유 입력이라 식별 정보 제외를 보장할 수 없어 순번으로.
