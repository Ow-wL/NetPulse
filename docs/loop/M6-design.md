# M6 설계 — 진단 화면

1판 · 2026-11-14 · 브랜치 `loop/m6-diagnose` (base `main` `91d366c`)

기획서 8절 M6 행: "빠른 진단, 안내형 결과, 사이트 점검, 보조 기능". 끝났다는 증거: G3, G5. 기준은 `docs/loop-plan.md` 6.1(F1 빠른 진단, F2 사이트 점검), 6.3(N5 안내형 진단), 7.5(화면 구조와 UX), 7.6(접근성), 기능 명세서 `feature-inventory.md` 1~3절. 엔진(검사 일곱, 판정, 결론 12규칙, 사이트 점검, 진단 기록 형식)은 M4에서 만들었고 이번에는 바꾸지 않는다 (진행 알림 하나만 더함, 3.1).

## 1. 목표와 끝났다는 증거

| 목표 | 증거 |
| --- | --- |

## 3. 엔진 쪽 추가 (A단계)

### 3.1 진행 알림

`QuickDiagnosis.RunAsync(…, IProgress<CheckResult>? progress = null)`: 검사 하나가 끝날 때마다(제한시간·오류 포함) 그 결과를 알린다. 판정·결론·반환값은 바꾸지 않는다. 게이트웨이는 어댑터 뒤에 돌므로 진행 순서는 끝난 순서다. 화면은 끝난 검사부터 카드를 채운다.

### 3.2 데모 진단 검사기 (`DemoDiagnosticProbes`)

- 데모 세계의 **지금 시간축 회차**(`DemoTimeBase.Scaled` 초)를 기준으로 시나리오에서 답한다.
  - 어댑터: `network`(유선·무선)와 그 회차 링크 상태. 링크 다운이면 어댑터 내려감.
  - 게이트웨이 Ping: 로컬 역할 대상의 그 회차 결과.
  - TCP·DNS·HTTPS: 외부 역할 대상의 그 회차 결과 (대상 둘 → t1·t2).
  - 네트워크 로그인: 기본 정상.
  - 링크: 그 회차 링크 상태, 로그는 지원, 최근 30분(1,800회차) 안의 다운 여부.
- 선택 블록 `diagnosis`가 있으면 그 값이 이긴다 (시간과 무관한 장면을 위해):

```json
"diagnosis": {
  "adapter": { "up": true, "ipv4": true, "apipa": false, "gateway": true, "dns": true },
  "gateway": "ok",
  "tcp": ["fail", "timeout"], "dns": ["ok", "ok"], "https": ["fail", "fail"],
  "portal": { "status": 302, "body": false },
  "link": { "now": "up", "log": "supported", "recentDown": false },
  "delayMs": { "https": 1500 }
}
```

  값은 `ok`/`fail`/`error`/`timeout`. `timeout`은 그 검사의 제한시간보다 길게 기다려 조율자의 제한시간 경로를 그대로 탄다 (가짜 결과를 만들지 않음). `delayMs`는 진행 중 장면을 위한 지연.
- 사이트 점검의 도메인: `diagnosis.site`(도메인 → `{dns, https}`)에 있으면 그 값, 없으면 `example.com`류 문서용 도메인만 성공·나머지 실패 (`.test`·`.example`·`example.com|net|org`).
- 주소·도메인은 문서용만 쓴다 (기존 시나리오 검증 규칙을 따름).

### 3.3 시스템 동작 (`ISystemActions`)

```csharp
public interface ISystemActions
{
    Task<SystemActionResult> FlushDnsAsync(CancellationToken ct);   // 제한 10초
    SystemActionResult OpenSettings(SettingsPage page);             // Network, Wifi, Proxy
    SystemActionResult OpenFolder(string folder);                   // 기록 폴더만
}
public enum SettingsPage { Network, Wifi, Proxy }
public sealed record SystemActionResult(bool Ok, string? Code);
```

- **실제 구현 (Platform)**: 고정 명령만 실행한다. 사용자 입력이 명령줄에 들어가지 않는다.
  - DNS 비우기: `%SystemRoot%\System32\ipconfig.exe /flushdns`, 셸 없이, 창 없이, 출력은 읽어 버리고 **종료 코드만** 쓴다. 관리자 권한을 요청하지 않는다. 10초 넘으면 끝내고 `timeout`.
  - 설정 열기: 고정 주소 셋(`ms-settings:network-status`, `ms-settings:network-wifi`, `ms-settings:network-proxy`)만 셸로 연다.
  - 폴더 열기: 앱이 아는 기록 위치(세계의 `RecordPaths`, 진단 기록 폴더) 안의 **존재하는 폴더**만 탐색기로 연다. 그 밖이면 거절(`not-allowed`).
- **데모 구현 (Core)**: 실행하지 않고 호출을 기록한다 (`Calls`), 결과는 시나리오의 `diagnosis.flushDns`(`ok`/`fail`/`timeout`, 기본 `ok`). 시험·캡처는 늘 데모 구현이다.
- 사용자 확인: DNS 비우기는 화면이 확인 대화상자를 거친 뒤에만 호스트를 부른다 (7.5 "시스템을 바꾸는 동작만 확인을 묻는다"). 설정·폴더 열기는 확인 없이.

### 3.4 진단 수명 (`DiagnosisHost`, Core.Live)

`MeasurementHost`와 같은 방식의 장면(`DiagnosisSnapshot`)과 `Changed` 알림.

| 상태 | 뜻 |
| --- | --- |
| `Idle` | 실행 전 (지난 결과 있을 수 있음) |
| `Running` | 빠른 진단 중 (끝난 검사 목록) |
| `Done` | 결과 있음 |

- **한 번에 하나**: 실행 중 다시 누르면 무시한다. 취소는 창 닫기·화면과 무관하게 계속 돌고(짧음, 최대 약 6초), 창을 닫으면 취소한다.
- **비교**: 이번 실행의 결과와 바로 앞 결과(같은 앱 실행 안, 또는 진단 기록 폴더의 가장 최근 기록)를 `Compare`. 앞 결과가 기록에서 읽은 것이면 검사 판정만 비교한다 (`StoredDiagnosis`).
- **저장**: 결과가 나오면 `사용자 폴더/diagnoses/diagnosis-<UTC>.json`(M4 C4 형식). 측정 중이면 `MeasurementHost.RunningId`를 `measurementId`로. 저장 실패는 결과 표시를 막지 않고 장면에 `SaveError`(코드)로 남긴다. 같은 초에 두 번이면 파일 이름에 `-2`를 붙인다.
- **사이트 점검**: 별도 상태(`SiteState`: 입력 오류 코드 / 실행 중 / 결과). 빠른 진단과 동시에 돌 수 있다. 입력 검증은 `SiteCheck.Validate`.
- **DNS 비우기 흐름**: `FlushAndRecheckAsync()` → 시스템 동작 → 결과와 상관없이 빠른 진단 다시 → 결과에 메시지("DNS 캐시를 비웠습니다" / "DNS 캐시를 비우지 못했습니다 (사유)")를 붙인다. 진단이 돌고 있으면 끝나기를 기다렸다가 비운다.
- **설정**: `DiagnosisSettings` 기본값 그대로 (설정 화면에서 바꾸기는 M9).

### 3.5 화면용 모델 (`DiagnosisView`, Presentation)

- **결론 카드**: 결론 번호 → 머리 단어(예: 11 "기본 연결 정상", 3 "이름 해석(DNS) 문제", 6 "인터넷 쪽으로 나가지 못함", 12 "진단 근거 부족"), 문장(`Found`), 단계(`Steps`, 번호 목록), 함께 맞은 결론(`AlsoMatched`, "다른 가능성"으로 접어서), 미측정·일부 미확인 알림(`Notes`).
- **결론의 무게**: 1·5·6은 문제(빨강 계열), 2·3·4·7은 주의, 8·9·10은 정보, 11은 정상, 12는 근거 부족(중립). 색만으로 구별하지 않고 머리 단어와 아이콘을 함께.
- **검사 카드**: 검사 이름, 판정 배지, 한 줄 설명(`DiagnosisTexts.Explain(check)`), 대상별 결과(t1·t2 "성공/실패/오류/시간 초과" + 소요 시간), 실행 상태(안 함·시간 초과·오류의 사유). 주소·도메인 값은 보이지 않는다 (사용자가 바꿀 수 있는 기본 대상이라도 화면에는 "대상 1·2", 이유: 복사·캡처·리포트에서 같은 문구를 쓰려고).
- **사유 코드 → 쉬운 말**: `apipa` "자동 할당 주소(169.254)만 있습니다", `no-gateway` "기본 게이트웨이가 없습니다", `no-route` "인터넷 쪽 경로를 찾지 못했습니다", `adapter-down` "어댑터가 내려가 있습니다", `timeout` "제한시간 안에 답이 없었습니다", `dns-HostNotFound` "이름을 찾지 못했습니다" … 모르는 코드는 "기타 사유 (코드)". G2가 엔진·검사기가 낼 수 있는 모든 코드를 덮는지 검사한다.
- **비교 띠**: "지난 검사와 달라진 검사 n개" + 검사마다 "이전 → 지금". 없으면 "지난 검사와 같습니다". 처음이면 없음.
- 문구 원칙: 단정하지 않는다 (M4 결론 문장 그대로), "~일 수 있습니다", 전문 용어 옆에 풀이.

## 4. 앱 (B단계)

### 4.1 진단 화면 배치

```
머리: "진단" + [빠른 진단 시작] (실행 중이면 "검사 중… 3/7")
┌ 결론 카드 (가장 크게) ──────────────────────────┐
│ 아이콘 · 머리 단어 · 문장                         │
│ 해볼 것 1. 2. 3.  [DNS 캐시 비우기](결론 3일 때) │
│ 다른 가능성 ▸ / 알림(미측정…) / 비교 띠          │
│ [결과 복사]  마지막 검사 오후 1:20              │
└──────────────────────────────────────────────────┘
검사 카드 일곱 (넓으면 3열, 좁으면 2열, 150%면 1~2열) — 누르면 펼쳐 대상별 결과
┌ 사이트 점검 ──────────────┐ ┌ 보조 도구 ─────────────────────┐
│ [도메인 입력] [점검]      │ │ DNS 캐시 비우기 (확인 후 실행)  │
│ DNS: 정상 · HTTPS: 실패   │ │ 네트워크 / Wi‑Fi / 프록시 설정  │
└───────────────────────────┘ │ 기록 폴더 열기                 │
                              └────────────────────────────────┘
```

- **상태별 모습**: 처음(실행 전) — 결론 카드 자리에 "아직 진단하지 않았습니다" + 무엇을 검사하는지 한 줄씩 + 시작 단추. 진행 중 — 검사 카드가 끝나는 대로 채워지고 나머지는 뼈대(Skeleton). 결과. 저장 실패 — 결론 카드 아래 경고 배너("진단 결과를 저장하지 못했습니다. 화면의 결과는 그대로입니다").
- 결론 3(DNS)일 때 단계 옆에 DNS 캐시 비우기 단추를 함께 둔다 (안내형: 해볼 것을 그 자리에서).
- 결론 1·5(링크·PC 연결)일 때 "네트워크 설정 열기", 4(로그인)일 때는 단계만 (브라우저를 앱이 열지 않음: 외부 사이트를 열지 않는 규칙).
- 결과 복사: `CopyText`를 클립보드로, 알림 "결과를 복사했습니다".
- DNS 비우기 확인 대화상자: "DNS 캐시를 비울까요? Windows가 기억한 이름 해석 결과를 지웁니다. 인터넷 연결이나 설정은 바뀌지 않습니다. 끝나면 빠른 진단을 다시 돌립니다." [비우기] [취소]. 초점은 취소에.

### 4.2 홈 빠른 진단 카드

홈 오른쪽 열(최근 측정 위, 좁으면 아래)에 작은 카드: 마지막 진단의 결론 머리 단어 + 언제("오늘 오후 1:20") + [진단 열기]. 진단한 적 없으면 "빠른 진단으로 지금 연결을 검사해 보세요" + [진단 시작](진단 화면으로 가서 바로 시작). 측정 중에도 보인다.

### 4.3 측정과의 관계

- 측정 중에도 진단할 수 있다 (게이트웨이 Ping·TCP가 측정과 동시에 나가는 것은 짧고 1회라 측정 판정에 영향 없음). 진단 기록에 측정 Id를 남긴다.
- 측정 화면·기록에 진단을 표시하는 것은 하지 않는다 (M7 기록 화면에서 연결을 보여 줌).

### 4.4 키보드와 화면 읽기

- 시작 단추 Enter, 검사 카드는 탭 순서대로, 펼치기는 Enter/Space. 진행은 정중하게 한 번("검사 중"), 끝나면 결론 머리 단어+문장을 알린다 (오류 결론도 정중하게: 지금 상태를 알리는 것이지 앱 오류가 아님).
- 사이트 점검 입력에서 Enter = 점검.

### 4.5 새 토큰·부품

- `DiagnosisParts`: `CheckCard`(펼침 가능), `ConclusionCard`, `CompareStrip`. 기존 `GlassCard`·`Badges`·`Banner`·`RowButton`·`GlassTextBox` 위에 짓는다.
- 결론 무게 → 기존 상태 색(Ok/Warn/Bad/Accent/Muted) 재사용, 새 색 없음.

## 5. 성능

빠른 진단은 최대 약 6초(어댑터 2 + 게이트웨이 1, 병렬로 TCP·DNS 3, HTTPS·로그인 4.5). 진행 알림은 검사당 한 번이라 화면 부담 없음. 별도 bench는 두지 않고, 진단 화면 진입·결과 표시 전환은 G5 전환 캡처로 본다.

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- `DemoDiagnosticProbes`: 시간축 회차별 답(끊김 회차 → TCP·HTTPS 실패, 링크 다운 → 어댑터 내려감·링크 실패), `diagnosis` 덮어쓰기, `timeout`이 조율자의 제한시간 경로를 탐(실행 상태 Timeout).
- 진행 알림: 일곱 검사가 한 번씩, 반환 결과와 같은 값.
- `DiagnosisHost`: 한 번에 하나, 비교(앱 안 앞 결과·기록에서 읽은 앞 결과), 저장(측정 Id, 같은 초 이름, 저장 실패 시 결과 유지), 사이트 점검 검증·동시 실행, DNS 비우기 흐름(실행 순서: 비우기 → 다시 진단 → 메시지, 진단 중이면 기다림), 창 닫기 취소.
- `DiagnosisView`: 결론 12종의 머리 단어·무게, 사유 코드 표가 모든 코드를 덮음(엔진 코드 목록과 대조), 비교 띠 문구.
- 복사 텍스트에 시나리오의 주소·도메인·대상 이름이 없음 (데모 시나리오 전부로).
- 실제 시스템 동작(Platform): 폴더 열기의 허용 범위 검사(허용 밖·없는 폴더 거절)만 G2. 실제 실행은 하지 않는다.

### 7.2 G3 데모 시나리오 (`M6FlowTests`, 로컬)

1. 진단 화면 처음 → 시작 → 진행 중 장면(지연 시나리오) → 결과: 화면 결론 번호·문장·단계·검사 판정 일곱 = 같은 시나리오 검사기로 Core를 직접 돌린 값. 저장 파일을 다시 읽은 값 = 화면.
2. 시나리오의 결론별(11 정상, 3 DNS, 6 바깥, 1 링크, 4 로그인, 10 일부, 12 근거 부족, 2 IPv4 직접 연결 안 됨) 결론 화면.
3. 다시 검사(시간축이 끊김 구간으로 넘어간 뒤) → 비교 띠의 바뀐 검사 = `Compare`.
4. 결과 복사 → 앱이 클립보드로 넘긴 텍스트(진단 값으로 노출) = `CopyText`.
5. 사이트 점검: 잘못된 입력 셋(빈 값, IP, 스킴) → 칸 오류·실행 안 함, 올바른 입력 → 두 줄 = Core.
6. DNS 비우기: 결론 3 장면에서 단추 → 대화상자 → 취소(시스템 동작 0회) → 다시 → 확인(1회) → 다시 진단 → 메시지.
7. 측정 중 진단 → 기록의 `measurementId` = 측정 Id. 홈 카드 → 진단 화면.
8. 키보드만으로: 진단 화면으로 이동 → 시작 → 결론 읽기 → 사이트 점검 입력·Enter.

### 7.3 실측 (로컬, 공개하지 않음)

데모 옵션 없이 진단 화면에서 빠른 진단 1회 + 사이트 점검 1회(`example.com`) → 화면 결론·검사 판정 = 같은 순간 기록 파일. 결과 판정은 통과 조건이 아니다(이 PC 상태). DNS 비우기·설정 열기는 실측에서도 누르지 않는다 (시스템을 바꾸므로 사용자가 직접).

## 9. 대안

- 진단을 모달 창으로: 7.5 "창 하나" 원칙에 어긋나 버림.
