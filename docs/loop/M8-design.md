# M8 설계 — 리포트

1판 · 2026-11-14 · 브랜치 `loop/m8-report` (`loop/m7-records` `828fe55` 위, M6·M7 PR 병합 전)

기획서 8절 M8 행: "리포트 생성, 가리기, 미리 보기, 내보내기". 끝났다는 증거: **G3: 내보낸 파일 내용 검사**, G5. 기준은 `docs/loop-plan.md` 6.2(R3 리포트 내보내기), 6.3(N6 통신사 전달용 리포트, 최소 범위 "외부 파일 없이 열리는 파일 형식 한 가지"), 수용 기준의 원칙("가리기를 켠 결과에 원본 식별 정보가 남지 않는지, 사용자 입력이 그대로 문자로 표시되는지"), 4.3 끝에서 끝까지(… 기록에서 다시 열기 → 리포트 내보내기), 7.5(리포트 화면: 미리 보기, 가리기 옵션, 내보내기), 7.6, 7.8. 리포트의 내용은 M7 기록 화면의 모델(`RecordView`, `EpisodeDetail`, `StoredDiagnosisView`)을 그대로 쓰고, 판정·등급·통계 규칙은 바꾸지 않는다.

**브랜치**: M6·M7 PR이 병합 전이다. 이 브랜치는 M7 끝에서 시작했고 이번에는 **설계와 설계 검토만** 한다(사용자 지시). M6·M7에 고칠 것이 생기면 아래 브랜치에서 고친 뒤 병합해 가져온다(되감기·강제 푸시 없음). 구현은 M7 병합 뒤 또는 사용자가 정할 때.

## 2. 구조

```
Core
  Report/ReportDocument.cs     (새: 리포트 문서 모델 — 절, 표, 그림, 문단. 화면·HTML이 같은 것을 그린다)
  Report/ReportBuilder.cs      (새: 기록 + 분석 + 진단 기록 + 가리기 옵션 → ReportDocument. RecordView·EpisodeDetail 재사용)
  Report/Redactor.cs           (새: 가리기 규칙. 대상·어댑터·사업자·자유 글 속 주소)
  Report/TimelineSvg.cs        (새: TimelineModel.Frame → SVG 글. 색은 문서 고정 팔레트)
  Report/ReportHtml.cs         (새: ReportDocument → HTML 한 파일. 모든 글자는 인코딩, 인라인 CSS·SVG만)
  Report/ReportTexts.cs        (새: 리포트 문구 표)
App
  Screens/ReportScreen.cs      (새, 준비 중 화면 교체)
  Design/Controls/ReportParts.cs (새: 문서 모델을 XAML로 그리는 미리 보기)
  Screens/RecordsScreen.cs     (상세에 "리포트 만들기")
  StartupOptions               (+ --report-out <폴더> 시험용 내보내기 위치)
```

문서 모델은 Core에 두고 화면(미리 보기)과 파일(HTML)이 **같은 모델**을 그린다. 문서 고정 팔레트는 디자인 토큰의 라이트 팔레트 값과 같게 두고 시험으로 고정한다 (Core는 Design을 참조하지 않으므로 값을 옮겨 적고 G2가 같음을 검사).

## 3. Core (A단계)

### 3.1 리포트 내용 (`ReportBuilder`)

입력: `MeasurementRecord`, `AnalysisResult`, 수명, 그 측정의 진단 기록들(`measurementId`가 같은 것), 옵션(가리기, 메모 포함, 진단 포함, 끊김 상세 수), 만든 시각, 앱 버전.

| 절 | 내용 | 출처 |
| --- | --- | --- |
| 1 요약 | 등급과 한 문장, 측정 기간(시작·끝·길이, 시간대 표기), 끝 사유, 관측 충족, 끊김 수·최장, 이 리포트가 말하는 것과 말하지 않는 것 한 문단 | `RecordView.Detail`, `ReportTexts` |
| 2 타임라인 | 전체 기간 그림(SVG), 범례, 그림 설명 글(대체 텍스트) | `TimelineModel.Frame`, `TimelineSvg` |
| 3 끊김 목록 | 끊김마다 시작 시각, 길이(최소~최대·열린 끝), 판정(혼합이면 하위 구간), 구간 후보(후보 없음이면 사유). 판정별 통계 | `RecordView`, `EpisodeLine`, `VerdictLine` |
| 4 관측 근거 | 대상별 통계(손실률·"100번 중 n번"·평균·최대 지연·최대 연속 손실), 링크 근거 요약(지원·접근 거부·이벤트 없음·끊김 관측의 네 상태 구분, 6.2 R2), 경로 유형, 지연 추세 표(5분 창 중앙값) | `TargetStats`, `LinkEvidence.Summaries`, `RecordView.Trend` |
| 5 끊김 상세 | 길이가 긴 순 최대 5개(옵션 0~10): 하위 구간, 앞뒤 2회차 표, 시작 경로 유형, 링크 근거 | `EpisodeDetail` |
| 6 증상 표시와 메모 | 표시 시각과 메모 (옵션으로 메모 빼기) | `SymptomMarks` |
| 7 측정 중 진단 | 그 측정 중 돌린 빠른 진단의 저장 결론·검사 판정 (옵션) | `StoredDiagnosisView` |
| 8 측정 조건 | 대상 구성(역할·방식·포트·순서), 주기·제한시간·예상 연결, 손상·누락 알림, 앱·분석기 버전, 리포트 만든 시각 | `RecordHeader`, `RecordView.DamageNotices` |

- 분석이 "관측 부족"·"판단 불가"면 요약이 그 사실을 먼저 말하고, 끊김 목록이 비어 있어도 "관측되지 않음"과 "관측하지 못함"을 구별한다 (근거 없이 좋다고 하지 않음).
- 측정 중인 기록으로는 만들지 않는다 (끝난 뒤). 끝 기록 없음·손상 기록은 알림을 붙여 만든다.

### 3.2 문구 (`ReportTexts`)

- 관측 문장만: "외부 대상 두 곳이 함께 응답하지 않은 구간이 n번 관측됐습니다" 같은 형식. "통신사 장애", "회선 불량", "고장", "원인은" 같은 단정은 쓰지 않는다 (G2가 금지어 목록으로 검사).
- 구간 후보는 "개념도 위의 후보"라고 밝힌다: 실제 패킷 경로가 아님 (M4 B4).
- 머리 문단(고정): 이 리포트는 이 PC에서 관측한 응답·지연·링크 상태의 기록이며, 원인을 단정하지 않는다. 측정 방법(대상 역할, 주기, 제한시간)을 함께 적는다.

### 3.3 가리기 (`Redactor`)

옵션은 둘: **통신사에 보낼 때(가리기, 기본)** / 가리지 않음(내가 볼 때). 가리기의 규칙:

| 값 | 가리기 켬 | 끔 |
| --- | --- | --- |
| 로컬 대상 주소(사설 주소) | "로컬 대상 1" (주소 없음) | 그대로 |
| 외부 대상 주소 | 공개 주소라도 가림: "외부 대상 2" | 그대로 |
| 대상 이름 | 역할 + 순번 (이름은 자유 입력이라 식별 값이 들어갈 수 있음, M7 3.3 [1-6]) | 그대로 |
| 사업자 이름 | "사업자 A·B" (서로 다른지 여부만 남김: 다양성 판단의 근거) | 그대로 |
| 어댑터 이름·인터페이스 번호 | 연결 유형만 ("유선 어댑터") | 그대로 |
| 측정 ID | 시각 부분만 (뒤의 무작위 꼬리 제거) | 그대로 |
| 메모(자유 글) | 그대로 두되 안의 IPv4·IPv6·MAC·이메일 꼴·Windows 사용자 폴더 경로 꼴을 "[가림]"으로 | 그대로 |
| 사용자 경로·컴퓨터 이름·사용자 이름 | 리포트에 애초에 넣지 않는다 (가리기와 무관) | 같음 |

- 가리기를 켠 문서는 **만든 뒤 한 번 더 검사**한다: 원본 기록의 주소·대상 이름·사업자 이름·어댑터 이름 목록 중 하나라도 문서 글에 있으면 내보내지 않고 오류 (안전망). 이름이 "공유기"처럼 일반 단어인 경우의 오탐은 문구 표의 고정 단어와 같을 때만 허용.
- 끈 경우 내보내기 전에 한 번 알린다 ("주소와 이름이 그대로 들어갑니다").

### 3.4 HTML (`ReportHtml`)

- 문서 하나: `<!doctype html>`, `<meta charset="utf-8">`, 인라인 `<style>`(인쇄용 규칙 포함), 본문, 인라인 `<svg>`. 스크립트·외부 글꼴·외부 주소·이미지 파일 없음. 글꼴은 시스템 글꼴 목록.
- **모든 글자는 HTML 인코딩**(본문·속성·SVG의 `<text>`·`<title>`). 사용자 입력은 문자로만 나온다.
- 접근성: 제목 계층(h1~h3), 표의 머리 칸, 그림의 `<title>`·`<desc>`와 본문의 그림 설명, 색만으로 구별하지 않음(띠에 무늬·글).
- 인쇄: A4 세로에서 표가 잘리지 않게(`break-inside: avoid`), 브라우저의 PDF 저장으로 PDF를 만들 수 있다고 안내 (앱이 PDF를 만들지는 않음).
- 파일 이름: `NetPulse-리포트-2026-11-13-1320.html` (측정 시작 지역 시각, 식별 정보 없음).

### 3.5 타임라인 그림 (`TimelineSvg`)

- 전체 기간 한 장, 폭 960 단위 고정(보는 쪽에서 늘어남), M5와 같은 요소: 인터넷·공유기 지연 선, 응답 없음 띠, 공백 빗금, 증상 표시선, 링크 끊김 표시, 시각 눈금.
- 데이터는 `TimelineModel.Frame` 그대로 (열 수 960). 12시간 기록에서도 점은 열의 두 배 이하.
- 색은 문서 고정 팔레트(라이트 값), 띠는 색과 무늬를 함께.

### 3.6 내보내기

- 저장 대화상자(`FileSavePicker`, `.html`), 시험은 `--report-out <폴더>`. 임시 파일에 쓰고 닫은 뒤 이동(덮어쓰기는 대화상자가 확인한 경우만). 실패는 사유와 함께, 화면의 미리 보기는 그대로.
- 내보낸 뒤 "폴더에서 보기"(M6 시스템 동작의 폴더 열기, 그 파일의 폴더만 허용).
- 앱 기록(app-log)에는 내보냄 여부·크기·가리기 여부만, 경로는 남기지 않는다.

## 4. 앱 (B단계)

### 4.1 리포트 화면

```
머리: "리포트" + [내보내기]
왼쪽(또는 위): 측정 고르기 (기본: 가장 최근에 끝난 측정, 목록은 M7 RecordLibrary) · 가리기 [통신사에 보낼 때 | 가리지 않음]
             · [메모 넣기] [진단 넣기] · 끊김 상세 수
오른쪽(또는 아래): 미리 보기 (문서 모델을 XAML로, 문서처럼 밝은 종이 면 위에)
```

- 미리 보기는 앱 테마와 상관없이 **문서 팔레트(밝은 면)** 로 그린다: 내보낼 파일의 모습. 종이 면은 유리 위의 불투명 표면.
- 기록 상세의 "리포트 만들기" → 그 측정이 골라진 리포트 화면.
- 옵션을 바꾸면 미리 보기를 다시 만든다 (백그라운드, 12시간 기록이면 "만드는 중").

### 4.2 상태표

| 상태 | 화면 | G5 장면 |
| --- | --- | --- |
| 끝난 측정 없음 | 빈 상태 + [측정 화면으로] | `report-empty` |
| 만드는 중 | 미리 보기 자리 뼈대 | `report-building` |
| 미리 보기 (가리기 켬) | 문서 | `report-preview` |
| 가리지 않음 | 문서 + 경고 띠 | `report-unmasked` |
| 끊김 없음 / 관측 부족 | 문서 (해당 문장) | `report-no-outage`, `report-insufficient` |
| 손상·끝 기록 없음 기록 | 문서 + 알림 | `report-damaged` |
| 내보내는 중 / 끝 / 실패 | 단추 상태·알림 | `report-exported`, `report-export-failed` |
| 안전망 걸림 (가린 문서에 원본 값) | 오류, 내보내지 않음 | G2만 (만들 수 없는 상태여야 함) |

### 4.3 키보드와 화면 읽기

측정 고르기·옵션·내보내기를 키보드로. 미리 보기는 절 제목을 화면 읽기 제목으로, 표는 행 이름으로 읽힌다.

## 5. 성능

12시간 기록(43,200회차) 리포트: 문서 만들기 95백분위 2초 이하(백그라운드), HTML 크기 3 MB 이하, 미리 보기 그리기 프레임 기준 M5와 같음(전환 최대 50 ms). bench `report-build`(만들기 시간·메모리), `report-preview`(프레임). 기준은 실측 뒤 구현 중 결정에서 확정한다.

- M7 `RecordLibrary`·`RecordView`·`EpisodeDetail`·`StoredDiagnosisView`를 그대로 쓴다. 바꿔야 하면 M7 브랜치에서 고친다.
- M6·M7 밤 UI 시험에서 나오는 수정은 각 브랜치에서 고치고 이 브랜치로 병합한다.

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- `ReportBuilder`: 절 8개의 값 = `RecordView`·`EpisodeDetail`·통계 (데모 시나리오 전부와 합성 기록: 혼합 끊김, 관측 부족, 판단 불가, 끝 기록 없음, 손상, 끊김 없음), 끊김 상세 수 옵션, 측정 중 기록 거절.
- `ReportTexts`: 금지어(단정 표현) 없음, 후보는 "후보"로, 관측 부족·판단 불가의 첫 문장.
- `Redactor`: 표 3.3 전부. 가리기를 켠 HTML에 원본 주소·이름·사업자·어댑터 이름·측정 ID 꼬리가 없음, 메모 속 IPv4·IPv6·MAC·이메일·경로 꼴이 가려짐, 안전망이 남은 값을 찾으면 오류.
- `ReportHtml`: 외부 참조 없음(`http`, `src=`, `<script`, `<link`, `@import`, `url(`), 사용자 입력 인코딩(`<script>alert(1)</script>`, `"`, `&`, 줄바꿈, 이모지·한글 결합 문자), 제목 계층, 표 머리, SVG `<title>`·`<desc>`.
- `TimelineSvg`: 점 수 상한, 공백·띠·표시선 개수 = Frame.
- 문서 팔레트 = 디자인 토큰 라이트 팔레트 (Design.Tests).

### 7.2 G3 (`M8FlowTests`, 로컬)

1. 끝에서 끝까지 (4.3): 데모 측정 → 증상 표시·메모 → 중지 → 기록에서 열기 → "리포트 만들기" → 내보내기(`--report-out`) → 파일 하나, 그 내용(절 제목·요약 문장·끊김 수·메모) = 시험이 기록을 다시 분석해 만든 값.
2. 가리기 켬/끔: 같은 기록으로 둘을 내보내 켬 쪽에 주소·이름이 없고, 끔 쪽에는 있음. 끔은 내보내기 전에 알림.
3. 메모 빼기·진단 빼기·끊김 상세 0개 옵션 → 파일에 해당 절 없음.
4. 미리 보기의 절 목록 = 파일의 절 목록.
5. 내보내기 실패(쓸 수 없는 폴더) → 오류 알림, 파일 없음.
6. 키보드만으로: 리포트 화면 → 옵션 → 내보내기.

### 7.3 G5

- 장면 (× 다크·라이트 × 100·150%): 4.2 상태표의 장면 열.
- 고대비 둘 × `report-preview`, 효과·움직임 줄이기, 홈 → 리포트 전환, 미리 보기 종이 면의 글자 실측 대비(문서 팔레트), bench (5절).
- 내보낸 HTML을 그림으로 확인하는 것은 자동 게이트 밖 (브라우저를 띄우지 않음): G4에 HTML 원문과 미리 보기 캡처를 함께 낸다.

## 8. 위험

| 위험 | 대응 |

| 가린 리포트에 식별 값이 샘 | 규칙 표(3.3) + 만든 뒤 안전망 검사 + 합성 기록 G2 |

| 미리 보기와 파일이 다름 | 같은 문서 모델, 절 목록 G3 비교 |
| 12시간 기록에서 느림·큰 파일 | Frame 열 수 고정, 끊김 상세 수 상한, bench |
| 문서 팔레트가 디자인 토큰과 어긋남 | 값 같음 시험 |

## 9. 대안

- PDF로 내보내기: 라이브러리(새 런타임 의존성, 사용자 확인 필요) 또는 인쇄 API가 필요하다. HTML은 브라우저 인쇄로 PDF가 되므로 HTML 하나로 (N6 최소 범위 "한 가지").
- 미리 보기를 WebView2로 HTML 그대로: 내보낼 파일과 픽셀까지 같다는 장점이 있지만, 창 전용 캡처(PrintWindow)에 WebView2 표면이 찍히지 않을 수 있고 G5 자동 검사(배치·대비)가 닿지 않는다. 같은 문서 모델을 XAML로 그리고 절 목록 비교로 같음을 확인.
- 타임라인 그림을 화면 캡처 PNG로: 테마·배율에 따라 달라지고 창 의존. 모델에서 SVG를 만들면 결정적이고 시험할 수 있다.
- 공개 외부 대상 주소는 가리지 않기: 공개 주소라도 사용자가 고른 대상 구성이 드러나고, 통신사에 필요한 것은 역할과 결과라 가린다 (끔 옵션으로 볼 수 있음).

## 10. 이 마일스톤에서 하지 않는 것

- 여러 측정을 묶은 리포트, 비교 리포트 (M7 비교 화면으로 충분, 필요하면 M9 이후).
- PDF·이미지 파일 내보내기, 메일·메신저로 보내기, 업로드 (서버 없는 단독 실행 원칙).
- 리포트 서식 고르기·로고·통신사별 양식.
- 리포트 기록 보관(만든 리포트 목록).
