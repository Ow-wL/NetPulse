## 3. Core (A단계)

### 3.1 리포트 내용 (`ReportBuilder`)

입력: 출처 열쇠·도장, `MeasurementRecord`, `AnalysisResult`, 수명, 그 측정의 진단 기록들, 옵션, 만든 시각, 앱 버전.

| 절 | 내용 | 출처 |
| --- | --- | --- |
| 1 요약 | 등급과 한 문장, 측정 기간(시작·끝·길이, 시간대), 끝 사유, 관측 충족, 끊김 수·최장, 이 리포트가 말하는 것과 말하지 않는 것 | `RecordView.Detail`, `ReportTexts` |
| 2 타임라인 | 전체 기간 그림(SVG), 범례, 그림 설명 글 | `TimelineModel.Frame`, `TimelineSvg` |
| 3 끊김 목록 | 끊김마다 시작 시각, 길이(최소~최대, 열린 끝), 판정(혼합이면 하위 구간과 각 후보), 판정별 통계. 300개를 넘으면 5절 규칙 | `RecordView`, `EpisodeLine`, `PartLine`, `VerdictLine` |
| 4 관측 근거 | 대상별 통계, **링크 근거: 네 상태(수집 미지원 / 접근 거부 / 관측했으나 이벤트 없음 / 끊김 관측)와 `Partial`·`Coverage`·`Secondary` 보조 사유, 근거 자체가 없으면 "근거를 모으지 못함"** [1-9], 경로 유형, 지연 추세 표 | `TargetStats`, `LinkEvidence`, `RecordView.Trend` |
| 5 끊김 상세 | 길이가 긴 순 최대 5개(옵션 0~10) | `EpisodeDetail` |
| 6 증상 표시와 메모 | 표시 시각. 메모는 옵션 (3.3) | `SymptomMarks` |
| 7 측정 중 진단 | 저장 결론·검사 판정 (옵션) | `StoredDiagnosisView` |
| 8 측정 조건 | 대상 구성(역할·방식·포트·순서), 주기·제한시간·예상 연결, 손상·누락 알림, 앱·분석기 버전, 만든 시각 | `RecordHeader`, `RecordView.DamageNotices` |

- 관측 부족·판단 불가면 요약이 먼저 말하고, 빈 끊김 목록에서 "관측되지 않음"과 "관측하지 못함"을 구별한다.
- **열린 끝 문구** [1-9]: 끝난 기록은 "측정 끝까지 이어짐 (n초 이상)", 끝 기록 없음은 "마지막 관측까지 이어짐, 그 뒤는 알 수 없음". "이어지는 중"은 쓰지 않는다(측정 중 화면의 말).
- 측정 중 기록으로는 만들지 않는다. 지원하지 않는 형식·읽지 못한 기록은 오류 상태(4.2).
- 기록의 오류·사유 문자열(검사 오류 사유, 진단 사유 코드 등)은 **그대로 넣지 않고** 코드 → 고정 문구 표로만 (원문에 경로·이름이 섞일 수 있음) [1-1].

### 3.2 문구 (`ReportTexts`)

- 관측 문장만. "통신사 장애", "회선 불량", "고장", "원인은", "때문에" 같은 단정은 쓰지 않는다 (G2 금지어).
- 구간 후보는 "개념도 위의 후보"로, 판정은 6.2의 네 이름 그대로.
- 머리 문단(고정): 이 PC에서 관측한 응답·지연·링크 상태의 기록이며 원인을 단정하지 않는다, 측정 방법(대상 역할, 주기, 제한시간).

### 3.3 가리기 (`Redactor`) [1-1, 1-2]

옵션: **통신사에 보낼 때(가리기, 기본)** / 가리지 않음(내가 볼 때). 필드별 규칙:

| 기록의 값 | 가리기 켬 | 끔 |
| --- | --- | --- |
| 대상 ID (`Target.Id`) | **넣지 않음** (어디에도) | 넣지 않음 |
| 대상 주소 (로컬·외부) | 넣지 않음 → "로컬 대상 1"·"외부 대상 2" | 그대로 |
| 대상 이름 | 역할 + 순번 | 그대로 |
| 사업자 이름 | "사업자 A·B" (서로 다른지만) | 그대로 |
| 측정 방식·포트 | 그대로 (식별 정보 아님, 비교·판정 조건) | 그대로 |
| 어댑터 별칭·인터페이스 번호 | 연결 유형만 ("유선 어댑터 1") | 그대로 |
| 측정 ID | 시각 부분만 | 그대로 |
| 오류·사유 문자열 | 코드 → 고정 문구 (원문 없음) | 같음 |
| 증상 메모 (자유 글) | **기본 빼기**. 넣으려면 사용자가 켜고(“메모 넣기: 글이 그대로 들어갑니다, 아래 패턴만 가립니다”), IPv4·IPv6·MAC·이메일·전화번호 꼴·UNC·드라이브 경로 꼴·URL의 호스트와 **기록의 대상 이름·주소·사업자 이름**을 "[가림]"으로 | 그대로 (켜면) |
| 날짜·시각·UTC 차 | **일부러 남김** (끊김이 언제였는지가 리포트의 핵심) | 같음 |
| 사용자 경로·컴퓨터 이름·사용자 이름·SSID·MAC | 기록에 필드가 없고 리포트에 넣지 않음 (메모 속에 있으면 위 패턴) | 같음 |

**안전망**: 문서의 글 조각은 출처를 가진다(생성 문구 / 기록 필드 / 사용자 메모). 가리기를 켠 문서를 HTML로 바꾸기 전에 **기록 필드·메모에서 온 조각과 모든 속성·SVG `<title>`·`<desc>`·문서 제목**에서, 원본 식별 값(대상 주소·이름·사업자·어댑터 별칭·측정 ID 꼬리)을 찾는다. 비교는 대소문자·앞뒤 공백·전각 정규화 뒤, 값이 3글자 이하면 단어 경계 일치만. 생성 문구 조각은 검사하지 않는다(고정 문구의 "공유기"와 이름 "공유기"를 구별). 걸리면 내보내지 않고 오류 상태(4.2: 사유 + "다시 만들기"), 앱 기록에는 걸린 필드 종류만.
- 끈 경우: 내보내기 전에 한 번 알림 ("주소와 이름이 그대로 들어갑니다").

### 3.4 HTML (`ReportHtml`) [1-7, 1-8]

- 문서 하나: `<!doctype html>`, `<meta charset="utf-8">`, 고정 인라인 `<style>`(인쇄 규칙 포함), 본문, 인라인 `<svg>`. **XML로도 읽히게** 쓴다(모든 태그 닫음, 속성 따옴표, 개체는 `&amp; &lt; &gt; &quot; &#39;`만) — 시험이 파서 없이 표준 XML 읽기로 검사한다.
- **문맥별 규칙**: 사용자·기록 문자열은 ① 텍스트 노드 ② 따옴표로 감싼 고정 이름 속성(`aria-label`, `title`, `data-field`의 값이 아니라 `data-value`)에만, 둘 다 HTML 인코딩. CSS는 고정 템플릿(문자열 끼워 넣기 없음). SVG 수치는 유한한 숫자를 고정 문화권 형식으로(NaN·무한대는 그리지 않음). URL을 받는 속성(`href`, `src`, `xlink:href`)에 사용자 문자열을 넣지 않는다. 파일 이름은 시각만.
- **외부 참조 검사** (문자열 전체 검색이 아님): 요소 `script`·`link`·`iframe`·`object`·`embed`·`img`·`image`·`foreignObject`·`base` 없음, `href`·`src`·`xlink:href`는 `#` 내부 조각만, 인라인 이벤트 속성(`on*`) 없음, CSS `@import` 없음·`url(`은 `url(#…)`만. SVG 네임스페이스 선언과 메모 속 `https://…` 글자는 허용.
- 접근성: 제목 계층, 표 머리 칸, 그림 `<title>`·`<desc>`, 색만으로 구별하지 않음.
- 표시 값 칸에는 `data-field="summary.grade"` 같은 **고정 필드 이름**을 단다 (G3이 값을 뽑는 자리, 값 자체는 텍스트 노드).
- 인쇄: A4 세로, 표·그림이 쪽 사이에서 잘리지 않게, 브라우저 PDF 저장 안내 (앱이 PDF를 만들지 않음).
- 파일 이름: `NetPulse-리포트-2026-11-13-1320.html` (측정 시작 지역 시각).

### 3.5 타임라인 그림 (`TimelineSvg`)

- 전체 기간 한 장, 폭 960 단위 고정. 인터넷·공유기 지연 선, 응답 없음 띠(색 + 무늬, `url(#…)` 내부 무늬), 공백 빗금, 증상 표시선, 링크 끊김, 시각 눈금.
- 데이터는 `TimelineModel.Frame` (열 960). 띠·표시는 Frame이 열 단위로 합친 것만 (원본 끊김 수와 무관하게 열 수 이하).

### 3.6 생성과 내보내기의 스냅숏 (`ReportRequest`) [1-3]

- 요청 = (출처 열쇠, 도장, 옵션, 요청 번호). 생성은 백그라운드 하나, 새 요청이 오면 앞 결과는 버린다(오래된 완료 무시: 번호가 최신이 아니면 게시하지 않음).
- 화면은 **게시된 불변 문서** 하나를 그리고, 내보내기는 그 문서 그대로(그 문서에서 만든 HTML). 생성 중에는 [내보내기] 꺼짐.
- 가리기를 켜는 쪽으로 바꾸면 그 순간 게시 문서를 버린다(가리지 않은 문서가 남아 내보내지는 일이 없게): 새 문서가 게시될 때까지 미리 보기는 "만드는 중".
- 기록 도장이 바뀌면(메모 저장 등) 게시 문서를 "오래됨"으로 표시하고 다시 만든다. 오래된 문서는 내보내지 않는다.

### 3.7 파일 쓰기 (`ReportFile`) [1-12]

- 대상 폴더에 고유 임시 파일 `.netpulse-report-<guid>.tmp`를 `CreateNew`로 → 쓰기 → flush → 닫기 → 대상이 없으면 이동(덮어쓰지 않음), 있으면(대화상자가 덮어쓰기를 확인한 경우만) `File.Replace`로 바꾸기. 
- 실패·취소 때 임시 파일을 지우고 **기존 파일은 그대로** (`File.Replace` 실패면 원래 파일 유지). 정리 실패는 원래 오류를 덮지 않는다. 가리지 않은 문서의 임시 파일도 남지 않는다.
- 시험 주입 `--report-fail write|move`로 쓰기 중·이동 직전 실패를 만든다.
- 앱 기록에는 내보냄 여부·크기·가리기 여부만 (경로 없음).

## 5. 성능 [1-10]

- **최악 사례**: 대상 8개, 12시간(43,200회차), 회차마다 성공·손실이 번갈아 끊김 약 21,600개, 증상 표시 100개, 경로 변경 500번. 보통 사례: M7 bench의 12시간 기록.
- **끊김 목록 상한**: 300개를 넘으면 목록에는 길이가 긴 300개를 시간순으로 두고 "나머지 n개는 위 판정별 통계에 들어 있습니다"를 적는다(통계는 전부를 센다). 끊김 상세는 옵션 상한(10).
- 재는 범위를 나눈다: 읽기·분석 / 문서 만들기 / 안전망 검사 / HTML 쓰기, 각 5번 반복.
- 기준(출발점, 실측 뒤 구현 중 결정에서 확정): 보통 사례 문서 만들기 95백분위 2초·HTML 3 MB, 최악 사례 5초·5 MB, 최고 전용 메모리 400 MB(M7과 같은 원칙: 넘으면 실측값으로 다시 정함). 미리 보기 그리기 프레임은 M5 기준.
- bench `report-build`(시간·크기·메모리), `report-preview`(프레임).

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- `ReportBuilder`: 절 8개 (데모 시나리오 전부 + 합성: 혼합 끊김, 관측 부족, 판단 불가, 끝 기록 없음, 손상, 끊김 없음, 링크 네 상태와 근거 없음), 열린 끝 문구 둘, 끊김 300개 상한, 측정 중 거절, 오류 문자열이 코드 문구로만.
- `ReportTexts`: 금지어 없음, 후보 표현, 판정 네 이름.
- `Redactor`: 3.3 표 전부. 이름·메모·사업자에 식별 값(주소·전화·이메일·UNC·경로·URL)을 넣은 합성 기록으로 가린 HTML에 원본 값 없음, 대상 ID는 어디에도 없음, 메모 기본 빠짐, 안전망: 출처 구분(생성 문구의 "공유기"는 통과, 메모에 남은 대상 이름은 걸림), 3글자 이하 단어 경계, 속성·SVG 제목까지 검사.
- `ReportHtml`: XML로 읽힘, 외부 참조 검사(요소·속성·CSS), 메모의 `https://`·`src=` 글자는 허용, 주입 문자열(`<script>`, `"><img onerror=…>`, `]]>`, `&`, 줄바꿈, 이모지·결합 문자)이 텍스트 노드로만, SVG 수치 형식, `data-field` 고정 이름.
- **같음**: 문서의 글 조각 순서 = HTML 텍스트 노드 순서(공백 정리 뒤), SVG 요소 수·종류 = Frame.
- `ReportRequest`: 오래된 완료 무시, 가리기 켜는 순간 게시 문서 버림, 도장 변경 → 오래됨, 생성 중 내보내기 불가 (완료 순서를 뒤집는 시험).
- `ReportFile`: 쓰기 실패·이동 실패·바꾸기 실패에서 임시 파일 없음·기존 파일 그대로.
- 문서 팔레트 = 디자인 토큰 라이트 팔레트 (Design.Tests).

### 7.2 G3 (`M8FlowTests`, 로컬) [1-4]

1. **끝에서 끝까지** (4.3): 데모 측정 → 증상 표시·메모 → 중지 → 기록에서 열기 → "리포트 만들기" → 메모 넣기 켬 → 내보내기(`--report-out`) → 파일 하나. 파일에서 `data-field`로 값을 뽑아, **시험이 기록을 다시 읽어 Core 원시 값(`AnalysisResult`·`TargetStats`·`LinkEvidence`·`SymptomMarks`·저장 진단)으로 만든 기대값**과 대조 (같은 `ReportBuilder`로 다시 만든 HTML과의 비교로 대신하지 않음):
   - 요약: 등급, 한 문장, 시작·끝 시각, 끝 사유, 관측 충족 수, 끊김 수, 최장(최소 길이·열린 끝).
   - 끊김 목록: 끊김마다 시작 시각, 길이 범위, 판정·하위 구간과 각 후보 종류.
   - 관측 근거: 대상별 유효 수·손실 수·손실률·평균·최대·최대 연속 손실, 링크 상태(네 상태·보조 사유), 경로 유형.
   - 측정 조건: 대상 역할·방식·포트, 주기, 제한시간, 예상 연결, 손상 알림.
   - 진단: 결론 번호의 머리말, 검사 판정 일곱. 메모: 표시 시각과 글.
2. 가리기 켬/끔: 같은 기록으로 둘을 내보내 켬 쪽에 주소·이름·대상 ID·측정 ID 꼬리가 없고, 끔 쪽에는 주소·이름이 있음(대상 ID는 끔에도 없음). 끔은 내보내기 전 알림.
3. 옵션: 메모 뺌(기본)·진단 뺌·끊김 상세 0개 → 해당 절 없음.
4. 미리 보기의 화면 글 순서(UIA) = 파일 텍스트 노드 순서.
5. 실패: 쓸 수 없는 폴더, `--report-fail write`, `--report-fail move`(기존 파일 있음) → 오류 알림, 임시 파일 없음, 기존 파일 내용 그대로. 저장 취소 → 아무 파일 없음.
6. 스냅숏: 가리지 않음으로 미리 보기 → 가리기로 바꾸자마자 내보내기 시도 → 꺼짐, 새 문서가 게시된 뒤 내보낸 파일은 가린 문서.
7. 키보드만으로: 리포트 화면 → 옵션 → 내보내기.

### 7.3 실측 (`M8LiveRunTests`, 로컬, 공개하지 않음) [1-11]

## 9. 대안

- PDF 내보내기: 라이브러리(새 런타임 의존성, 사용자 확인 필요) 또는 인쇄 API가 필요. HTML은 브라우저 인쇄로 PDF가 된다.
- 미리 보기를 WebView2로: 픽셀까지 같지만 창 전용 캡처·G5 자동 검사가 닿지 않을 수 있다. XAML 미리 보기 + 글 순서 비교 + **Edge 헤드리스로 실제 HTML 확인**의 조합으로.
- HTML 검사에 HTML 파서 패키지: 시험 의존성이 늘어 XML로 읽히는 HTML로 쓰고 표준 XML 읽기로 검사.
- 메모를 가린 문서에도 기본으로 넣기: 자유 글의 식별 값을 패턴만으로 다 잡을 수 없어 기본 빼기 [1-1].
- 끊김 목록 전부: 최악 사례에서 2만 행은 읽을 수 없고 파일이 커서 상한 + 통계 [1-10].

## 10. 이 마일스톤에서 하지 않는 것
