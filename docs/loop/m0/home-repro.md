# 흑요석 홈 시안의 WinUI 3 재현 (D1 확정 전 확인)

- 목적: 사용자가 C(WinUI 3)를 조건부로 고르면서, 고른 흑요석 시안을 C로 같은 품질로 낼 수 있는지 확인한다 (`DECISIONS.md` "D1 조건부 선호").
- 소스: `spikes/c-winui/HomeWindow.cs` (`NetPulseSpikeC.exe --home`). 시안: `spikes/design/home-mockups.html`.
- 측정·캡처한 소스: 커밋 `80a6941`, 깨끗한 작업트리. 원본 `.loop/logs/m0-home/` (커밋 제외).
- 비교 이미지: `home-repro/compare-*.png` (왼쪽 시안, 오른쪽 C, 둘 다 1440×900), `home-repro/compare-transition.png` (테마 전환 네 시점)

## 요소별

상태 표기: **일치**(색 토큰과 정적 외관이 비교 이미지에서 같음), **근사**(같은 효과를 다른 수단으로 냄, 차이 있음), **미구현**.

| 요소 | 방법 | 상태 |
| --- | --- | --- |
| 흑요석 색·글꼴 | 시안의 토큰 값을 그대로 옮김. Pretendard를 실행 파일 옆 `Fonts`에서 읽음 | 일치 |
| 형태·간격 | 유리 반경 18, 떠 있는 유리 12, 줄 높이 1.5 (제목 1.25) | 일치 |
| 한국어 줄바꿈 | 글자 사이에 단어 결합자(U+2060)를 넣어 단어 단위로만 줄바꿈 | 일치 ("것으로 / 보입니다") |
| 유리 3단계 | `AcrylicBrush` 틴트 70·52·36%, 위가 밝은 테두리로 1px 하이라이트 흉내 | **근사**. 시안의 블러 강도 22·18·12 px는 옮길 수 없다(속성 없음). 라이트에서는 `ThemeShadow` 그림자가 시안보다 진함 |
| 배경 빛과 흐름 | 가장자리가 투명한 원형 그라디언트 + Storyboard 이동 | 근사 (CSS blur 대신 그라디언트) |
| 연한 오로라 (켜고 끄기) | 길쭉한 빛 띠 셋, 투명도 0.6초 전환. 장면을 다시 만들지 않음 | **근사**. 시안보다 옅고 위치·퍼짐이 다름 → M2에서 토큰으로 맞춤 |
| 등급 링 | 원의 점선 간격 애니메이션. 처음 한 번만 채우고, 테마·상태를 바꿔도 현재 값을 유지 | 일치 |
| 경로 맵의 흐르는 빛, 노드 파동 | 점선 오프셋 애니메이션, 크기·투명도 반복 | 일치 |
| 타임라인 | 프레임마다 이동, 매초 다시 그림. 장면마다 그래프를 따로 두고 같은 데이터로 그림 | 일치 |
| 끊김 상태 | 배경 빛 색, 경로 붉은 깜빡임, 등급 D, 진단 칩, 제목 | 일치 |
| 카드 등장, 점수 올라가기 | Storyboard, 16 ms 타이머 | 일치 |
| 테마 원형 확산 | 이전 장면을 둔 채 새 장면을 위에 올리고 Composition 원형 클립을 키움. 이전 장면은 입력·접근성 트리에서 뺌 | 일치 (아래 측정) |

## 측정 (단일 실행, 앱 내부 계측)

`spikes/tools/run-home-bench.ps1`. 연한 오로라를 켠 다크 화면에서, 1초 주기 루프백 Ping 측정 루프를 함께 돌렸다.

| 구간 | 평균 fps | 95백분위 프레임 간격 | 최대 프레임 간격 |
| --- | --- | --- | --- |
| 정지 장면 10초 | 164.3 | 6.2 ms | 15.4 ms |
| 오로라 켜고 끄기 6회 | 163.8 | 6.3 ms | 16.7 ms |
| 원형 전환 20회 | 152.7 | 6.3 ms | **75.2 ms** |
| 전환 뒤 정지 장면 10초 | 164.6 | 6.2 ms | 15.8 ms |

| 자원 (10초 표본, 프로세스 1개) | 전환 전 | 전환 20회 뒤 |
| --- | --- | --- |
| CPU (전체 코어 기준) | 5.56% | 5.37% |
| 작업 집합 최대 | 164.7 MB | 195.4 MB |
| 전용 작업 집합 최대 | 56.9 MB | 83.6 MB |
| 관리 메모리 (강제 수집 뒤) | 0.7 MB | 1.0 MB |
| 남아 있는 장면 / 그래프 / 애니메이션 묶음 | 1 / 1 / 1 | 1 / 1 / 1 |

- 측정 루프: 57회차, 중복·누락 0, 예정 대비 지연 최대 15.0 ms. 화면 전환이 측정을 흐트러뜨리지 않았다.
- 전환 시간: 애니메이션 시작 호출까지 31~65 ms, 끝까지 640~691 ms (이 값은 앱이 기록한 호출 시각이고, 첫 표시 프레임의 지연은 아니다).
- **전환 중 한 프레임이 최대 75 ms**: 새 장면 전체를 만드는 순간이다. 제품에서는 테마를 바꿀 때 장면을 통째로 다시 만들지 않는 방식으로 설계한다 (M2).
- **메모리 증가**: 전환 20회 뒤 작업 집합이 약 31 MB 늘었다. 관리 메모리는 그대로이고, 이전 측정에서 10회 뒤 +22 MB, 20회 뒤 +27 MB(전용)로 회수에 비례하지 않아 네이티브 캐시로 추정한다. 누수가 아니라는 증명은 아니다. 장시간 시험(M2 이후)에서 확인한다.
  - 원인 하나는 찾아 고쳤다: 떼어 낸 장면의 무한 반복 애니메이션이 계속 돌았다. 장면마다 애니메이션을 기록해 뗄 때 멈춘다.
- 자원은 스파이크 합격선(CPU 15%, 메모리 400 MB) 안이다. 이 화면은 스파이크 시험 장면보다 CPU를 더 쓴다(약 2% → 5.5%). 움직이는 요소가 많기 때문이다.

## 전환 중 자동화 격리

| 시점 | `verdict` (control view / 전체) | `theme-light` 버튼 |
| --- | --- | --- |
| 전환 전 | 1 / 1 | 1 |
| 전환 시작 150 ms 뒤 (두 장면이 함께 있음) | 1 / 1 | 1 |
| 전환 뒤 | 1 / 1 | 1 |

전환 뒤 키보드 초점은 새 장면의 같은 버튼에 있다. 화면 읽기 프로그램으로는 확인하지 않았다.

## 남은 차이와 확인하지 못한 것

- 연한 오로라의 세기·위치, 라이트 그림자 세기 (위).
- 흑요석 시안의 미세한 결(점 무늬 질감)은 옮기지 않았다.
- 타임라인 두 그래프가 같은 색인 것은 시안 그대로다. M2에서 보조 계열색을 정한다 (`DECISIONS.md` D2).
- 대비 계산(오로라를 켠 가장 불리한 배경 포함), 고대비 실제 화면, 키보드 탐색, 화면 읽기, 다른 배율, 장시간 실행.
- Windows 설정은 읽도록 했지만 이 PC의 설정을 바꿔 시험하지는 않았다 (사용자 시스템 설정).
