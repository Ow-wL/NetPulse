# M5 설계: 홈과 측정 화면 (1판)

기준: `docs/loop-plan.md` 6.1(F3, F4), 6.2(R1, R5), 6.3(N1, N2, N8, N9, N13, N14), 7절(디자인), 8절 M5 행. 디자인 기준 이미지는 `docs/design/reference/obsidian-*.png`(D2 흑요석). 기존 앱 동작은 `docs/loop/feature-inventory.md` 4·5·7절. 엔진 계약은 `M3-design.md`, `M4-design.md`.
M5는 첫 화면 마일스톤이다. 지금 앱은 M1의 빈 창(`ShellWindow`)이고, 실시간 모드는 시작하자마자 탐지 제안 프로필로 측정을 돌린다. M5가 끝나면 사용자는 앱을 열어 탐지 결과를 확인하고 두 번의 조작으로 첫 측정을 시작하고, 측정 중 끊김을 타임라인에서 보고, 증상을 표시하고, 측정을 멈춘다.

## 1. 목표와 끝났다는 증거

| 범위 (기획서 8절 M5) | 끝났다는 증거 |
| --- | --- |
| 앱 틀과 탐색, 화면 전환 | 여섯 탐색 항목이 모두 열린다 (G3). 화면 전환이 모션 도구를 거치고 움직임 줄이기에서 페이드만 남는다 (G5 자동 검사) |
| 첫 실행 안내 (N14) | 빈 사용자 폴더에서 시작해 **조작 두 번**(확인 → 측정 시작)으로 첫 측정이 시작된다 (G3이 조작 수를 센다). 탐지 실패·네트워크 없음 화면 (G5 캡처) |
| 홈 (상태 한 줄, 경로 맵, 시작 버튼, 최근 측정) | 데모 측정 뒤 홈의 등급·끊김 수·최근 측정 줄이 **저장된 기록을 Core 분석으로 다시 계산한 값과 같다** (G3) |
| 경로 맵 (N13) | 구간 상태 결정 규칙을 순수 함수로 시험 (G2). 데모 `outage`·`link-drop`에서 해당 구간이 문제로 그려진다 (G3 진단 값 + G5 캡처) |
| 겹침 타임라인 (N1) | 간추리기·공백·띠·표시 계산을 순수 함수로 시험 (G2). 확대·이동·지금으로 조작 (G3). 12시간 분량에서 프레임 기준 (G5 bench) |
| 증상 표시와 메모 (F4, N8) | 누른 시각의 `symptom` 이벤트와 메모 이벤트가 기록에 남고 다시 읽힌다 (G2). 화면에서 표시 → 메모 저장 → 기록 확인 (G3) |
| 대상과 프로필 편집 (R1) | 추가·수정·삭제·순서·사용 여부·프로필 추가와 삭제, 검증 오류는 저장을 막고 경고는 보여준다 (G2 + G3). 다음 실행에 남는다 (G3) |
| N9 연속 실패 지표 | 대상 카드에 최대 연속 실패, 마지막 성공·실패 시각. 값이 `StatsCalculator`와 같다 (G3) |
| R5 (배율 150%, 키보드) | 새 화면 전부 배치 검사(잘림·겹침·글자 잘림 0) 1배·1.5배 (G5). 키보드만으로 첫 측정 시작·증상 표시·중지 (`KeyboardTests`) |
| 이월 지적 (M2 3건, M4 3건) | 6절 |

**세 단계로 나눠 커밋한다** (단계마다 로컬 게이트 G1·G2. G4는 마지막에 한 번):
- A. 엔진 쪽 추가 (Core): 증상 표시, 실시간 전달, 기록 목록, 데모를 세션으로, 화면용 순수 모델 + M4 이월 시험 3건
- B. 앱 틀과 화면: 탐색, 첫 실행, 홈, 측정, 측정 구성 편집, 최소 설정, 새 부품 + M2 이월 3건
- C. 게이트: G3 시나리오(데모·실측), G5 캡처 매트릭스·배치·대비·bench, 스크립트

## 3. 엔진 쪽 추가 (A단계)

### 3.1 증상 표시와 메모 (F4, N8)

M3 기록 계약의 `symptom` 이벤트를 처음 쓴다. 기록은 줄 추가만 하므로 메모 수정은 새 이벤트로 남긴다.

| 이벤트 `type` | 필드 | 뜻 |
| --- | --- | --- |
| `symptom` | `mark` (측정 안 순번 `s1`, `s2`…), `memo` (선택), 공통 `round`·`at`·`wall` | 사용자가 끊김을 느낀 시각. `at`은 **누른 순간의** 경과 시간, `round`는 그때까지 시작한 마지막 회차 |
| `symptomMemo` | `mark`, `memo` (빈 값이면 메모 지움) | 메모를 붙이거나 고침. 같은 `mark`의 마지막 줄이 이긴다 |

- `MeasurementSession.MarkSymptom(string? memo) → SymptomResult(string? Mark, long AtMs, DateTimeOffset Wall, bool Written, string? Error)`: 측정이 돌고 있을 때만 받는다 (`Running`이고 끝내는 중이 아님). 아니면 `Mark = null`.
- `EditSymptomMemo(string mark, string? memo) → bool Written`: 같은 측정이 돌고 있을 때만. 끝난 측정의 메모 수정은 M7(기록 화면)에서 정한다.
- 메모 정리: 앞뒤 공백을 지우고, 줄바꿈과 제어 문자는 공백 하나로 바꾸고, **200자**까지 (넘으면 잘라 쓰고 `memoTruncated: true`). 화면은 메모를 언제나 글자 그대로(마크업 해석 없이) 보여준다.
- 쓰기 실패(저장소 실패, 이벤트 큐 넘침): `Written = false`. 화면은 "기록하지 못했습니다. 이 시각을 따로 적어 두세요: 오후 2:32:10"을 오류 알림으로 띄운다 (기존 앱 동작, 기능 명세서 5절).
- `SymptomMarks.FromEvents(events) → IReadOnlyList<SymptomMark(Mark, Round, AtMs, Wall, Memo, EditedAt, Truncated)>` + 무시한 줄 수 (모르는 `mark`의 메모, 중복 `mark`). 읽기 쪽은 이것만 쓴다.
- 기록 형식 버전은 1을 유지한다 (이벤트 종류 추가는 M3 계약상 호환. 모르는 종류는 읽기에서 보존).

### 3.2 실시간 전달 (`LiveFeed`)

지금 화면이 받을 수 있는 것은 엔진 구독의 **최신 상태 하나**(중간 상태를 건너뛸 수 있음)와 매번 전체를 복사하는 `ObservedRounds`뿐이다. 12시간 측정(43,200회차)을 매초 전체 복사하지 않도록 커서 방식으로 바꾼다.

- `session.Live.Read(LiveCursor? after) → LiveDelta(LiveCursor Next, IReadOnlyList<RoundData> Rounds, IReadOnlyList<JsonObject> Events, IReadOnlyList<GapSpan> Gaps, SessionStatus Status)`.
  - `Rounds`: 커서 뒤에 **처리 작업이 확정 분류한** 회차 (기록과 같은 순서·같은 값).
  - `Events`: 커서 뒤에 쓴 이벤트 중 화면이 쓰는 종류(`symptom`, `symptomMemo`, `link`, `route`, `gap`, `storage`). 쓰기에 실패한 이벤트도 화면에는 전달한다 (`written: false` 표시).
  - `Gaps`: 전체 목록 (작다).
- `session.Header`: 기록 머리 (대상·계획 시간·예상 연결). 잠정 분석에 필요하다.
- 메모리: 세션이 회차·이벤트를 이미 메모리에 들고 있으므로 늘지 않는다. 링크 표본 이벤트는 상태가 바뀔 때만 쓰므로 작다 (M4).
- 스레드: `Read`는 아무 스레드에서 불러도 된다 (세션의 기존 잠금 안에서 커서 뒤만 복사).

### 3.3 기록 목록 (`RecordCatalog`)

- `RecordCatalog.List(IEnumerable<string> roots, int max) → IReadOnlyList<RecordEntry(Id, StartedAt, PlannedMs, Targets, Expected, EndReason?, EndedAt?, Status, Segments)>`: 각 측정 폴더의 `measurement.json`과 `summary.json`만 읽는다. 최신순.
  - `Status`: `Complete`(요약 있음), `InProgress`(요약 없음, 지금 도는 측정), `Interrupted`(요약 없음, 지금 도는 측정이 아님 → 앱이 비정상 종료한 것), `Unreadable`.
  - 두 위치(기본, 대체)의 같은 측정 조각은 한 항목으로 묶는다 (`FindSegments`와 같은 규칙).
- 홈은 최신 3개를 보여주고, 각 항목은 백그라운드에서 `RecordReader.Read` → `MeasurementAnalysis.Analyze`로 등급·끊김 수·최장 길이를 계산한다. 결과는 앱 실행 동안 (측정 ID, 요약 유무)로 캐시한다. 분석 결과를 파일에 저장하지 않는다 (분석기 버전이 바뀌면 다시 계산해야 하므로).

### 3.4 데모를 세션으로

기획서 4.3: "데모는 가장 바깥에서만 바꿔 끼운다 … 집계·저장·분석·화면은 제품 코드를 그대로 탄다." 지금 데모는 엔진만 돌리고 기록·분석을 타지 않는다. M5에서 데모도 `MeasurementSession`으로 돌린다.

- 시나리오 형식 (버전 1, 선택 항목 추가):
  - 대상에 `name`, `provider`. 없으면 `id`를 이름으로, 사업자는 비움 (그러면 외부 다양성 경고와 등급 "판단 불가"가 그대로 나온다. 의도한 동작).
  - `network`: `{ "kind": "wired" | "wireless" | "none", "virtual": bool, "otherGateways": n }`. 없으면 `wired`, 가상 아님, 0.
- `DemoWorld(Scenario, double speed, long? holdRound)`:
  - 탐지 결과: `network.kind`가 `none`이면 `NoNetwork`. 아니면 시나리오 대상으로 만든 제안 프로필 (`DetectionPlanner`의 실제 외부 주소 대신 시나리오의 문서용 주소). 계획 시간은 시나리오 길이.
  - 검사기 `DemoProbe`, 경로·링크 관측기 `DemoNetwork`, 시계 `DemoClock`.
  - `DemoClock`: `ScaledClock`에 **멈춤 회차**를 더한 것. `holdRound`가 있으면 그 회차 + 0.5초 지점에서 시간이 멈춘다 (`Delay`는 취소될 때까지 끝나지 않는다). 캡처를 "같은 데이터·같은 시각"으로 찍기 위한 것이다 (기획서 7.8).
- 번들 시나리오 갱신: `steady`, `outage`, `link-drop`에 이름·사업자(문서용 예시 이름 "예시 통신사 A/B"), 새 `no-network`(첫 실행의 네트워크 없음 화면), `long`(12시간, bench용).
- 데모의 사용자 폴더 기본값은 `%LOCALAPPDATA%\NetPulse\demo`다. 데모 기록이 실제 기록 목록에 섞이지 않게 한다. (`--user-data`를 주면 그것)

### 3.5 화면용 순수 모델 (`Presentation/`)

**TimelineModel** (N1):
- 입력: 회차(`RoundData`), 대상 역할, 공백, 증상 표시, 링크 다운 구간(`LinkEvidenceBuilder` 결과), 보기 창 `[fromMs, toMs]`, 열 수(그래프 폭 픽셀).
- 계열 두 개 (기준 이미지와 같음):
  - **공유기 지연**: 첫 로컬 대상의 응답 시간.
  - **인터넷 지연**: 그 회차에 응답한 외부 대상들 응답 시간의 **중앙값** (둘이면 평균). 한 대상만 응답하면 그 값. 하나도 없으면 값 없음.
- 간추리기: 창을 열 수로 나눈 칸마다 최솟값·최댓값을 낸다 (급증이 사라지지 않게). 열 수의 두 배를 넘는 점을 그리지 않는다.
- **이어 그리지 않는 곳**: 값 없는 회차, 누락 회차(회차 번호가 건너뜀), 관측 공백(절전·멈춤). 이 앞뒤를 선으로 잇지 않는다 (기획서 "이어받을 판단 규칙").
- 띠:
  - `외부 응답 없음`: 사용 중인 외부 대상이 모두 손실인 회차의 연속 구간 (끊김 색 띠).
  - `일부 응답 없음`: 일부 대상만 손실 (주의 색, 위쪽 얇은 줄).
  - `관측 공백`: 공백 구간 (빗금 회색, "관측하지 못함").
  - 검사 오류만 있는 회차는 띠를 그리지 않고 값 없음으로 둔다 (손실과 구별).
- 표시: 증상(주의 색 세로 점선 + 위쪽 점), 링크 다운(위쪽 줄에 끊김 색 막대. 출처 "직접 관측"/"기록"을 이름에 적음).
- 띠·표시는 판정(M4)이 아니라 **관측**이다. 판정은 등급 문장과 M7의 끊김 목록에서 보여준다. 화면에는 "띠는 응답이 없었던 시간입니다"로 설명한다.
- 화면 읽기용 요약 문장: "최근 2분: 외부 응답 없음 1번(8초), 증상 표시 1개, 관측 공백 없음".

**PathMapModel** (N13):
- 노드: 이 PC(연결 종류 유선/Wi‑Fi/알 수 없음), 공유기, 인터넷. 구간: PC–공유기, 공유기–인터넷.
- 구간마다 `확인됨`(최근 5회차 안에 그 구간 너머 대상이 응답) / `확인 안 됨`(측정하지 않거나 응답 기록 없음) 그리고 상태 `정상`/`주의`/`문제`/`알 수 없음`.
- 상태 결정 (측정 중, 최근 5회차 기준):
  - 링크 다운을 지금 직접 관측 → PC–공유기 `문제`.
  - 로컬 대상 응답 + 외부 모두 손실 3회차 이상 연속 → 공유기–인터넷 `문제`.
  - 로컬 대상도 외부도 모두 손실 3회차 이상 → PC–공유기 `문제`, 공유기–인터넷 `알 수 없음` (그 너머는 판단할 수 없음).
  - 일부 손실·지연 기준 초과 → 해당 구간 `주의`.
  - 로컬 대상이 없으면 공유기 노드는 "측정하지 않음", PC–공유기는 `확인 안 됨`.
  - 잠정 분석이 경로 보류(`route-hold`)면 두 구간 모두 `알 수 없음`과 "경로가 예상과 달라 판단을 보류합니다".
- 측정하지 않을 때: 탐지 결과의 구조만 그리고 모든 구간 `확인 안 됨`.
- 이 결정은 화면 표시용이다. 원인 구간 후보의 공식 결과는 M4 분석(`Candidate`)이고, 측정이 끝나면 맵은 분석 결과의 가장 긴 끊김 구간 후보를 따른다.
- 맵 위에 언제나 "개념도 · 실제 경로와 다를 수 있음"을 적는다.

**LiveSummary**:
- 대상 카드 값: 최근 응답(ms / 응답 없음 / 검사 오류), 손실률과 쉬운 문장("100번 중 2번 응답이 없었습니다"), 평균 지연(성공만), 최대 연속 실패(N9, 회차 수), 마지막 성공·실패 시각. 값은 `StatsCalculator`의 결과를 그대로 쓴다.
- 홈 한 줄 상태와 숫자 줄: 등급 문장(M4 `Sentences`) + "최근 N분 동안 끊김 n회 · 평균 지연 n ms · 응답 성공 n%".
- 제목 칩: 연결 종류, 공유기 최근 지연, 인터넷 최근 지연(위 대표값).

## 4. 앱 (B단계)

### 4.1 시작과 세계

- 앱은 **측정을 시작하지 않고** 뜬다. `AppWorld`가 실측 또는 데모의 시계·탐지·검사기·관측기·기록 위치를 묶는다.
- 시작 시 `ProfileStore.Load(사용자 폴더)`:
  - `Missing` → 첫 실행 안내.
  - `Unreadable`/`UnknownVersion`/`Invalid` → 파일은 이미 옆으로 옮겨졌다. 첫 실행 안내 위에 "저장된 측정 구성을 읽지 못해 따로 보관했습니다" 안내.
  - `Loaded` → 홈.
- 설정(`settings.json`)을 메인 창에서도 읽는다 (지금은 전시 화면만 읽음).
- 새 시험 인수: `--screen <id>`(시작 화면), `--start`(저장된 프로필로 바로 측정 시작), `--demo-hold <회차>`. 모르는 인수는 지금처럼 거부한다.

### 4.2 창과 층

- `AppShell`은 전시 화면과 같은 층을 쓴다: 배경 빛 → 앱 격자(왼쪽 `NavRail`, 오른쪽 화면 호스트) → 알림 → 대화상자 → 진단 값. `--ui-scale`의 `Viewbox`도 같은 방식.
- 제목 표시줄: 지금처럼 시스템 제목 표시줄을 테마 색으로 칠한다. **콘텐츠를 제목 표시줄까지 넓히지 않는다** (M2 설계는 M5로 미뤘음). 이유: 끌기 영역·캡션 버튼 영역 처리와 창 캡처·자동화 경계가 새 위험이고, 기준 이미지의 정보 구조에는 영향이 없다. M11 디자인 총점검에서 다시 본다. (DECISIONS에 기록)
- 탐색 항목: 홈, 측정, 진단, 기록, 리포트 + 아래 설정. 진단(M6)·기록(M7)·리포트(M8)는 이번에는 **준비 중 화면**(빈 상태 카드 한 장: "이 화면은 다음 단계에서 만듭니다")이다.
- 탐색 막대 아래쪽에 측정 상태 알약을 둔다: "측정하지 않음" / "측정 중 · 3분 12초" / "끊김 감지 · 방금 전". 누르면 측정 화면으로 간다. (`NavRail`에 아래쪽 칸 API를 더한다)

### 4.3 화면 전환

- 기본: 나가는 화면 83 ms 페이드 아웃 → 들어오는 화면의 카드가 차례로 등장 (`Motion.Fade` + `Motion.Stagger`). M2 설계가 약속했던 `Motion.CrossFade`를 이 조합으로 만든다.
- 공통 요소 이동 (`Motion.SharedMove`) 한 가지: 홈의 "최근 2분" 카드 → 측정 화면의 타임라인 카드. 홈에서 측정을 시작하거나 그 카드를 누를 때. 기획서 7.4 "공통 요소는 자리를 이어받아 이동".
- 움직임 줄이기: 페이드만 남는다 (모션 도구가 이미 보장).
- 화면 객체는 처음 열 때 만들고 유지한다 (다시 열 때 상태를 잃지 않게). 측정 중 실시간 갱신은 **보이는 화면만** 그린다. 숨은 화면은 돌아올 때 최신 값으로 한 번 그린다.

### 4.4 측정 수명 (`MeasurementHost`)

상태: `NoProfile` → `Idle` → `Starting` → `Measuring` → `Stopping` → `Idle`(마지막 결과 있음).

- 시작: 현재 프로필로 `MeasurementSession.Start`. 실패(`SessionStartException`: 두 저장 위치 모두 실패, 프로필 검증 실패) → `Idle` + 오류 알림 + 측정 화면 배너.
- 측정 중: 백그라운드 작업이 250 ms마다 `Live.Read(cursor)`를 부르고, 받은 것을 화면 모델에 넘긴다. 화면은 UI 스레드에서 프레임당 한 번만 반영한다. (데모 배속에서도 회차가 밀리지 않게)
- 잠정 분석: 새 회차가 있으면 5초마다 백그라운드에서 `MeasurementAnalysis.Analyze(header, rounds, gaps, events, null, provisional: true, elapsedMs)`. 이전 분석이 끝나지 않았으면 건너뛴다. 걸린 시간을 기록한다 (bench에서 확인).
- 끝: 사용자가 중지(`StopAsync`, 확인 묻지 않음. 기록은 저장되고 되돌릴 일이 없음) 또는 계획 시간 완료. 끝나면 최종 기록을 다시 읽어 확정 분석 → 결과 카드, 최근 측정 갱신, "측정이 끝났습니다" 알림.
- 저장되지 않은 회차(`Unsaved > 0`)나 봉인 실패는 결과 카드에 경고로 보여준다 (M3 설계 "화면이 알린다").
- **창 닫기**: 측정 중이면 지금처럼 멈추고 저장한 뒤 닫는다. 트레이로 숨기는 것은 M9(N7). 닫기 전 확인은 묻지 않는다.
- 측정 중에는 측정 구성 편집을 막는다 (읽기 전용 + "측정 중에는 바꿀 수 없습니다").

### 4.5 화면

모든 화면은 상태(빈, 불러오는 중, 정상, 문제, 오류)를 따로 정의한다 (기획서 7.5).

**첫 실행 안내 (N14)**
- 1단계 "연결을 확인했습니다": 탐지 중(카드 불러오는 중) → 결과 카드: 연결 종류, 공유기(찾음/못 찾음, 주소), 외부 대상 이름 둘, 측정 시간(10분 기본, `SegmentedChoice` 10분·30분·1시간·직접). 경고: 가상·VPN 어댑터("VPN이나 가상 어댑터를 통해 연결된 것 같습니다. 측정 결과가 실제 회선과 다를 수 있습니다"), 다른 게이트웨이, 로컬 대상 없음.
- 행동: **[이대로 측정 시작]**(주요) → 프로필 저장 → 측정 시작 → 측정 화면. [대상 고치기] → 측정 구성 편집(첫 실행 문맥, 저장하면 1단계로 돌아옴). [다시 확인].
- 네트워크 없음/IPv4 경로 없음: 이유 문장 + [다시 확인] + [대상 직접 입력]. (R5 "IPv4 경로 없음 안내")
- 첫 측정까지 조작: 측정 시간 기본값이면 **[이대로 측정 시작] 한 번**, 탐색 포함 두 번 이내 (G3이 센다).

**홈** (기준 이미지 배치. 빠른 진단 카드는 M6에서 더한다)
- 머리: 날짜(앱 시계 기준), "네트워크 상태", 칩(연결 종류·공유기·인터넷 지연).
- 큰 카드: 등급 고리 + 한 문장 + 숫자 줄 + [측정 시작]/[측정 중지] + [빠른 진단](진단 화면으로).
  - 측정 중: 잠정 등급 ("측정 중 · 잠정"). 첫 1분은 "관측 부족" (M4: 판단 가능한 회차 60 미만).
  - 측정하지 않을 때: 마지막 측정 결과 ("지난 측정 · 오늘 오후 1:20") 또는 처음이면 "아직 측정한 기록이 없습니다" + [측정 시작].
  - 프로필 없음: "측정 구성을 확인해 주세요" + [첫 실행 안내 열기].
- 경로 맵 카드 (4.6).
- 최근 2분 카드: 측정 중이면 실시간 타임라인(작은 크기), 아니면 빈 상태 "측정을 시작하면 최근 2분이 여기 그려집니다".
- 최근 측정 카드: 3줄 (등급 배지, 시작 시각, 길이·연결 종류·메모 첫 줄, 끊김 수, 최장). 불러오는 중/빈/오류(읽지 못한 기록 수). "전체 보기" → 기록(준비 중).
- 등급 표기: 좋음 A, 보통 B, 나쁨 C, 매우 나쁨 D, 관측 부족 "–", 판단 불가 "?". **점수(예: 96점)는 만들지 않는다**: 분석에 점수 개념이 없고, 근거 없는 정밀도를 보여주지 않는다 (기획서 N2 "근거 없이 좋은 등급을 주지 않음"). 기준 이미지의 "연결 품질 96점" 자리에는 등급 이름("좋음")을 쓴다. (DECISIONS에 기록)

**측정**
- 머리: "측정", 프로필 이름, 진행 막대(경과/계획, 남은 시간), [측정 시작|중지], [증상 표시], [측정 구성].
- 타임라인 카드 (4.7). 아래 범례 (인터넷 지연, 공유기 지연, 응답 없음, 관측 공백, 증상 표시, 링크 끊김).
- 증상 표시: 누르는 즉시 시각을 기록하고(3.1), 타임라인 아래 메모 패널이 열린다: "오후 2:32:10에 증상을 표시했습니다" + 글 상자 "무슨 일이 있었나요? (선택)" + [저장] [건너뛰기]. Esc는 건너뛰기. 단축키 **Ctrl+M** (측정 중일 때만).
- 증상 목록: 시각·메모·[메모 고치기]. 목록 항목을 고르면 타임라인이 그 시각으로 이동하고 표시가 강조된다. (캔버스 위 표시를 키보드로 고르는 대신 목록이 같은 일을 한다)
- 대상 카드 (3.5 LiveSummary).
- 배너: 저장 실패(대체 위치로 옮김/저장 안 됨), 절전 공백 중, 응답 기준선 없는 대상, "끊긴 상태에서 시작했을 수 있음", 경로 보류.
- 끝난 뒤: 결과 카드(등급, 한 문장, 끊김 수, 최장, 저장 상태). "기록에서 자세히 보기"는 M7.

**측정 구성 편집 (R1)**
- 프로필 고르기(목록) + [새 프로필](현재 것 복사) + [삭제](마지막 하나는 불가) + 이름.
- 측정 시간(분, 1~720, 숫자 글 상자 + 10·30·60 빠른 선택), 예상 연결(상관없음/유선/Wi‑Fi), 응답 제한 시간(ms, 200~900, "고급"으로 접힘).
- 대상 줄: [위][아래] 순서, 사용 토글, 이름, 주소(IPv4), 역할(공유기·내부 장비 / 외부), 사업자, [삭제]. [대상 추가](최대 8). 새 대상 ID는 자동(`t1`…). 측정 방식은 ICMP만 편집한다. 파일에 TCP 대상이 있으면 "TCP 443 · 편집은 다음 단계에서"로 읽기 전용 (TCP 편집은 M9, M3 설계).
- [자동 탐지로 다시 채우기]: 탐지 제안으로 대상을 바꾼다 (저장 전까지 초안).
- 모든 변경은 **초안**이다. [저장]은 `ProfileValidator` 오류가 0일 때만 켜진다. 오류는 해당 칸 아래 빨간 글과 위쪽 요약에, 경고는 노란 배너로. [취소]는 초안을 버린다. 그래서 삭제도 저장 전에는 되돌릴 수 있다 (확인을 묻지 않음).
- 저장: `ProfileStore.Save` (임시 파일 → 바꾸기). 실패하면 오류 알림, 초안 유지.
- "대상 순서는 실제 경로를 증명하지 않습니다"를 목록 위에 적는다 (기획서 R1).

**설정 (최소)**: 테마(다크/라이트/Windows 따르기), 연한 오로라, 효과 줄이기, 움직임 줄이기, [측정 구성 열기]. 알림·저장 위치는 M9.

**준비 중 화면**: 진단·기록·리포트. 빈 상태 카드 하나. 홈의 [빠른 진단], "전체 보기"는 이 화면으로 간다.

### 4.6 경로 맵 부품 (`PathMap`)

- 노드 셋(원형 아이콘 + 이름 + 부제: 연결 종류 / 지연 / "응답 없음" / "측정하지 않음"), 구간 둘.
- 구간 그리기: `확인됨`은 실선, `확인 안 됨`은 점선 + 흐린 색. 상태색은 정상(강조색), 주의, 문제. 색만으로 전하지 않도록 문제 구간에는 ✕ 표시와 부제 글자를 함께 쓴다.
- 흐르는 빛: 확인된 정상 구간에만 작은 빛이 흐른다 (`Motion.Sweep`, 반복형). 문제 구간으로 바뀌는 순간 `Motion.Blink` 3번. 움직임 줄이기에서 둘 다 없음.
- 화면 읽기: 맵 전체 이름 = "개념도. 이 PC에서 공유기까지 정상, 공유기에서 인터넷까지 응답 없음".

### 4.7 겹침 타임라인 부품 (`Timeline`) (N1)

- 그리기: XAML `Polyline`·`Rectangle`로 그리되 점 수를 열 수 두 배로 제한한다 (3.5). 새 회차가 오면 마지막 열만 다시 계산하고, 창이 움직일 때만 전체를 다시 계산한다. M2 `LineChart`는 전시용으로 두고 새 부품을 만든다.
- 축: 세로 ms(창 안 최댓값을 20 ms 단위로 올림, 최소 40 ms), 가로 시각(창 길이에 맞는 눈금: "오후 2:31", "−1분" 등).
- 확대·이동: 창 길이 단계 1분·2분·5분·10분·30분·1시간·3시간·6시간·12시간·전체. 버튼 [−] [+] [전체] [지금으로], 좌우 이동 버튼. 키보드(타임라인에 초점): ←/→ 이동(창의 1/4), +/− 확대, Home/End 처음/지금. Ctrl+휠 확대, 휠 이동.
- **지금 따라가기**: 창의 오른쪽 끝이 "지금"이면 새 회차마다 창이 따라 움직인다. 사용자가 과거로 이동하면 따라가기를 멈추고 [지금으로]가 켜진다.
- 홈의 작은 타임라인은 같은 부품의 간단 모드(2분 고정, 조작 없음)다.
- 화면 읽기: 이름 = 요약 문장(3.5). 보이는 창의 범위를 `HelpText`로.

### 4.8 새 부품과 토큰

| 부품 | 상태 | 비고 |
| --- | --- | --- |
| `GlassTextBox` | 기본, 초점, 오류(빨간 테두리 + 아래 글), 비활성, 읽기 전용 | WinUI `TextBox` 틀 위에 보통 유리. 두 겹 초점 표시. 값 패턴 (자동화로 글 입력) |
| `Meter` | 진행, 완료 | 측정 진행 막대. 이름 = "10분 중 3분 12초" |
| `GradeRing` | 등급 6가지 | 고리 채움 = 등급 단계(A 4칸 … D 1칸), 관측 부족·판단 불가는 점선 고리 |
| `PathMap`, `Timeline` | 4.6, 4.7 | |
| `RecordRow` | 기본, 포인터, 초점, 불러오는 중 | 버튼 (호출 패턴) |
| `Banner` | 정보, 주의, 오류 | 글 많은 알림이 아닌 카드 안 한 줄. 아이콘 + 글자 |
| `PageHeader` | | 제목, 부제, 오른쪽 행동 |

- 새 아이콘: 중지, 연필, 더하기, 빼기, 위, 아래, 휴지통, 뒤로, 표시(깃발), PC, 공유기, 지구, 시계.
- 새 색 토큰을 만들지 않는다. 타임라인의 공유기 계열 = `series2`(점선), 인터넷 = `accent`, 응답 없음 띠 = `bad` + 강조 불투명도 토큰, 일부 응답 없음 = `warn`, 공백 = `faint` 빗금, 증상 = `warn`, 링크 끊김 = `bad`. 새 불투명도·굵기 값은 `Metrics`에 토큰으로 더한다.
- 정적 검사 규칙은 그대로 적용된다. `TextBox`는 금지 목록에 없다. 글 상자 안의 기본 시각 상태 애니메이션은 M2처럼 상태 없는 틀로 바꾼다.

### 4.9 키보드와 화면 읽기 (R5)

- 탭 순서: 탐색 막대(한 번 진입) → 화면 머리 행동 → 카드 순서대로. 측정 구성 편집의 대상 줄은 줄마다 한 번 진입하고 줄 안은 탭으로.
- Esc: 메모 패널 닫기 → 편집 화면 뒤로(초안이 있으면 "저장하지 않은 변경이 있습니다" 대화상자). 대화상자 규칙은 M2 그대로.
- 측정 시작·중지, 증상 표시, 저장은 모두 키보드로 닿는다 (`KeyboardTests`에 시나리오 추가).
- 실시간 값 변화는 화면 읽기에 계속 알리지 않는다 (소음). 끊김 감지·회복, 측정 끝, 저장 실패만 알림으로 알린다.

### 4.10 문구

- 결론 먼저, 쉬운 말 (기획서 7.5). "패킷 손실 2.1%" 옆에 "100번 중 2번 응답이 없었습니다".
- 단정하지 않는다: 띠는 "응답이 없었던 시간", 맵은 "개념도", 후보는 "가능성이 높은 곳".
- 화면의 모든 문장은 화면 코드에 흩지 않고 화면별 문구 묶음(`Screens/Text.cs`)에 둔다 (M8 리포트·M11 문구 점검에서 한 곳을 본다).

## 5. 실시간 성능

- 기준(이 PC 한 대): 측정 화면을 12시간 분량(`long` 시나리오를 높은 배속으로 채운 뒤 1배속)으로 보면서 정지 구간 프레임 95백분위 16.7 ms 이하, 화면 전환 최대 50 ms 이하. 잠정 분석 1회 95백분위 500 ms 이하 (백그라운드라 프레임에 직접 걸리지 않지만 늦어지면 화면이 낡는다). 전용 메모리 400 MB 이하.
- 방법: `--bench measure` (M2 bench와 같은 구간 정의·기록 방식). 결과는 비공개 산출물, 요약만 `docs/loop/m5/bench.md`.
- 기준을 못 맞추면: 먼저 간추리기 열 수·갱신 주기를 조정하고, 그래도 안 되면 결과와 함께 보고한다 (Win2D 같은 새 의존성은 사용자 승인 사항).

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- Core: 증상 표시 (측정 중만, 시각·회차, 메모 정리·200자·제어 문자, 쓰기 실패, 메모 고침 마지막이 이김, 모르는 표시의 메모 무시, 다시 읽기 보존). 실시간 전달 (커서 뒤만, 순서·값이 기록과 같음, 동시 읽기). 기록 목록 (최신순, 조각 묶음, 진행 중·중단·읽을 수 없음). 데모 세계 (탐지 결과, 멈춤 회차에서 시간이 멈추고 중지는 끝남, 시나리오 선택 항목 없음·있음). 시나리오 형식 (이름·사업자·network).
- Presentation: 타임라인 (간추리기가 최댓값·최솟값 보존, 누락·공백·값 없음에서 선이 끊김, 띠 종류별, 검사 오류는 띠 아님, 창 경계 걸침, 표시 위치), 경로 맵 (4.6 규칙 전부 + 로컬 없음 + 경로 보류 + 측정 안 함), LiveSummary (대표 지연 0·1·2·3개 응답, 문장, 카드 값이 `StatsCalculator`와 같음).
- Design: 새 부품이 쓰는 색 조합의 대비(글 상자 바탕 위 글자·자리표시 글자·오류 글, 타임라인 띠 위 축 글자, 경로 맵 노드 부제), 이월 2의 대화상자 범위, 정적 검사 (새 화면 코드 전부).

### 7.2 G3 데모 시나리오 (`FirstRunToStopTests`, 로컬)

빈 사용자 폴더, `--demo outage --demo-speed 20`. 단계마다 60초, 전체 10분 (기획서 4.9).
1. 첫 실행 안내가 뜨고 탐지 결과가 시나리오와 같다 (연결 유선, 공유기 192.0.2.1, 외부 대상 이름 둘).
2. [대상 고치기] → 외부 대상 하나 이름을 바꾸고(값 패턴) 측정 시간을 2분으로 → [저장] → 1단계로 돌아옴. (R1 경로)
3. [이대로 측정 시작] → 측정 화면. 첫 실행부터 측정 시작까지 조작 수를 센다 (2단계 편집을 뺀 기본 경로는 별도 시험 `FirstMeasurementStartsInTwoActions`).
4. 10회차 이후 [증상 표시] → 메모 "화상회의 중 끊김" → [저장].
5. 40회차 이후: 타임라인 요약 이름에 "외부 응답 없음 1번", 증상 표시 1개. 경로 맵 진단 값은 20~27회차 동안 공유기–인터넷 `문제`였다는 기록(진단 값의 상태 변화 기록).
6. 계획 끝(120회차)까지 기다림 → 결과 카드.
7. 기록 검사: 머리의 대상 이름(바꾼 이름), `symptom` 이벤트와 메모, 요약 `Completed`. 시험이 Core로 기록을 다시 분석해 결과 카드의 등급 이름·끊김 수, 대상 카드의 손실률·최대 연속 실패가 **같은지** 본다.
8. 홈: 최근 측정 첫 줄이 이 측정이고 등급·끊김 수가 같다.
9. 같은 사용자 폴더로 다시 실행: 첫 실행 안내가 뜨지 않고, 측정 구성 편집에 바꾼 이름이 있고, 최근 측정에 남아 있다.

추가 시험: 측정 중 중지(`Stopped`), 측정 중 편집 막힘, 프로필 검증 오류가 저장을 막음, 네트워크 없음 데모의 첫 실행, 확대·이동·지금으로(보이는 범위 진단 값), 화면 전환 여섯 항목, 측정 중 창 닫기(저장 후 종료, 요약 `Stopped`).

### 7.3 실측 시나리오 (로컬, 공개하지 않음)

데모 옵션 없이 빈 사용자 폴더: 첫 실행(실제 탐지) → 측정 시작 → 20초 뒤 증상 표시 → 중지 → 기록 저장 확인 → 다시 실행해 최근 측정에 있음. 응답 성공 여부는 통과 조건이 아니다 (기획서 4.3). 캡처·로그는 `.loop/shots`, `.loop/logs`.

| 첫 실행 탐지가 느림 | 백그라운드 + 불러오는 중 카드 + 5초 제한 뒤 "다시 확인" |

## 9. 대안

- **Win2D로 타임라인**: 빠르지만 새 런타임 의존성(사용자 승인 사항). 간추리기로 점 수를 제한하면 XAML로 충분할 것으로 보고 bench로 확인한다.
- **엔진 구독만으로 실시간 화면**: 중간 상태를 건너뛸 수 있어 타임라인에 구멍이 생긴다. 커서 방식(3.2)을 고른다.
- **기록 파일을 다시 읽어 실시간 화면**: 디스크를 매초 읽고, 쓰기 중인 줄을 다룬다. 세션 메모리에 이미 있는 것을 쓴다.
- **증상 메모를 별도 파일로**: 수정이 쉽지만 기록 한 폴더 원칙과 조각·대체 위치 규칙이 복잡해진다. 이벤트 추가로 한다.
- **점수(0~100)**: 기준 이미지에 있지만 분석에 근거가 없다 (4.5).
- **대화상자 안에 메모 입력**: 대화상자에 콘텐츠 칸이 없고, 표시 직후 화면을 가리면 타임라인을 보며 쓰기 어렵다. 타임라인 아래 패널로 한다.
