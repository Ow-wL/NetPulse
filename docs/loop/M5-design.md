# M5 설계: 홈과 측정 화면 (3판)

1판에 대한 Codex 설계 검토 1라운드 지적 11건([1-n])과 2판에 대한 2라운드(마지막) 지적 8건([2-n], Claude 판정으로 모두 수용)을 반영했다 (`DECISIONS.md` "M5 설계 검토 1라운드", "2라운드").

기준: `docs/loop-plan.md` 6.1(F3, F4), 6.2(R1, R5), 6.3(N1, N2, N8, N9, N13, N14), 7절(디자인), 8절 M5 행. 디자인 기준 이미지는 `docs/design/reference/obsidian-*.png`(D2 흑요석). 기존 앱 동작은 `docs/loop/feature-inventory.md` 4·5·7절. 엔진 계약은 `M3-design.md`, `M4-design.md`.
M5는 첫 화면 마일스톤이다. 지금 앱은 M1의 빈 창(`ShellWindow`)이고, 실시간 모드는 시작하자마자 탐지 제안 프로필로 측정을 돌린다. M5가 끝나면 사용자는 앱을 열어 탐지 결과를 확인하고 두 번의 조작으로 첫 측정을 시작하고, 측정 중 끊김을 타임라인에서 보고, 증상을 표시하고, 측정을 멈춘다.

## 3. 엔진 쪽 추가 (A단계)

### 3.1 증상 표시와 메모 (F4, N8)

M3 기록 계약의 `symptom` 이벤트를 처음 쓴다. 기록은 줄 추가만 하므로 메모 수정은 새 이벤트로 남긴다.

| 이벤트 `type` | 필드 | 뜻 |
| --- | --- | --- |
| `symptom` | `mark` (측정 안 순번 `s1`, `s2`…), `memo` (선택), 공통 `round`·`at`·`wall` | 사용자가 끊김을 느낀 시각. `at`은 **누른 순간의** 경과 시간, `round`는 그때까지 시작한 마지막 회차 |
| `symptomMemo` | `mark`, `memo` (빈 값이면 메모 지움) | 메모를 붙이거나 고침. 같은 `mark`의 마지막 줄이 이긴다 |

**쓰기 경로와 확정 시점** [1-3]
- `MeasurementSession.MarkSymptom(string? memo) → SymptomTicket(string Mark, long AtMs, DateTimeOffset Wall, long Round, Task<EventWriteState> Saved)` 또는 측정이 돌지 않으면 `null`.
  - **표시 ID·시각·회차는 누른 순간 호출한 스레드에서 확정**한다 (세션 잠금 안에서 순번 증가, `clock.Elapsed`·`clock.Now`).
  - 파일 쓰기는 하지 않는다. 이벤트 줄을 **세션의 단일 처리 작업**(회차를 처리하는 그 작업)의 입력 통로에 넣는다. 처리 작업이 회차 사이에서 꺼내 기존 `WriteEvent` 경로로 쓴다. 그래서 디스크 쓰기는 언제나 한 작업에서만 일어나고 (`RetryEvents` 동시 호출 없음), UI 스레드는 디스크를 기다리지 않는다.
  - `Saved`: `Saved`(파일에 확정) / `Pending`(저장소 실패로 재시도 대기열에 있음) / `Lost`(대기열 상한으로 버림, 또는 측정 끝까지 못 씀). `Pending`은 나중에 `Saved`나 `Lost`로 바뀌고, 그 변화는 실시간 전달(3.2)의 상태 갱신으로도 온다.
- `EditSymptomMemo(string mark, string? memo) → Task<EventWriteState>?`: 같은 경로. 측정이 끝내기 단계(봉인)에 들어간 뒤에는 `null`을 돌려주고, 화면은 3.1의 "끝난 뒤 메모"로 넘긴다.
- 중지와의 순서: 끝내기는 입력 통로를 닫고, **이미 들어온 사용자 이벤트를 먼저 쓴 뒤** 요약을 쓴다. 닫힌 뒤 들어온 것은 `null`.
- 화면: 누르는 즉시 "오후 2:32:10에 증상을 표시했습니다". `Pending`이면 "아직 저장하지 못해 다시 시도 중입니다", `Lost`면 "기록하지 못했습니다. 이 시각을 따로 적어 두세요: 오후 2:32:10" 오류 알림 (기존 앱 동작, 기능 명세서 5절).

**끝난 뒤 메모** [1-8]
- 측정이 끝난 뒤(계획 완료로 끝나는 순간 메모를 쓰던 경우 포함) 메모는 기록 폴더의 **`notes.jsonl`**에 같은 `symptomMemo` 줄 형식으로 덧붙인다 (`RecordNotes.Append(segmentFolder, line)`, 줄마다 flush). 기록 본문(`events.jsonl`, 요약)은 봉인 뒤 건드리지 않는다.
- 읽기: `RecordReader`가 `notes.jsonl`을 읽어 `Notes`로 보존하고, `SymptomMarks.FromEvents(events, notes)`가 이벤트 → 노트 순서로 적용한다. 노트 파일이 손상되면 그 줄만 무시하고 무시 수를 낸다.
- M7(기록 화면)의 메모 수정도 이 경로를 쓴다. 기록 형식 버전은 1을 유지한다 (`notes.jsonl`은 없어도 되는 추가 파일이고, 이전 읽기 코드는 무시한다).

**메모 정리와 해석**
- 앞뒤 공백을 지우고, 줄바꿈과 제어 문자는 공백 하나로 바꾸고, **200자**까지 (넘으면 잘라 쓰고 `memoTruncated: true`). 화면은 메모를 언제나 글자 그대로(마크업 해석 없이) 보여준다.
- `SymptomMarks.FromEvents(events, notes) → (IReadOnlyList<SymptomMark(Mark, Round, AtMs, Wall, Memo, EditedAt, Truncated)>, int Ignored)` (모르는 `mark`의 메모, 중복 `mark`). 읽기 쪽은 이것만 쓴다.
- 기록 형식 버전은 1을 유지한다 (이벤트 종류 추가는 M3 계약상 호환. 모르는 종류는 읽기에서 보존).

### 3.2 실시간 전달 (`LiveFeed`)

지금 화면이 받을 수 있는 것은 엔진 구독의 **최신 상태 하나**(중간 상태를 건너뛸 수 있음)와 매번 전체를 복사하는 `ObservedRounds`뿐이다. 12시간 측정(43,200회차)을 매초 전체 복사하지 않도록 커서 방식으로 바꾼다.

**게시 단위와 커서** [1-4]
- 세션은 화면용 **게시 목록**(순번 붙은 항목의 추가 전용 목록)을 가진다. 항목은 셋이다.
  - `RoundItem(Seq, RoundData, IReadOnlyList<LiveEvent> Related)`: 한 회차와 **그 회차를 처리하며 만든 이벤트**(`route`, `gap`, `clock`). 처리 작업이 회차를 분류하고 관련 이벤트 쓰기를 시도한 **뒤에** 한 번에 게시한다. 그래서 회차만 있고 그 회차의 경로가 없는 상태는 화면에 보이지 않는다.
  - `EventItem(Seq, LiveEvent)`: 회차와 따로 생기는 이벤트 (`symptom`, `symptomMemo`, `link`, `storage`).
  - `StateItem(Seq, string EventId, EventWriteState State)`: 이미 게시한 이벤트의 쓰기 상태가 바뀜 (`Pending` → `Saved`/`Lost`).
- `LiveEvent(string EventId, string Type, long? Round, long AtMs, DateTimeOffset Wall, string Json, EventWriteState State)`: 불변이다 (`JsonObject`를 넘기지 않고 줄 문자열 사본을 넘긴다).
- `session.Live.Read(LiveCursor? after) → LiveDelta(LiveCursor Next, IReadOnlyList<LiveItem> Items, IReadOnlyList<GapSpan> Gaps, LinkLive Links, SessionStatus Status)`.
  - `LiveCursor(SessionId, Seq)`. 다른 세션의 커서를 주면 예외 (측정을 다시 시작한 뒤 이전 커서를 쓰는 실수를 막음).
  - 게시 목록에 넣는 것과 `Read`의 복사는 같은 잠금 안이고, 항목은 불변이다.
- `session.Header`: 기록 머리 (대상·계획 시간·예상 연결). 잠정 분석에 필요하다.
**전달 버퍼와 분석 근거를 나눈다** [1-4, 2-1]
- **분석 근거 저장소**: 세션은 분석에 쓰는 이벤트(`route`, `link`, `gap`, `clock`, `storage`, `symptom`, `symptomMemo`)를 **버리지 않고** 모두 들고 있다. 기록 파일의 `events.jsonl`과 같은 내용의 메모리 사본이다 (경로·링크는 바뀔 때만 쓰므로 보통 작다. 기록 파일 크기만큼만 는다). 쓰기에 실패한 이벤트도 여기에는 남는다 (화면 값이 저장 실패 때문에 바뀌지 않게).
- `session.Live.AnalysisInputs() → (RecordHeader, rounds, gaps, events, LinkLive, long ElapsedMs, LiveCursor At)`: 잠정 분석은 이것만 쓴다. 같은 잠금 안에서 찍은 한 시점의 사본이고, `At`(게시 순번)과 `ElapsedMs`로 그 시점을 식별한다 (G3 비교용, 7.2).
- **전달 버퍼**(게시 목록)는 화면이 아직 받지 않은 항목만 들고 있으면 된다. 상한 10,000 항목을 넘으면 앞쪽을 버리고, 버린 범위를 가리키는 커서로 `Read`하면 `LiveDelta.Resync = true`를 돌려준다. 그러면 화면은 `AnalysisInputs()`로 화면 모델을 다시 만든다 (재동기화).
- 최종 분석은 기록 파일을 다시 읽어서 한다.
- 시험: 전달 버퍼 상한을 넘긴 뒤에도 같은 회차의 판정·후보가 상한 전과 같음, 버린 범위 커서의 재동기화.
- 시험: 저장 지연(쓰기 막힘) 중 읽기, 대체 위치로 옮긴 뒤, 실패 뒤 복구로 `Pending` → `Saved`, 끝내기와 읽기 교차, 회차와 관련 이벤트가 늘 함께 오는지.

**실시간 링크 근거** [1-5]
- 같은 상태의 반복 표본은 파일에 쓰지 않으므로 이벤트만으로는 "지금도 다운인가, 언제까지 관측했나"를 알 수 없다. 그래서 `LinkLive`를 따로 낸다: 어댑터마다 `(Alias, Capability, State, FirstMs(이 상태의 첫 관측), LastSampleMs(마지막 표본), Coverage(지금까지), Unobserved(넘침 구간))`.
- 진행 중 다운은 **첫 다운 관측 ~ 마지막 표본**까지만 그리고 "이어지는 중" 표시를 붙인다. 현재 시각까지 늘리지 않는다. 표본이 끊기면(관측 불가, 넘침) 그 구간은 미관측으로 그린다.
- **잠정 분석에도 같은 근거를 넘긴다** [2-2]: `MeasurementAnalysis.Analyze`에 선택 인수 `LinkLive? live`를 더한다. 주어지면 `LinkEvidenceBuilder`가 이벤트로 복원한 근거에 `live`의 열린 상태(진행 중 다운의 마지막 표본, 지금까지의 관측 범위, 미관측 구간)를 합친다. 종료 요약이 없는 진행 중 측정을 "중단됨"으로 보지 않는다. 화면의 막대와 분석이 같은 `AnalysisInputs()` 사본에서 나오므로 서로 어긋나지 않는다.
- 시험: 다운이 이어지는 중, 회복 직전, 표본이 끊긴 뒤, 넘침 구간 — 각각에서 타임라인 막대, 회차 판정(`LinkDown`), 구간 후보(`PcLink`)를 함께 검사.

### 3.3 기록 목록 (`RecordCatalog`)

- `RecordCatalog.List(IEnumerable<string> roots, int max, string? runningId) → IReadOnlyList<RecordEntry(Id, StartedAt, PlannedMs, Targets, Expected, Lifecycle, EndReason?, EndedAt?, Integrity, Segments)>`: 각 측정 폴더의 `measurement.json`과 `summary.json`만 읽는다. 최신순. **지금 도는 측정의 ID는 호출하는 쪽이 넘긴다** [1-7].
  - 두 축을 따로 둔다 [1-7]:
    - `Lifecycle`: `Running`(ID가 `runningId`), `Ended`(요약이 형식 검사를 통과), `NoSummary`(요약 없음 또는 손상. 비정상 종료일 수도, 요약 쓰기 실패일 수도 있다고 그대로 말한다: "끝 기록 없음").
    - `Integrity`: `Ok`, `Damaged`(요약 손상 포함), `MissingSegments`, `Unreadable`(머리를 읽지 못함).
  - 두 위치(기본, 대체)의 같은 측정 조각은 한 항목으로 묶는다 (`FindSegments`와 같은 규칙).
  - 홈은 `RecordReader`의 누락 안내(`MissingNotice`)와 손상 수를 그 줄에 함께 보여준다.
- 홈은 최신 3개를 보여주고, 각 항목은 백그라운드에서 `RecordReader.Read` → `MeasurementAnalysis.Analyze`로 등급·끊김 수·최장 길이를 계산한다. 결과는 앱 실행 동안 (측정 ID, 요약 유무)로 캐시한다. 분석 결과를 파일에 저장하지 않는다 (분석기 버전이 바뀌면 다시 계산해야 하므로).

### 3.4 데모를 세션으로

기획서 4.3: "데모는 가장 바깥에서만 바꿔 끼운다 … 집계·저장·분석·화면은 제품 코드를 그대로 탄다." 지금 데모는 엔진만 돌리고 기록·분석을 타지 않는다. M5에서 데모도 `MeasurementSession`으로 돌린다.

- 시나리오 형식 (버전 1, 선택 항목 추가):
  - 대상에 `name`, `provider`. 없으면 `id`를 이름으로, 사업자는 비움 (그러면 외부 다양성 경고와 등급 "판단 불가"가 그대로 나온다. 의도한 동작).
  - `network`: `{ "kind": "wired" | "wireless" | "none", "virtual": bool, "otherGateways": n }`. 없으면 `wired`, 가상 아님, 0.
- `DemoWorld(Scenario, double speed, long? holdRound)`:
  - 탐지 결과: `network.kind`가 `none`이면 `NoNetwork`. 아니면 시나리오 대상으로 만든 제안 프로필 (`DetectionPlanner`의 실제 외부 주소 대신 시나리오의 문서용 주소). 계획 시간은 시나리오 길이.
  - 검사기 `DemoProbe`, 경로·링크 관측기 `DemoNetwork`.
  - 입력 경계의 고장 주입 (선택 항목 `faults`): `detectDelayMs`(탐지가 늦음 → 불러오는 중 화면), `detect: "unknown"`(탐지 실패), `storageStartFail`(두 저장 위치 모두 시작 실패), `storageFailFrom`(그 회차부터 저장 실패, `storageRecoverAt`에서 회복), `suspendAt`·`suspendSeconds`(그 회차에서 데모 절전 알림을 보내고 측정 시계를 그만큼 건너뜀 → M3 절전 공백 경로). 저장 고장은 기록 위치 공급자(`IRecordRoot`)를 감싸 바꿔 끼운다. 집계·저장 로직은 제품 코드 그대로다 [1-9].

**측정마다 새 시계** [1-2]
- 지금 `RoundScheduler`는 시계의 `Elapsed`를 그대로 회차 번호로 쓰고, 시계는 만들 때부터 흐른다. 그래서 시계는 **측정을 시작할 때마다 새로 만든다**: `AppWorld.NewMeasurementClock() → IClock`.
  - 실측: 새 `SystemClock`.
  - 데모: 앱 전체에 **데모 시간축**이 하나 있다. 시간축의 배속 경과 `T`(실제 경과 × 구간별 배속, 멈추면 고정)에서 `Now = startAt + T`. 측정을 시작하면 그 순간의 `T0`를 잡아 측정 시계를 `Elapsed = T − T0`, `Now = startAt + T`로 만든다. 그래서 두 번째 측정도 0회차부터, 벽시계는 이어지고, **배속 전환·멈춤은 두 시간에 똑같이 적용된다** [2-4]. 벽시계와 경과 시간의 차이가 일정하므로 M3 시각 변경 검사(`CheckClock`)가 배속 전환을 시각 변경으로 기록하지 않는다.
- 화면의 "지금"(머리 날짜, "오늘 오후 1:20")은 측정 시계가 아니라 앱 벽시계(실측 `DateTimeOffset.Now`, 데모 벽시계)를 쓴다.
- 시간축의 배속은 구간별이다 [1-10]: `--demo-speed 600 --demo-speed-after 42600:1`처럼 **지금 측정의 회차** 경계에서 배속을 바꾼다. `--demo-hold <회차>`면 지금 측정이 그 회차 + 0.5초에 닿는 순간 **시간축 전체가 멈춘다** (`Now`와 `Elapsed` 모두 고정. `Delay`는 취소될 때까지 끝나지 않고, 중지는 끝난다). 캡처를 "같은 데이터·같은 시각"으로 찍기 위한 것이다 (기획서 7.8).
- 시험: 안내 화면에서 오래 기다린 뒤 시작해도 0회차부터, 중지 뒤 다시 측정(벽시계는 이어짐), 멈춤 동안 `Now` 고정, 배속 전환 전후 `Now − Elapsed` 보존과 `clock` 이벤트 없음.
- 번들 시나리오 갱신: `steady`, `outage`, `link-drop`에 이름·사업자(문서용 예시 이름 "예시 통신사 A/B"). `link-drop`은 90회차까지 정상 뒤 링크 다운으로 바꾼다. 새 `outage-long`(90회차까지 정상 뒤 외부 단절, 7.2), `no-network`(첫 실행의 네트워크 없음 화면), `vpn`(가상 어댑터 경고), `gap`(절전 공백), `long`(720분, bench용).
- 데모의 사용자 폴더 기본값은 `%LOCALAPPDATA%\NetPulse\demo`다. 데모 기록이 실제 기록 목록에 섞이지 않게 한다. (`--user-data`를 주면 그것)

### 3.5 화면용 순수 모델 (`Presentation/`)

**TimelineModel** (N1):
- 입력: 회차(`RoundData`), 대상 역할, 공백, 증상 표시, 링크 다운 구간(`LinkEvidenceBuilder` 결과), 보기 창 `[fromMs, toMs]`, 열 수(그래프 폭 픽셀).
- 계열 두 개 (기준 이미지와 같음):
  - **공유기 지연**: 첫 로컬 대상의 응답 시간.
  - **인터넷 지연**: 그 회차에 응답한 외부 대상들 응답 시간의 **중앙값** (둘이면 평균). 한 대상만 응답하면 그 값. 하나도 없으면 값 없음.
- 간추리기: 창을 열 수로 나눈 칸마다 최솟값·최댓값을 낸다 (급증이 사라지지 않게). 열 수의 두 배를 넘는 점을 그리지 않는다.
- **이어 그리지 않는 곳**: 값 없는 회차, 누락 회차(회차 번호가 건너뜀), 관측 공백(절전·멈춤). 이 앞뒤를 선으로 잇지 않는다 (기획서 "이어받을 판단 규칙").
- 띠:
  - `외부 응답 없음`: 사용 중인 외부 대상이 모두 손실인 회차의 연속 구간 (끊김 색 띠).
  - `일부 응답 없음`: 일부 대상만 손실 (주의 색, 위쪽 얇은 줄).
  - `관측 공백`: 공백 구간 (빗금 회색, "관측하지 못함").
  - 검사 오류만 있는 회차는 띠를 그리지 않고 값 없음으로 둔다 (손실과 구별).
- **띠의 시작·끝** [1-6]: 띠는 응답 없음이 관측된 **회차 칸**을 칠한다. 칸은 그 회차 예정 시각부터 다음 회차 예정 시각까지다 (첫 손실 회차 칸의 시작 ~ 마지막 손실 회차 칸의 끝). 이것은 "응답 없음이 관측된 회차들"이지 실제 끊김의 시작·끝이 아니다.
- **길이 문구** [1-6]: 길이는 언제나 M4·M3의 범위 값(최소 = 첫·마지막 손실 표본 사이, 최대 = 앞뒤 성공 표본 사이, 열린 끝)으로 쓴다.
  - 범위: "약 7~9초", 최솟값만 확실하면 "7초 이상", 측정 끝까지 이어지면 "측정 끝까지 이어짐 (7초 이상)". 한 회차만이면 "1회차"이고, **앞뒤 성공 표본이 있어 범위 최댓값이 있을 때만** "1회차 · 최대 약 2초"처럼 상한을 붙인다 [2-8].
  - 첫·마지막 손실 표본의 차이 하나를 끊김 길이처럼 쓰지 않는다 (기획서 "이어받지 않는 것").
  - 시험: 한 회차 손실, 측정 끝까지 손실, 공백에 걸친 손실, 앞쪽 성공 없음(측정 시작부터 손실).
- 표시: 증상(주의 색 세로 점선 + 위쪽 점), 링크 다운(위쪽 줄에 끊김 색 막대. 출처 "직접 관측"/"기록"을 이름에 적음. 진행 중이면 마지막 표본까지 + "이어지는 중", 3.2).
- 띠·표시는 판정(M4)이 아니라 **관측**이다. 판정은 등급 문장과 M7의 끊김 목록에서 보여준다. 범례와 화면 읽기는 "응답 없음이 관측된 회차"로 설명한다.
- 화면 읽기용 요약 문장: "최근 2분: 외부 응답 없음 1번(약 7~9초), 증상 표시 1개, 관측 공백 없음".

**PathMapModel** (N13) [1-1]

맵은 **관측 사실**과 **구간 후보**를 따로 그린다. 1판은 최근 회차의 연속 손실만으로 구간을 "문제"로 칠했는데, 이는 M4 분석의 구간 후보 조건(응답 기준선, 외부 대상 다양성, 같은 인터페이스 경로)을 건너뛰는 더 강한 판단이었다. 2판은 화면이 따로 판단하지 않는다.
- **노드** (관측 사실):
  - 이 PC: 최근 경로의 연결 종류(유선/Wi‑Fi/알 수 없음). 링크 다운을 지금 직접 관측하면 "링크 끊김 관측"(3.2 `LinkLive`).
  - 로컬 대상: **이름은 사용자가 정한 대상 이름**이다 (탐지가 만든 기본 이름이 "공유기"일 뿐, 무조건 "공유기"라고 부르지 않는다). 로컬 대상이 여럿이면 순서상 첫 대상 + "로컬 대상 n개". 부제: 최근 지연 / "응답 없음 n회 연속" / "측정하지 않음" / "응답 기준선 없음".
  - 인터넷: 외부 대상 "n개 중 m개 응답" + 대표 지연.
- **선** (관측 사실): 선 너머 노드의 대상이 최근 5회차 안에 응답했으면 실선("응답 확인"), 아니면 점선. 범례에 "응답 확인은 그 대상이 응답했다는 뜻이며, 패킷이 이 경로로 지나갔다는 증명이 아닙니다"를 적는다.
- **구간 후보** (판단): M4 분석 결과만 쓴다.
  - 후보는 끊김 구간(`Episode`)이 아니라 **하위 구간(`SubRun`)**에 있다 (M4). 그래서 고르는 규칙을 정한다 [2-3]:
  - 측정 중: 잠정 분석의 진행 중인 끊김 구간에서 **마지막 하위 구간**의 `Candidate`. 끊김이 진행 중이 아니면 맵에 후보를 그리지 않는다 ("지금은 끊김이 관측되지 않습니다").
  - 측정이 끝난 뒤: 가장 긴 끊김 구간(최소 길이 기준, 같으면 먼저 것). 혼합이 아니면 그 하위 구간의 후보. **혼합이면 한 곳을 고르지 않는다**: 선을 칠하지 않고 "여러 종류가 섞인 끊김이라 한 곳을 고르지 않습니다"와 하위 구간 후보를 시간 순서대로 글로 적는다 ("먼저 이 PC 쪽 링크, 이어서 공유기 너머").
  - `PcLink` → PC–로컬 선, `AfterRouter` → 로컬–인터넷 선, `PcToRouterOrRouter` → PC–로컬 선과 로컬 노드. `None`(이유 있음)이면 어느 선도 칠하지 않고 이유 문장("응답 기준선이 없어 구간을 판단하지 않습니다" 등)을 맵 아래에 적는다.
  - 후보 선은 문제 색 + ✕ + "가능성이 높은 곳" 글자. 색만으로 전하지 않는다.
  - 잠정 분석은 최대 5초 늦다. 그 사이는 노드의 관측 사실(응답 없음 n회 연속)만 바뀐다.
  - 경로 보류(`route-hold`)면 "경로가 예상과 달라 구간을 판단하지 않습니다".
- 측정하지 않을 때: 탐지 결과나 마지막 측정의 구조만 그리고 선은 모두 점선.
- 맵 위에 언제나 "개념도 · 실제 경로와 다를 수 있음"을 적는다.
- 시험: 외부 대상 하나만, 처음부터 무응답(기준선 없음), 로컬·외부 경로 인터페이스가 다름, 로컬 대상 없음·여럿, 경로 보류, 직접 관측 링크 다운, 분석 전(첫 1분), 혼합 구간(링크 다운 → 외부 단절, 맵과 화면 읽기 문장), 진행 중 하위 구간이 바뀜 — 각 경우 후보 선이 M4 분석과 같거나 없음.

**LiveSummary**:
- 대상 카드 값: 최근 응답(ms / 응답 없음 / 검사 오류), 손실률과 쉬운 문장("100번 중 2번 응답이 없었습니다"), 평균 지연(성공만), 최대 연속 실패(N9, 회차 수), 마지막 성공·실패 시각. 값은 `StatsCalculator`의 결과를 그대로 쓴다.
- 홈 한 줄 상태와 숫자 줄: 등급 문장(M4 `Sentences`) + "최근 N분 동안 끊김 n회 · 평균 지연 n ms · 응답 성공 n%".
- 제목 칩: 연결 종류, 공유기 최근 지연, 인터넷 최근 지연(위 대표값).

## 4. 앱 (B단계)

### 4.1 시작과 세계

- 앱은 **측정을 시작하지 않고** 뜬다. `AppWorld`가 실측 또는 데모의 시계·탐지·검사기·관측기·기록 위치를 묶는다.
- 시작 시 `ProfileStore.Load(사용자 폴더)`:
  - `Missing` → 첫 실행 안내.
  - `Unreadable`/`UnknownVersion`/`Invalid` → 파일은 이미 옆으로 옮겨졌다. 첫 실행 안내 위에 "저장된 측정 구성을 읽지 못해 따로 보관했습니다" 안내.
  - `Loaded` → 홈.
- 설정(`settings.json`)을 메인 창에서도 읽는다 (지금은 전시 화면만 읽음).
- 새 시험 인수: `--screen <id>`(시작 화면), `--start`(저장된 프로필로 바로 측정 시작. 데모에서 프로필이 없으면 데모 탐지 제안으로), `--demo-hold <회차>`, `--demo-speed-after <회차:배속>`, `--hold-analysis`(최근 측정 분석을 시작하지 않음), `--hold-start`(측정 시작 직전에 멈춤). 모두 캡처·bench 재현용이며 기록 머리와 앱 기록에 남는다. 모르는 인수는 지금처럼 거부한다.

### 4.2 창과 층

- `AppShell`은 전시 화면과 같은 층을 쓴다: 배경 빛 → 앱 격자(왼쪽 `NavRail`, 오른쪽 화면 호스트) → 알림 → 대화상자 → 진단 값. `--ui-scale`의 `Viewbox`도 같은 방식.
- 제목 표시줄: 지금처럼 시스템 제목 표시줄을 테마 색으로 칠한다. **콘텐츠를 제목 표시줄까지 넓히지 않는다** (M2 설계는 M5로 미뤘음). 이유: 끌기 영역·캡션 버튼 영역 처리와 창 캡처·자동화 경계가 새 위험이고, 기준 이미지의 정보 구조에는 영향이 없다. M11 디자인 총점검에서 다시 본다. (DECISIONS에 기록)
- 탐색 항목: 홈, 측정, 진단, 기록, 리포트 + 아래 설정. 진단(M6)·기록(M7)·리포트(M8)는 이번에는 **준비 중 화면**(빈 상태 카드 한 장: "이 화면은 다음 단계에서 만듭니다")이다.
- 탐색 막대 아래쪽에 측정 상태 알약을 둔다: "측정하지 않음" / "측정 중 · 3분 12초" / "끊김 감지 · 방금 전". 누르면 측정 화면으로 간다. (`NavRail`에 아래쪽 칸 API를 더한다)

### 4.3 화면 전환

- 기본: 나가는 화면 83 ms 페이드 아웃 → 들어오는 화면의 카드가 차례로 등장 (`Motion.Fade` + `Motion.Stagger`). M2 설계가 약속했던 `Motion.CrossFade`를 이 조합으로 만든다.
- 공통 요소 이동 (`Motion.SharedMove`) 한 가지: 홈의 "최근 2분" 카드 → 측정 화면의 타임라인 카드. 홈에서 측정을 시작하거나 그 카드를 누를 때. 기획서 7.4 "공통 요소는 자리를 이어받아 이동".
- 움직임 줄이기: 페이드만 남는다 (모션 도구가 이미 보장).
- 화면 객체는 처음 열 때 만들고 유지한다 (다시 열 때 상태를 잃지 않게). 측정 중 실시간 갱신은 **보이는 화면만** 그린다. 숨은 화면은 돌아올 때 최신 값으로 한 번 그린다.

### 4.4 측정 수명 (`MeasurementHost`)

상태: `NoProfile` → `Idle` → `Starting` → `Measuring` → `Stopping` → `Idle`(마지막 결과 있음).

- 시작: 현재 프로필과 **새 측정 시계**(3.4)로 `MeasurementSession.Start`. 실패(`SessionStartException`: 두 저장 위치 모두 실패, 프로필 검증 실패) → `Idle` + 오류 알림 + 측정 화면 배너.
- 측정 중: 백그라운드 작업이 250 ms마다 `Live.Read(cursor)`를 부르고, 받은 것을 화면 모델에 넘긴다. 화면은 UI 스레드에서 프레임당 한 번만 반영한다. (데모 배속에서도 회차가 밀리지 않게)
- 잠정 분석: 새 회차가 있으면 5초마다 백그라운드에서 `AnalysisInputs()`(3.2) 사본으로 `MeasurementAnalysis.Analyze(header, rounds, gaps, events, null, provisional: true, elapsedMs, live)`. 이전 분석이 끝나지 않았으면 건너뛴다. 걸린 시간과 그 사본의 `At`·`ElapsedMs`를 진단 값과 기록에 낸다 (bench, G3 비교).
- 끝: 사용자가 중지(`StopAsync`, 확인 묻지 않음. 기록은 저장되고 되돌릴 일이 없음) 또는 계획 시간 완료. 중지를 누를 때 메모 초안이 있으면 먼저 메모를 넣고(세션 입력 통로, 3.1) 중지한다. 끝나면 최종 기록을 다시 읽어 확정 분석 → 결과 카드, 최근 측정 갱신, "측정이 끝났습니다" 알림.
- 저장되지 않은 회차(`Unsaved > 0`)나 봉인 실패는 결과 카드에 경고로 보여준다 (M3 설계 "화면이 알린다").
- **창 닫기**: 측정 중이면 지금처럼 멈추고 저장한 뒤 닫는다. 트레이로 숨기는 것은 M9(N7). 닫기 전 확인은 묻지 않는다.
- 측정 중에는 측정 구성 편집을 막는다 (읽기 전용 + "측정 중에는 바꿀 수 없습니다").

### 4.5 화면

모든 화면은 상태(빈, 불러오는 중, 정상, 문제, 오류)를 따로 정의한다 (기획서 7.5).

**첫 실행 안내 (N14)**
- 1단계 "연결을 확인했습니다": 탐지 중(카드 불러오는 중) → 결과 카드: 연결 종류, 공유기(찾음/못 찾음, 주소), 외부 대상 이름 둘, 측정 시간(10분 기본, `SegmentedChoice` 10분·30분·1시간·직접). 경고: 가상·VPN 어댑터("VPN이나 가상 어댑터를 통해 연결된 것 같습니다. 측정 결과가 실제 회선과 다를 수 있습니다"), 다른 게이트웨이, 로컬 대상 없음.
- 행동: **[이대로 측정 시작]**(주요) → 프로필 저장 → 측정 시작 → 측정 화면. [대상 고치기] → 측정 구성 편집(첫 실행 문맥, 저장하면 1단계로 돌아옴). [다시 확인].
- 네트워크 없음/IPv4 경로 없음: 이유 문장 + [다시 확인] + [대상 직접 입력]. (R5 "IPv4 경로 없음 안내")
- 첫 측정까지 조작: 측정 시간 기본값이면 **[이대로 측정 시작] 한 번**, 탐색 포함 두 번 이내 (G3이 센다).

**홈** (기준 이미지 배치. 빠른 진단 카드는 M6에서 더한다)
- 머리: 날짜(앱 시계 기준), "네트워크 상태", 칩(연결 종류·공유기·인터넷 지연).
- 큰 카드: 등급 고리 + 한 문장 + 숫자 줄 + [측정 시작]/[측정 중지] + [빠른 진단](진단 화면으로).
  - 측정 중: 잠정 등급 ("측정 중 · 잠정"). 첫 1분은 "관측 부족" (M4: 판단 가능한 회차 60 미만).
  - 측정하지 않을 때: 마지막 측정 결과 ("지난 측정 · 오늘 오후 1:20") 또는 처음이면 "아직 측정한 기록이 없습니다" + [측정 시작].
  - 프로필 없음: "측정 구성을 확인해 주세요" + [첫 실행 안내 열기].
- 경로 맵 카드 (4.6).
- 최근 2분 카드: 측정 중이면 실시간 타임라인(작은 크기), 아니면 빈 상태 "측정을 시작하면 최근 2분이 여기 그려집니다".
- 최근 측정 카드: 3줄 (등급 배지, 시작 시각, 길이·연결 종류·메모 첫 줄, 끊김 수, 최장). 불러오는 중/빈/오류(읽지 못한 기록 수). "전체 보기" → 기록(준비 중).
- 등급 표기: 좋음 A, 보통 B, 나쁨 C, 매우 나쁨 D, 관측 부족 "–", 판단 불가 "?". **점수(예: 96점)는 만들지 않는다**: 분석에 점수 개념이 없고, 근거 없는 정밀도를 보여주지 않는다 (기획서 N2 "근거 없이 좋은 등급을 주지 않음"). 기준 이미지의 "연결 품질 96점" 자리에는 등급 이름("좋음")을 쓴다. (DECISIONS에 기록)

**측정**
- 머리: "측정", 프로필 이름, 진행 막대(경과/계획, 남은 시간), [측정 시작|중지], [증상 표시], [측정 구성].
- 타임라인 카드 (4.7). 아래 범례 (인터넷 지연, 공유기 지연, 응답 없음, 관측 공백, 증상 표시, 링크 끊김).
- 증상 표시: 누르는 즉시 시각을 기록하고(3.1), 타임라인 아래 메모 패널이 열린다: "오후 2:32:10에 증상을 표시했습니다" + 글 상자 "무슨 일이 있었나요? (선택)" + [저장] [건너뛰기]. Esc는 건너뛰기. 단축키 **Ctrl+M** (측정 중일 때만).
- **메모 초안의 수명** [1-8]:
  - 초안은 측정 화면이 들고 있다. 다른 화면으로 갔다 와도 남는다.
  - 패널이 열린 채 다시 증상 표시: 글이 있는 초안은 **먼저 그 표시의 메모로 저장**하고(버리지 않음) 새 표시의 패널을 연다.
  - 측정이 끝나는 순간 패널이 열려 있으면: 패널은 그대로 두고 "측정이 끝났습니다. 메모는 기록에 따로 붙습니다"를 보이고, [저장]은 끝난 뒤 메모(3.1 `notes.jsonl`)로 쓴다. 저장이 실패하면 이유를 보이고 초안을 남긴다. 자동으로 버리지 않는다.
  - [저장]·[건너뛰기] 뒤 초점은 [증상 표시] 버튼으로 돌아간다. 측정이 끝나 버튼이 꺼져 있으면 [측정 시작]으로.
  - **확정까지 보관** [2-5]: 메모 초안은 (측정 ID, 표시 ID)별 보관함(`MemoDrafts`)에 쓰기 결과가 `Saved`가 될 때까지 남는다. 반복 표시·[저장]·중지·**창 닫기**·계획 완료는 모두 같은 저장 함수를 부른다 (측정 중이면 세션 입력 통로, 끝났으면 노트 쓰기). `Lost`나 노트 쓰기 실패면 그 초안이 증상 목록에 "저장하지 못함 · 다시 시도"로 남는다. 창 닫기는 보관함의 대기 중 저장을 최대 3초 기다리고, 그래도 남으면 닫기 전 기록(`app-log`)에 표시 ID와 실패만 남긴다 (메모 글은 남기지 않음).
  - **노트 쓰기** (`NotesWriter`): 앱에 하나인 직렬 작업이 한다. 쓰는 곳은 그 측정의 **요약이 있는 조각 폴더**(없으면 마지막 조각). 실패하면 1초·3초 뒤 두 번 다시 시도하고, 그래도 실패면 `Lost`. 다음 실행에서 자동으로 다시 쓰지 않는다 (보관함은 메모리에만 있음).
  - 시험: 끝나는 경계에서 저장, 패널 열린 채 반복 표시, 화면 이동 후 복귀, 저장 거부·실패 문구, 키보드만으로 (Ctrl+M → 입력 → Enter).
- 증상 목록: 시각·메모·[메모 고치기]. 목록 항목을 고르면 타임라인이 그 시각으로 이동하고 표시가 강조된다. (캔버스 위 표시를 키보드로 고르는 대신 목록이 같은 일을 한다)
- 대상 카드 (3.5 LiveSummary).
- 배너: 저장 실패(대체 위치로 옮김/저장 안 됨), 절전 공백 중, 응답 기준선 없는 대상, "끊긴 상태에서 시작했을 수 있음", 경로 보류.
- 끝난 뒤: 결과 카드(등급, 한 문장, 끊김 수, 최장, 저장 상태). "기록에서 자세히 보기"는 M7.

**측정 구성 편집 (R1)**
- 프로필 고르기(목록) + [새 프로필](현재 것 복사) + [삭제](마지막 하나는 불가) + 이름.
- 측정 시간(분, 1~720, 숫자 글 상자 + 10·30·60 빠른 선택), 예상 연결(상관없음/유선/Wi‑Fi), 응답 제한 시간(ms, 200~900, "고급"으로 접힘).
- 대상 줄: [위][아래] 순서, 사용 토글, 이름, 주소(IPv4), 역할(공유기·내부 장비 / 외부), 사업자, [삭제]. [대상 추가](최대 8). 새 대상 ID는 자동(`t1`…). 측정 방식은 ICMP만 편집한다. 파일에 TCP 대상이 있으면 "TCP 443 · 편집은 다음 단계에서"로 읽기 전용 (TCP 편집은 M9, M3 설계).
- [자동 탐지로 다시 채우기]: 탐지 제안으로 대상을 바꾼다 (저장 전까지 초안).
- 모든 변경은 **초안**이다. [저장]은 `ProfileValidator` 오류가 0일 때만 켜진다. 오류는 해당 칸 아래 빨간 글과 위쪽 요약에, 경고는 노란 배너로. [취소]는 초안을 버린다. 그래서 삭제도 저장 전에는 되돌릴 수 있다 (확인을 묻지 않음).
- 저장: `ProfileStore.Save` (임시 파일 → 바꾸기). 실패하면 오류 알림, 초안 유지.
- "대상 순서는 실제 경로를 증명하지 않습니다"를 목록 위에 적는다 (기획서 R1).

**설정 (최소)**: 테마(다크/라이트/Windows 따르기), 연한 오로라, 효과 줄이기, 움직임 줄이기, [측정 구성 열기]. 알림·저장 위치는 M9.

**준비 중 화면**: 진단·기록·리포트. 빈 상태 카드 하나. 홈의 [빠른 진단], "전체 보기"는 이 화면으로 간다.

### 4.6 경로 맵 부품 (`PathMap`)

- 노드 셋(원형 아이콘 + 이름 + 부제, 3.5의 관측 사실), 선 둘.
- 선 그리기: "응답 확인"은 실선, 아니면 점선 + 흐린 색. 구간 후보 선만 문제 색 + ✕ + "가능성이 높은 곳". 색만으로 전하지 않는다.
- 흐르는 빛: "응답 확인" 실선에만 작은 빛이 흐른다 (`Motion.Sweep`, 반복형). 후보 선이 새로 생기는 순간 `Motion.Blink` 3번. 움직임 줄이기에서 둘 다 없음.
- 화면 읽기: 맵 전체 이름 = "개념도. 공유기 응답함 2 ms. 외부 대상 2개 중 0개 응답. 가능성이 높은 곳: 공유기 너머".

### 4.7 겹침 타임라인 부품 (`Timeline`) (N1)

- 그리기: XAML `Polyline`·`Rectangle`로 그리되 점 수를 열 수 두 배로 제한한다 (3.5). 새 회차가 오면 마지막 열만 다시 계산하고, 창이 움직일 때만 전체를 다시 계산한다. M2 `LineChart`는 전시용으로 두고 새 부품을 만든다.
- 축: 세로 ms(창 안 최댓값을 20 ms 단위로 올림, 최소 40 ms), 가로 시각(창 길이에 맞는 눈금: "오후 2:31", "−1분" 등).
- 확대·이동: 창 길이 단계 1분·2분·5분·10분·30분·1시간·3시간·6시간·12시간·전체. 버튼 [−] [+] [전체] [지금으로], 좌우 이동 버튼. 키보드(타임라인에 초점): ←/→ 이동(창의 1/4), +/− 확대, Home/End 처음/지금. Ctrl+휠 확대, 휠 이동.
- **지금 따라가기**: 창의 오른쪽 끝이 "지금"이면 새 회차마다 창이 따라 움직인다. 사용자가 과거로 이동하면 따라가기를 멈추고 [지금으로]가 켜진다.
- 홈의 작은 타임라인은 같은 부품의 간단 모드(2분 고정, 조작 없음)다.
- 화면 읽기: 이름 = 요약 문장(3.5). 보이는 창의 범위를 `HelpText`로.

### 4.8 새 부품과 토큰

| 부품 | 상태 | 비고 |
| --- | --- | --- |
| `GlassTextBox` | 기본, 초점, 오류(빨간 테두리 + 아래 글), 비활성, 읽기 전용 | WinUI `TextBox` 틀 위에 보통 유리. 두 겹 초점 표시. 값 패턴 (자동화로 글 입력) |
| `Meter` | 진행, 완료 | 측정 진행 막대. 이름 = "10분 중 3분 12초" |
| `GradeRing` | 등급 6가지 | 고리 채움 = 등급 단계(A 4칸 … D 1칸), 관측 부족·판단 불가는 점선 고리 |
| `PathMap`, `Timeline` | 4.6, 4.7 | |
| `RecordRow` | 기본, 포인터, 초점, 불러오는 중 | 버튼 (호출 패턴) |
| `Banner` | 정보, 주의, 오류 | 글 많은 알림이 아닌 카드 안 한 줄. 아이콘 + 글자 |
| `PageHeader` | | 제목, 부제, 오른쪽 행동 |

- 새 아이콘: 중지, 연필, 더하기, 빼기, 위, 아래, 휴지통, 뒤로, 표시(깃발), PC, 공유기, 지구, 시계.
- 새 색 토큰을 만들지 않는다. 타임라인의 공유기 계열 = `series2`(점선), 인터넷 = `accent`, 응답 없음 띠 = `bad` + 강조 불투명도 토큰, 일부 응답 없음 = `warn`, 공백 = `faint` 빗금, 증상 = `warn`, 링크 끊김 = `bad`. 새 불투명도·굵기 값은 `Metrics`에 토큰으로 더한다.
- 정적 검사 규칙은 그대로 적용된다. `TextBox`는 금지 목록에 없다. 글 상자 안의 기본 시각 상태 애니메이션은 M2처럼 상태 없는 틀로 바꾼다.

### 4.9 키보드와 화면 읽기 (R5)

- 탭 순서: 탐색 막대(한 번 진입) → 화면 머리 행동 → 카드 순서대로. 측정 구성 편집의 대상 줄은 줄마다 한 번 진입하고 줄 안은 탭으로.
- Esc: 메모 패널 닫기 → 편집 화면 뒤로(초안이 있으면 "저장하지 않은 변경이 있습니다" 대화상자). 대화상자 규칙은 M2 그대로.
- 측정 시작·중지, 증상 표시, 저장은 모두 키보드로 닿는다 (`KeyboardTests`에 시나리오 추가).
- 실시간 값 변화는 화면 읽기에 계속 알리지 않는다 (소음). 끊김 감지·회복, 측정 끝, 저장 실패만 알림으로 알린다.

### 4.10 문구

- 결론 먼저, 쉬운 말 (기획서 7.5). "패킷 손실 2.1%" 옆에 "100번 중 2번 응답이 없었습니다".
- 단정하지 않는다: 띠는 "응답 없음이 관측된 회차", 맵은 "개념도", 후보는 "가능성이 높은 곳".
- 화면의 모든 문장은 화면 코드에 흩지 않고 화면별 문구 묶음(`Screens/Text.cs`)에 둔다 (M8 리포트·M11 문구 점검에서 한 곳을 본다).

## 5. 실시간 성능

- 기준(이 PC 한 대): 정지 구간 프레임 95백분위 16.7 ms 이하, 화면 전환·확대·이동 구간 최대 50 ms 이하이고 33 ms 초과가 구간당 2회 이하. 잠정 분석 1회 95백분위 500 ms 이하 (백그라운드라 프레임에 직접 걸리지 않지만 늦어지면 화면이 낡는다). 전용 메모리 400 MB 이하.
- **재현 절차** (`--bench measure`, M2 bench와 같은 구간 기록 방식) [1-10]:
  1. 시나리오 `long`(43,200회차 = 720분, 프로필 최대 측정 시간), `--demo-speed 600 --demo-speed-after 42600:1 --start`. 측정 화면, 창 2분. [2-6]
  2. 채우기: 42,600회차(11시간 50분)까지 600배속 (약 71초). 이 구간은 재지 않는다. 1배속으로 바뀐 뒤 계획 끝까지 10분이 남아 아래 구간(약 3분)이 측정 중에 끝난다.
  3. 1배속 전환 뒤 준비 10초 (버림).
  4. `idle-live`: 창 2분, 지금 따라가기, 90초.
  5. `zoom-full`: [전체]로 12시간 창 → 30초 정지.
  6. `pan`: 왼쪽 이동 10번 (1초 간격), [지금으로].
  7. `nav`: 홈 ↔ 측정 6번 (1.5초 간격).
  8. 잠정 분석 시간은 4~7 동안(준비 구간 제외) 5초마다 기록. 4~7은 약 145초라 약 29개다. 20개 미만이면 무효.
  9. 프레임 표본이 구간 길이 × 30개보다 적으면 무효. 무효면 한 번 다시 돌리고, 또 무효면 실패 (M2 규칙).
- 결과는 비공개 산출물, 요약만 `docs/loop/m5/bench.md`.
- 기준을 못 맞추면: 먼저 간추리기 열 수·갱신 주기를 조정하고, 그래도 안 되면 결과와 함께 보고한다 (Win2D 같은 새 의존성은 사용자 승인 사항).

## 6. 이월 지적

**M2 (G4 3라운드, 비차단)**
1. 창을 닫을 때 진행 중인 원형 전환의 정리를 기다리지 않음 [1-11] → 닫기 순서를 바꾼다:
   1. `Theme.BeginShutdown()`: 새 전환과 대기 요청을 받지 않는다.
   2. 진행 중 전환에 취소를 요청하고, **UI가 살아 있는 동안** 그 전환의 `finally` 정리(클립 해제, 찍은 화면 제거, 유리 복귀, 렌더링 구독 해제)가 끝나기를 기다린다 (`Theme.ShutdownAsync()`가 돌려주는 작업).
   3. 2초 안에 끝나지 않으면 기다림을 멈추고 **같은 정리를 UI 스레드에서 직접** 실행한다 (정리 함수는 여러 번 불려도 한 번만 일한다). 기록에 `themeCleanupTimeout`.
   4. 그 뒤 `Detach` → 창 닫기.
   - 시험: `--reveal-hold`로 전환 도중에 멈춘 채 닫기. 닫기 직전 진단 값에서 찍은 화면 층 0, 클립 없음, 렌더링 구독 0을 확인하고, 기록에 `themeError` 없이 정상 종료.
2. 대화상자 뒤 범위에 글자·그래프색이 없음 → 대화상자 배후 범위에 `content` 표면 위 글자·그래프·상태색을 넣는다 (`BackgroundRange`). `muted`가 4.5 아래로 계산되면 대화상자 재질 불투명도를 올리거나 대화상자 안 보조 글자를 `ink`로 바꾼다 (값은 구현에서 계산으로 정하고 DECISIONS에 기록). 실측 대비 장면에 대화상자를 더한다.
3. 라이트 세 재질의 두께 구분이 약함 → 테두리·위쪽 하이라이트·그림자 토큰을 단계별로 벌린다. 대비 시험은 그대로 통과해야 한다. 전시 화면 재질 캡처로 확인.

**M4 (G4 5·6라운드, 비차단 + 새 저장소 CI)**
1. 링크 표본 마감 검사의 두 위치(받을 때, 큐에서 꺼낼 때)를 각각 시험: 받을 때는 마감 뒤 표본을 콜백으로 넣어 큐에 들어가지 않음을, 꺼낼 때는 시험 지점으로 큐에 이미 들어간 표본이 마감 뒤 처리에서 버려짐을 고정.
2. 넘침 경쟁 시험의 `Task.Delay(200)` → 큐 배출과 재관측 생산자 진입을 신호로 확인하고, 분리된 두 다운 구간의 존재와 경계를 단언.
3. `OverflowIsRecorded`의 CI 시간 초과 → 먼저 넘침 중 회차 처리 지연이 제품 문제인지 잰다 (알림 3000개 동안 회차 처리 지연 시간). 제품 문제가 아니면 시험을 신호 기반으로 바꾸고 제한시간을 처리 완료 신호로 대체한다. 제품 문제면 고치고 기록한다.

## 7. 테스트 계획

### 7.1 G2 (CI에서도 돎)

- Core:

  - 기록 목록: 최신순, 조각 묶음, 두 축(`Running`/`Ended`/`NoSummary` × `Ok`/`Damaged`/`MissingSegments`/`Unreadable`), 손상된 요약, 현재 측정 ID.
  - 데모 세계: 탐지 결과·실패·늦음, 측정마다 새 시계(안내 화면 대기 뒤 0회차, 다시 측정), 멈춤 회차에서 시간이 멈추고 중지는 끝남, 배속 전환 경계, 고장 주입(저장 시작 실패·중간 실패·회복, 절전 공백), 시나리오 선택 항목 없음·있음.

### 7.2 G3 데모 시나리오 (`FirstRunToStopTests`, 로컬)

빈 사용자 폴더, `--demo outage-long --demo-speed 20`. 단계마다 60초, 전체 10분 (기획서 4.9).
`outage-long` [2-7]: 0~89회차 정상(기준선과 등급에 필요한 60회차를 넘김), 90~149회차 외부 대상 둘 다 손실·공유기는 응답 → 예상 후보 `AfterRouter`. `link-drop`도 같은 방식으로 90회차까지 정상 뒤 링크 다운 → 예상 후보 `PcLink`.
1. 첫 실행 안내가 뜨고 탐지 결과가 시나리오와 같다 (연결 유선, 공유기 192.0.2.1, 외부 대상 이름 둘).
2. [대상 고치기] → 외부 대상 하나 이름을 바꾸고(값 패턴) 측정 시간을 3분으로 → [저장] → 1단계로 돌아옴. (R1 경로)
3. [이대로 측정 시작] → 측정 화면. 첫 실행부터 측정 시작까지 조작 수를 센다 (2단계 편집을 뺀 기본 경로는 별도 시험 `FirstMeasurementStartsInTwoActions`).
4. 100회차 이후 [증상 표시] → 메모 "화상회의 중 끊김" → [저장].
5. 120회차 이후 (끊김 진행 중): 타임라인 요약 이름에 "외부 응답 없음 1번 · 이어지는 중", 증상 표시 1개. 경로 맵이 그린 후보가 **`AfterRouter`**이고, 진단 값으로 낸 그 분석의 `At`·`ElapsedMs`까지로 기록을 잘라 시험이 다시 계산한 M4 분석 후보와 같다 [2-7].
6. 계획 끝(180회차)까지 기다림 → 결과 카드.
7. 기록 검사: 머리의 대상 이름(바꾼 이름), `symptom` 이벤트와 메모, 요약 `Completed`. 시험이 Core로 기록을 다시 분석해 결과 카드의 등급 이름·끊김 수, 대상 카드의 손실률·최대 연속 실패가 **같은지** 본다.
8. 홈: 최근 측정 첫 줄이 이 측정이고 등급·끊김 수가 같다.
9. 같은 사용자 폴더로 다시 실행: 첫 실행 안내가 뜨지 않고, 측정 구성 편집에 바꾼 이름이 있고, 최근 측정에 남아 있다.

추가 시험: 측정 중 중지(`Stopped`), 측정 중 편집 막힘, 프로필 검증 오류가 저장을 막음, 네트워크 없음 데모의 첫 실행, 확대·이동·지금으로(보이는 범위 진단 값), 화면 전환 여섯 항목, 측정 중 창 닫기(저장 후 종료, 요약 `Stopped`).

### 7.3 실측 시나리오 (로컬, 공개하지 않음)

데모 옵션 없이 빈 사용자 폴더: 첫 실행(실제 탐지) → 측정 시작 → 20초 뒤 증상 표시 → 중지 → 기록 저장 확인 → 다시 실행해 최근 측정에 있음. 응답 성공 여부는 통과 조건이 아니다 (기획서 4.3). 캡처·로그는 `.loop/shots`, `.loop/logs`.

## 9. 대안

- **Win2D로 타임라인**: 빠르지만 새 런타임 의존성(사용자 승인 사항). 간추리기로 점 수를 제한하면 XAML로 충분할 것으로 보고 bench로 확인한다.
- **엔진 구독만으로 실시간 화면**: 중간 상태를 건너뛸 수 있어 타임라인에 구멍이 생긴다. 커서 방식(3.2)을 고른다.
- **기록 파일을 다시 읽어 실시간 화면**: 디스크를 매초 읽고, 쓰기 중인 줄을 다룬다. 세션 메모리에 이미 있는 것을 쓴다.
- **증상 메모를 처음부터 별도 파일에만**: 측정 중 메모까지 노트로 쓰면 기록 본문만으로 측정을 읽을 수 없다. 측정 중에는 이벤트로, 봉인 뒤에만 같은 폴더의 `notes.jsonl`로 쓴다 (3.1).
- **점수(0~100)**: 기준 이미지에 있지만 분석에 근거가 없다 (4.5).
- **대화상자 안에 메모 입력**: 대화상자에 콘텐츠 칸이 없고, 표시 직후 화면을 가리면 타임라인을 보며 쓰기 어렵다. 타임라인 아래 패널로 한다.

## 10. 이 마일스톤에서 하지 않는 것
