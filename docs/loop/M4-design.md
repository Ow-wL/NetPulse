## A. 근거 수집

### A1. 이 PC 실측 (설계 근거, 관리자 아님)

`docs/loop/m4/pc-measurement.md` 1절 (이름·주소 없이). 요점: 관리자 아니어도 후보 로그가 모두 읽힘. 지난 30일 유선 링크 다운 46건·업 41건. 다운→업 최소 0.17초, 중앙 3.4초, 최대 110초. 드라이버 이벤트에는 어댑터 설명 문자열(데이터 3개 중 두 번째), 무선 이벤트에는 인터페이스 GUID. 인터페이스 전체 열거는 회당 약 8~10 ms.

결론: 직접 관측은 **상태 표본**이라 짧은 다운·업을 놓칠 수 있다. 전이를 기록하는 드라이버 로그가 그 틈을 메운다. 둘 다 쓰고, 둘 다 보장값으로 말하지 않는다. [1-1]

### A2. 직접 관측 (기본 경로) — `LinkObserver`

- **감시 대상**: 측정 대상들의 경로가 쓰는 인터페이스. 내부에서는 **LUID·GUID**로 식별하고(재활성화 때 번호가 바뀔 수 있음), 기록에는 세션 안 **어댑터 별칭**(`a1`, `a2` …)과 그때의 인터페이스 번호·유형·가상 여부를 쓴다. GUID·설명은 기록하지 않는다. [1-3]
  - 측정 시작 때 감시할 인터페이스가 없으면(경로 없음) 수집 능력은 `unsupported`, 사유 `no-interface`. 이후 경로가 생기면 그때부터 감시. [1-1]
- **알림 + 회차 읽기**: `NotifyIpInterfaceChange` 알림이 오면, 그리고 엔진 회차마다, 감시 인터페이스를 `GetIfEntry2`로 읽는다. 콜백 스레드는 읽기와 큐 넣기만 한다.
- **표본의 뜻**: 읽은 결과는 "그 시각에 본 상태"(`observedAt`)다. 전이가 실제로 일어난 시각이 아니다. 알림 처리 전에 다운·업이 끝나면 직접 관측은 그 다운을 못 본다 (로그가 보완). 해상도는 보장하지 않으며 문서·화면에 "직접 관측은 상태 표본"으로 적는다. [1-1]
- **상태 해석**: `MediaConnectState = Disconnected` 또는 `OperStatus ∈ {Down, LowerLayerDown, NotPresent}` → `down`. `Connected` + `Up` → `up`. 그 밖·읽기 실패 → `unknown`. 사라짐 → `removed`.
- **같은 상태 연속은 버린다** (알림과 회차 읽기가 같은 상태를 두 번 봐도 한 번).

### A3. 로그 (보완 경로) — `LinkLogReader`

**해석표는 실측으로 확인한 것만** [1-3]:

| 로그 | 공급자(정확히) | 다운 | 업 | 어댑터 단서 | 확인 |
| --- | --- | --- | --- | --- | --- |
| `System` | `e2fexpress` | 27 | 32 | 이벤트 데이터 2번째(문자열) = 어댑터 설명 | 이 PC |
| `System` | `e2fnexpress` | 27 | 32 | 같음 | 이 PC |
| `Microsoft-Windows-WLAN-AutoConfig/Operational` | `Microsoft-Windows-WLAN-AutoConfig` | 8003 | 8001 | 필드 `InterfaceGuid` | 이 PC (필드만. 이 PC 측정 연결은 유선) |

- 다른 공급자는 추측해 넣지 않는다. 필드가 없거나 자료형이 다르면 그 이벤트는 `unparsed`로 세고 쓰지 않는다.
- **어댑터 대응**: 지금 있는 **모든** 어댑터(측정에 안 쓰는 것·내려간 것 포함)에서 설명이 유일하게 맞으면, 또는 GUID가 맞으면 그 어댑터. 설명이 둘 이상과 맞으면 `ambiguous`, 없으면 `unlinked` → **판정에 쓰지 않는다**(사실로 보존·표시만).
- 측정 구간 로그만 판정에 쓴다. 측정 시작 전 이벤트(빠른 진단의 최근 30분 포함)는 "지금 어댑터 기준 대응"이므로 판정 근거가 아니라 참고(`historical`)로만 쓴다.
- **언제**: 측정이 끝난 뒤 한 번. 측정 끝 3초 뒤까지 기다리되(벽시계, 최대 3초) 조회 자체는 제한 5초. 넘으면 로그 경로는 `unsupported`, 사유 `timeout`. [1-13]

### A4. 근거 상태: 세 축 [1-2]

경로(직접 / 로그)마다, 감시 어댑터마다 세 가지를 따로 둔다.

| 축 | 값 |
| --- | --- |
| **수집 능력** | `supported` / `unsupported`(사유) / `denied` |
| **관측 범위** | 직접: 측정 시간 중 성공 읽기가 있던 회차 비율과 미관측 구간 목록. 로그: 읽은 구간 |
| **링크 상태(시간별)** | `up` / `down` / `unknown` 구간들 |

R2의 네 표시 상태는 여기서 계산한다:

| 표시 | 조건 |
| --- | --- |
| `unsupported` | 수집 능력이 `unsupported`, **또는 관측 범위가 90% 미만**(사유 `partial`) |
| `denied` | 수집 능력이 `denied` |
| `down` | 다운 구간이 하나라도 관측됨 (범위와 무관) |
| `observed-none` | 지원되고, 관측 범위 90% 이상이고, 다운 없음 |

- `unsupported`·`denied`·`partial`은 **"정상"으로 표시하지 않는다.**
- **다운 구간의 끝**: `down` 다음이 `up`이면 그 시각, `unknown`이거나 기록이 끊겼으면 **마지막으로 `down`을 본 시각까지만** 확정 다운이고 그 뒤는 미확인이다 (측정 끝까지 늘리지 않음). [1-2]
- 직접과 로그는 합집합으로 쓴다. 각 다운 구간에 출처를 단다. 직접 관측이 놓친 짧은 다운이 로그에만 있는 것은 정상적인 경우다 (충돌로 보지 않음).

### A5. 기록

**`link` 이벤트** (M3 6.3 계약을 채움, `events.jsonl` 공통 필드 `id`·`type`·`at`·`wall`·`round?`에 더해):

| 필드 | 뜻 |
| --- | --- |
| `source` | `direct` / `log` |
| `adapter` | 세션 어댑터 별칭 (`unlinked`·`ambiguous`면 없음) |
| `interfaceIndex`, `kind`, `virtual` | 그 시점 인터페이스 번호·유형·가상 여부 |
| `collection` | 상태 표본(`up`/`down`/`unknown`/`removed`), 요약(`unsupported`/`denied`/`observed-none`/`partial`), `overflow` |
| `eventWall` | 원본 시각 (직접: 읽은 시각, 로그: 이벤트 시각, UTC) |
| `eventMs` | `eventWall`을 측정 경과 시간으로 환산한 값. 환산할 수 없으면 없음 (A6) |
| `link` | `linked` / `unlinked` / `ambiguous` / `historical` |
| `code`, `coverage` | 실패 사유 코드, 요약일 때 관측 범위 |

- 공통 필드 `at`은 **기록한 시점**의 경과 ms, `eventMs`는 **사건 시점**이다. 판정은 `eventMs`만 쓴다. [1-4]
- 시작 때 감시 어댑터마다 수집 능력 한 줄, 끝날 때 경로·어댑터마다 요약 한 줄(직접·로그 둘 다). 요약 줄이 없는 기록(중간에 끊김)은 읽을 때 그 경로를 `unsupported`(사유 `interrupted`)로 본다.

**링크 흐름과 유실** [1-13]:
- 직접 관측 표본은 엔진 회차와 별개의 **제한 큐**(1024)로 세션 처리 작업에 들어가 회차와 같은 작업이 순서대로 쓴다. 가득 차면 버린 수를 세고 `collection: overflow`(개수) 줄을 남기며, 그 구간은 관측 범위에서 빠진다.
- 이벤트 쓰기 대기가 상한을 넘어 오래된 이벤트를 버리면(M3 동작) 그 수를 요약의 **`eventsDropped`**에 적고, 다시 읽을 때 이벤트 손상으로 표시한다 (지금은 조용히 버림 → 고침).
- 종료 순서: 엔진 정지 → 알림 해제(해제 뒤 도착한 콜백은 버림) → 큐 배출 → 로그 읽기(A3 기한) → 요약. M3의 마감·제한 규칙 안에서 한다.

### A6. 로그 시각 환산 [1-4]

- **대응 구간**: 측정 동안 `벽시계 − 경과 시간` 차이가 일정한 구간들. 경계는 절전 공백(M3 `gap` suspend)과 시각 변경(`clock`) 이벤트.
- 로그 이벤트의 UTC가 **정확히 한 구간**에만 들어가면 그 구간의 차이로 `eventMs`를 계산한다.
- 절전 공백의 벽시계 범위 안이거나, 시각이 뒤로 가서 두 구간에 겹치거나, 측정 범위 밖이면 **환산하지 않는다**: 원본 UTC만 보존하고 판정에서 뺀다 (표시만).

### A7. 기록 확장 (M3 형식 버전 1 안에서 필드 추가) [1-5]

| 위치 | 필드 | 없을 때의 의미 |
| --- | --- | --- |
| `measurement.json` | `expected`: `any`/`wired`/`wireless` | `unrecorded` — 사용자가 고른 "상관없음"과 다르다. 판정은 유형 비교를 하지 않고 "예상 연결 유형 미기록"을 결론에 붙인다 |
| `rounds.jsonl` | `end`: 측정 공급자 결과를 다 받은 경과 ms | `at + timeoutMs` (최대 범위로 봄) |
| `summary.json` | `eventsDropped` | 0 |

## B. 판정

### B1. 입력과 원칙

- 입력: 기록 하나(머리의 대상·역할·사업자·주소·예상 연결 유형, 회차와 끝 시각, 공백, 경로 이벤트, 링크 근거). 측정 중에는 지금까지의 회차로 같은 분석을 하고 결과를 **잠정**으로 표시한다 (기준선이 바뀌면 지난 판정도 바뀔 수 있음).
- 분석 결과는 저장하지 않고 읽을 때마다 계산한다. 결과에 `analyzerVersion = 1`.
- 응답 조합은 **관측 결과**, 원인 구간은 **후보**. 사용자 대상 순서는 경로 증거가 아니다.

### B2. 응답 기준선

- 대상이 측정 전체(측정 중이면 지금까지)에서 성공을 한 번이라도 했으면 "기준선 있음". 기준선 없는 대상은 판정에서 빼고 "응답 기준선 없음"으로 표시. **모든 대상이 기준선 없음**이면 판정 전체를 판단 불가로 두고 "끊긴 상태에서 시작했을 수 있음".
- **외부 다양성**: 기준선 있는 외부 대상 중 **사업자 이름이 서로 다르고 주소도 서로 다른** 것이 둘 이상. [1-6] 프로필 검증에 "같은 주소 대상 중복"을 오류로 더한다.

### B3. 회차 판정

공백 회차는 판정하지 않는다. **불완전**(활성 대상 결과 누락 또는 검사 오류)은 판정과 별개로 항상 표시한다 (M3 통계와 같음). [1-6]

손실 없는 회차는 `정상` 또는 `지연 상승`(B6). 기준선 있는 대상의 손실이 있는 회차는 위에서부터 처음 맞는 것:

| 순서 | 판정 | 조건 |
| --- | --- | --- |
| 1 | **판단 불가 (경로 보류)** | 손실 대상 중 하나라도 회차 시점 경로가 실패했거나 유형이 예상 유형과 다름. 링크 다운이 함께 관측돼도 이 판정을 유지하고, 링크 사실은 "함께 관측된 근거"로 단다 [1-7] |
| 2 | **로컬 링크 단절 관측** | 손실 대상 중 하나의 회차 시점 경로 인터페이스가 **물리 어댑터**(유선·무선이고 가상 아님)이고, 그 어댑터의 **확정 다운 구간이 회차 [시작, 끝]과 겹침** (끝 = 기록의 `end`). 가상·터널 인터페이스의 다운은 "인터페이스 다운 관측" 사실로만 단다 [1-7] |
| 3 | **외부 연결 단절 추정** | 외부 다양성 조건을 채우고, 기준선 있는 외부 대상 **모두**가 이 회차에 유효 결과(성공·손실)를 냈고 **모두 손실** |
| 4 | **판단 불가 (근거 부족)** | 유효 결과를 낸 기준선 있는 외부 대상이 모두 손실인데, 오류·누락으로 결과가 없는 외부 대상이 있거나 다양성 조건을 못 채움 [1-6] |
| 5 | **대상 응답 실패** | 그 밖의 손실 (가까운 대상 실패·먼 대상 성공 포함). 실패 대상 목록을 단다 |

- 회차 [시작 − 1초, 끝 + 1초]에 걸친 다운은 **시간상 인접한 링크 근거**로 상세에 보여 주지만 판정 조건은 아니다. [1-7]
- 기준선 없는 대상의 손실은 판정 조건에 들어가지 않는다. 오류만 있는 회차는 불완전 + 판정 없음.

### B4. 끊김 구간(N3)과 구간 후보

- **구간**: 기준선 있는 대상의 손실이 있는 회차가 회차 번호로 이어지면 한 구간. 공백·건너뜀·손실 없는 회차에서 끊는다. 손실과 오류가 함께 있는 불완전 회차는 구간에 들어간다. 길이는 M3 `LossRun`과 같은 경과 시간 범위(최소·최대, 열린 끝).
- **하위 구간**: 구간 안에서 같은 판정이 이어지는 최대 묶음. [1-8]
- **구간 요약**: 하위 구간이 하나면 그 판정, 둘 이상이면 **`혼합`**(대표 판정을 고르지 않음). 혼합 구간은 하위 구간 목록을 단다.
- **통계와 등급은 하위 구간으로 센다**: "외부 연결 단절 추정 구간 수·길이"는 외부 단절 하위 구간만. 경로 보류·근거 부족 하위 구간의 길이를 확정 단절 길이에 넣지 않는다. [1-8]
- **구간 후보** (개념도 PC → 공유기 → 인터넷. 실제 패킷 경로라고 하지 않음). 하위 구간마다:

| 하위 구간 판정 | 조건 | 후보 |
| --- | --- | --- |
| 로컬 링크 단절 관측 | — | "이 PC의 [유선/무선] 링크" (어댑터 다운 관측됨. 원인이 링크라는 단정은 아님) |
| 외부 연결 단절 추정 | 기준선 있는 로컬 대상이 **모두** 성공, 그리고 외부 대상과 같은 인터페이스 경로 | "공유기 이후 (인터넷 쪽)" |
| 외부 연결 단절 추정 | 기준선 있는 로컬 대상이 **모두** 손실, 같은 인터페이스 경로 | "PC~공유기 구간 또는 공유기" |
| 외부 연결 단절 추정 | 로컬 대상 일부만 손실, 로컬 기준선 없음, 로컬 대상 없음, 경로 인터페이스가 다름 | 후보 없음 (사유) |
| 대상 응답 실패 | — | 후보 없음 (그 대상 문제이거나 응답 제한일 수 있음) |
| 판단 불가 | — | 후보 없음 (사유) |

- 끊김 목록 통계(N3): 판정별 하위 구간 수, 최장·평균 길이(최소 길이 기준, 열린 끝 개수 따로).
- 구간 상세(N1·M7용): 앞뒤 2회차 응답, 시작 시점 대상별 경로, 인접 링크 근거 (최대 8건).

### B5. 등급 (N2)

**판정 가능한 외부 관측**: 공백 아닌 회차 중, 기준선 있는 외부 대상 **모두**가 유효 결과(성공·손실)를 낸 회차. [1-9]

| 등급 | 조건 (위에서부터) |
| --- | --- |
| **관측 부족** | 판정 가능한 외부 관측이 60회차 미만, 또는 공백 아닌 회차의 80% 미만, 또는 외부 다양성 조건 미충족 |
| **판단 불가** | 판단 불가 회차가 손실 회차의 50% 이상 **이고** 3회 이상 |
| **매우 나쁨** | 로컬 링크 단절 관측 하위 구간 1개 이상, 또는 외부 단절 하위 구간 3개 이상, 또는 그 하나의 최소 길이 30초 이상, 또는 외부 손실률(기준선 있는 외부 대상 평균) 5% 이상 |
| **나쁨** | 외부 단절 하위 구간 1개 이상, 또는 외부 손실률 1% 이상, 또는 지연 상승 회차 10% 이상 |
| **보통** | 대상 응답 실패 회차 1% 이상, 또는 지연 상승 회차 3% 이상, 또는 외부 손실 1회 이상 |
| **좋음** | 그 밖 |

- 비율의 분모는 **관측한 회차**(측정 중이면 지금까지, 조기 중지면 중지까지)다. 계획 대비 진행률은 따로 보고하고 등급에 쓰지 않는다. [1-9]
- 반례 시험: 첫 회차만 성공하고 나머지가 검사 오류인 기록 → 관측 부족 (1판에서는 좋음이었음).
- 링크 근거가 `unsupported`·`denied`·`partial`이면 결론에 "링크 근거를 얻지 못함"을 붙인다 (등급을 올리지도 내리지도 않음). 예상 연결 유형 미기록도 결론에 붙인다.
- **한 문장 결론**: 등급 + 가장 큰 사유 하나. 문장 목록은 코드 상수로 두고 시험한다.

### B6. 지연 기준선과 지연 상승 [1-10]

- 이 기능은 **측정 전체 대비 이상치(순간 상승)** 탐지다. 측정 도중 지연이 계속 높아진 **지속 악화**는 이것으로 잡지 않는다는 한계를 결론·문서에 적는다. 지속 악화는 5분 창별 중앙값을 결과에 담아 M7 그래프에서 보이게 한다 (판정·등급에는 쓰지 않음).
- 대상별 기준선 = 성공 지연의 중앙값. 성공이 20개 미만이면 기준선 없음. 임계값 = `중앙값 + max(2 × 중앙값, 30 ms)`. 실측으로 검증된 값이 아니며 시험으로 고정한다.
- 측정 중 결과는 잠정(기준선이 바뀌면 과거 표시가 바뀜).

## C. 빠른 진단 (F1)과 사이트 점검 (F2)

### C1. 검사와 대상별 결과 [1-12]

모든 검사에 제한시간. **두 대상 검사는 대상마다 따로 제한**하고 대상별 결과를 보존한다 (하나가 늦어도 다른 하나의 성공을 버리지 않음). 늦게 끝난 작업의 예외는 관찰만 하고 버린다.

대상별 결과: `ok` / `fail`(확정 실패: 연결 거부 아닌 시간 초과·응답 없음, DNS 이름 없음, HTTP 오류 상태 등) / `error`(검사 자체를 못 함: 소켓 오류, 예외) / `timeout`(제한 초과).

| 검사 | 대상 | 하는 일 | 제한 |
| --- | --- | --- | --- |
| 어댑터 | 1 | 외부 주소로 가는 가장 좋은 인터페이스의 IPv4, 게이트웨이, DNS 서버 유무 | 2초 |
| 게이트웨이 | 1 | 게이트웨이에 ICMP 1회 | 1초 |
| 외부 TCP 443 | 2 | 기본 외부 대상 두 주소에 TCP 연결 (`TcpProbe`: 거부 = `ok`, 시간 초과 = `fail`, 소켓 오류 = `error`) | 대상마다 3초 |
| DNS | 2 | 도메인 둘을 Windows 해석기로 | 대상마다 3초 |
| HTTPS | 2 | 같은 두 도메인에 HEAD, 리디렉션 안 따름, 쿠키 없음, 인증서 검증 유지. 200~499(407 제외) `ok` | 대상마다 4.5초 |
| 네트워크 로그인 | 1 | 연결 확인 주소에 HTTP GET, 본문 64바이트 비교 | 4.5초 |
| 링크 근거 | — | 지금 상태(직접 한 번 읽기) + 최근 30분 로그(`historical`) | 3초 |

**두 대상 검사의 판정** (조합표):

| 대상 결과 | 판정 |
| --- | --- |
| `ok` 둘 | 정상 |
| `ok` 하나 + 나머지 아무것 | 확인 ("일부만 성공") |
| `ok` 없음, `fail` 하나 이상 | 실패 |
| `ok`·`fail` 없음 (`error`·`timeout`만) | 미측정 (사유) |

**한 대상 검사의 판정**:
- 어댑터: IPv4 없음(169.254 포함)·어댑터 내려감 → 실패. 게이트웨이 없음 → 확인. 경로 없음 → 작동 인터페이스 있으면 확인, 없으면 실패. 조회 오류·시간 초과 → 미측정.
- 게이트웨이: 응답 정상, 무응답 **확인**(Ping을 막을 수 있음), 게이트웨이 모름·오류 미측정.
- 네트워크 로그인: 본문 일치 정상. 200인데 다름 또는 3xx·4xx 확인. 그 밖 미측정.
- 링크 근거: **지금 다운이면 로그 상태와 무관하게 실패**. 그 밖에 30분 안 다운 → 확인. 지금 상태를 읽었고 로그가 `observed-none` → 정상. 로그가 `unsupported`·`denied` → 미측정(사유)이되 "지금 링크는 연결됨" 사실은 보존. 지금 상태도 못 읽으면 미측정.
- 게이트웨이 검사만 어댑터 결과를 기다리고 나머지는 동시에.
- 기본 주소·도메인(기본 외부 대상 두 주소, `www.microsoft.com`·`www.google.com`, `http://www.msftconnecttest.com/connecttest.txt`의 `Microsoft Connect Test`)은 설정 가능한 기본값 (설정 화면은 M9).

### C2. 결론과 안내 (N5) [1-11]

위에서부터 처음 맞는 것 하나가 주 결론, 맞는 나머지는 "함께 볼 것". **조건에 쓰는 검사가 미측정이면 그 규칙은 맞지 않는 것으로 본다.**

| # | 조건 | 찾은 것 | 해볼 것 |
| --- | --- | --- | --- |
| 1 | 링크 근거 실패 | 어댑터 링크가 지금 내려가 있음 | 케이블·포트 → 다른 포트 → 어댑터 다시 사용 |
| 2 | HTTPS 정상·확인, TCP 실패 | 웹은 되지만 IPv4 직접 연결이 안 됨 | IPv6·프록시·VPN 사용 여부 |
| 3 | TCP 정상·확인, DNS 실패 | 이름 해석 문제 | DNS 캐시 비우기(F7, 확인 후) → 재검사 → 어댑터 DNS 설정 |
| 4 | HTTPS 실패·확인, 네트워크 로그인 확인 | 공용 Wi‑Fi 로그인이나 프록시 정책 | 브라우저로 로그인 페이지 |
| 5 | 어댑터 실패, TCP 실패, HTTPS 실패 | PC 연결 자체 | 케이블·Wi‑Fi 접속 확인 |
| 6 | TCP 실패, HTTPS 실패 | 게이트웨이 정상이면 공유기 이후, 아니면 게이트웨이와 외부 모두 | 다른 기기 → 공유기 재시작 → 통신사 |
| 7 | HTTPS 실패·확인 | 웹 연결 추가 확인 필요 | 프록시·VPN·시계·인증서 |
| 8 | 링크 근거 확인 | 최근 30분 안에 링크가 끊긴 적 있음 (지금 어댑터 기준) | 실시간 측정으로 간헐 끊김 기록 |
| 9 | (TCP 또는 HTTPS 정상·확인) 그리고 (게이트웨이 또는 로그인 확인) | 인터넷은 되지만 예외 관측 | 설명만 |
| 10 | 어댑터 정상, **TCP·DNS·HTTPS 모두 정상** | 기본 연결 정상 | 간헐 끊김이면 실시간 측정 |
| 11 | 그 밖 (근거 부족) | **진단 근거 부족**: 확인하지 못한 검사 목록 | 다시 검사, 실시간 측정 |

- 정상 결론(10)은 성공 관측이 있어야만 나온다. 미측정이 섞이면 11로 끝난다.
- 일부 성공(`확인`)은 결론 문장에 "일부만 성공"으로 그대로 쓴다 (이어받을 규칙).
- **이전 결과 비교**: 검사마다 판정이 바뀐 것 목록 (화면은 M6).
- **복사 텍스트**: 검사 판정·결론·안내만. 주소·도메인 결과값·어댑터 설명·예외 메시지·사용자 대상 이름은 넣지 않는다.

### C3. 사이트 점검 (F2)

- 입력 검증: 도메인 형식(점 하나 이상, 레이블 규칙, 레이블 63자·전체 253자, IP 주소·스킴·경로·포트 거절. 국제 도메인은 IDN 변환 뒤 검사).
- DNS 한 줄, HTTPS 한 줄 (C1과 같은 대상별 결과·판정).

### C4. 진단 결과 기록

- `diagnosis-<시작 UTC>.json`, `format: "netpulse.diagnosis"`, `version: 1`: 시작·끝 시각, 앱 버전, 연결된 측정 Id(있으면), 검사마다 판정·사유 코드·소요 시간·**대상별 결과**(대상은 `t1`·`t2` 같은 순번, 주소 없음), 결론 번호들.
- 실행 상태를 구별한다: `run`(결과 있음) / `notRun`(사용자가 고르지 않음·앞 검사 때문에 생략, 사유) / `timeout`·`error`(실행했으나 결과 없음). [1-12]
- 저장은 M6 화면에서 부른다. M4는 형식·쓰기·읽기·손상 처리.
