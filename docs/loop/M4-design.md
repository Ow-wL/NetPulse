## A. 근거 수집

### A1. 이 PC 실측 (설계 근거, 관리자 아님)

`docs/loop/m4/pc-measurement.md`에 이름·주소 없이 남긴다. 2026-11-13 측정.

| 항목 | 결과 |
| --- | --- |
| 로그 읽기 (관리자 아님) | `System`, `NetworkProfile/Operational`, `WLAN-AutoConfig/Operational`, `NCSI/Operational`, `Dhcp-Client/Admin`, `Wired-AutoConfig/Operational` 모두 읽힘 |
| 유선 드라이버 링크 이벤트 (`System`) | 지난 30일 링크 다운(27) 46건, 업(32) 41건 (Intel 계열 유선 드라이버 두 종류). 하루 15회인 날도 있음 |
| 다운 → 업 간격 | 157쌍: 최소 0.17초, 중앙 3.4초, 최대 110초 |
| 드라이버 이벤트의 어댑터 식별 | 이벤트 데이터에 어댑터 설명 문자열이 있다 (장치 경로·GUID는 없음) |
| 무선 로그 | 연결 끊김(8003)·연결(8001)에 인터페이스 GUID가 있다 |
| `NetworkProfile` 10000/10001 | 네트워크 프로필 GUID만 있고 인터페이스 식별이 없다 → 링크 근거로 쓰지 않음 |
| 인터페이스 전체 열거 비용 | `GetAllNetworkInterfaces` 회당 p50 7.8 ms, p95 10 ms (PowerShell 기준) → 회차마다 열거하지 않음 |

결론: **1초 주기 조회만으로는 1초 미만 끊김을 놓친다.** 기본 경로는 변경 알림 + 회차 확인, 로그는 보완 경로다.

### A2. 직접 관측 (기본 경로) — `LinkObserver`

- **감시 대상**: 측정 대상들의 경로가 쓰는 인터페이스 번호 집합 (M3 경로 관측 결과). 경로가 새 인터페이스로 바뀌면 그 인터페이스도 감시에 넣는다. 감시는 측정 끝까지.
- **알림**: `NotifyIpInterfaceChange`(IPv4)를 등록. 알림이 오면 그 인터페이스를 바로 `GetIfEntry2`로 읽어 `OperStatus`와 `MediaConnectState`를 본다. 알림 콜백 스레드에서는 읽기와 큐 넣기만 한다.
- **회차 확인**: 엔진 회차마다 감시 인터페이스를 `GetIfEntry2`로 읽는다 (알림을 놓쳐도 1초 안에 잡음). 비용은 통합 시험으로 잰다 (기준 p95 1 ms 이하).
- **상태 해석**: `MediaConnectState = Disconnected` 또는 `OperStatus ∈ {Down, LowerLayerDown, NotPresent}` → 링크 다운. `Connected` + `Up` → 링크 업. 그 밖(`Dormant`, `Testing`, `Unknown`)은 `unknown`으로 그대로 기록. 인터페이스가 사라짐(`ERROR_FILE_NOT_FOUND`) → `removed`(다운으로 다룸).
- **해상도**: 알림 경로는 수 ms, 알림이 오지 않으면 회차 간격(1초). 알림과 회차 확인이 같은 전이를 두 번 보면 한 번만 기록 (직전 상태와 같으면 버림).
- **실패**: 등록 실패 → 그 측정의 직접 관측 수집 상태 `unsupported`(사유 코드). `ERROR_ACCESS_DENIED` → `denied`. 한 인터페이스 읽기 실패는 그 인터페이스만 `unknown`.
- 관측 결과는 엔진 회차와 독립적인 **링크 관측 흐름**으로 세션에 들어가 M3 `events.jsonl`에 `link` 이벤트로 쓴다 (A5). 시각은 세션 시계의 경과 ms와 UTC.

### A3. 로그 (보완 경로) — `LinkLogReader`

- **언제**: 측정이 끝난 뒤 한 번, 측정 구간(시작 3초 전 ~ 끝 3초 뒤)을 읽는다. 빠른 진단은 최근 30분.
- **무엇을**: `LinkCatalog`의 해석표에 있는 것만.

| 출처 | 다운 | 업 | 어댑터 대응 | 근거 |
| --- | --- | --- | --- | --- |
| `System`, 공급자 `e1*express`·`e2f*express` 계열 (Intel 유선) | 27 | 32 | 이벤트 데이터의 어댑터 설명 = 인터페이스 설명 | 이 PC 실측 |
| `WLAN-AutoConfig/Operational` | 8003 | 8001 | 인터페이스 GUID = 인터페이스 Id | 이 PC 실측 (필드) |
| 그 밖의 드라이버 | — | — | — | 해석표에 없음 → 그 어댑터는 로그 경로 `unsupported` |

- 해석표는 확인된 것만 넣는다. 확인하지 않은 공급자를 추측해 넣지 않는다. 새 공급자는 실측 근거와 함께 표에 더한다.
- **어댑터 대응**: 측정 인터페이스의 설명·GUID와 맞으면 그 인터페이스 번호로 연결. 같은 설명이 둘 이상이면 `ambiguous`, 하나도 안 맞으면 `unlinked`로 기록 (판정에 쓰지 않음, 타임라인 표시는 M5).
- 설명 문자열 자체는 기록에 남기지 않는다 (인터페이스 번호·유형만).

### A4. 근거 상태 (R2)

측정 하나에서 **경로별·인터페이스별**로 넷 중 하나. 판정과 화면은 둘을 함께 본다.

| 상태 | 직접 관측 | 로그 |
| --- | --- | --- |
| `unsupported` | 알림 등록 실패 / 인터페이스 읽기 미지원 | 그 어댑터의 드라이버가 해석표에 없음, 로그 없음 |
| `denied` | 접근 거부 | 로그 접근 거부 |
| `observed-none` | 감시했고 다운 없음 | 읽었고 해석표의 공급자가 있으나 구간 안 이벤트 없음 |
| `down` | 다운 관측 (전이 목록 포함) | 다운 이벤트 있음 |

- **`unsupported`·`denied`를 "정상"으로 표시하지 않는다.** 등급·결론은 이 둘을 "근거 없음"으로 다룬다 (B5).
- 로그를 읽다 실패한 사유(예외 형식·코드)는 남기고 메시지·경로는 남기지 않는다 (M3과 같은 규칙).

### A5. 기록 (M3 `link` 이벤트 계약 채우기)

`events.jsonl` 공통 필드 + 아래. M3 6.3에서 정한 `collection: unsupported/denied/observed-none/down/up`과 출처를 쓴다.

| 필드 | 뜻 |
| --- | --- |
| `source` | `direct` / `log` |
| `interfaceIndex`, `kind` | 측정 인터페이스와 연결 (`unlinked`·`ambiguous`면 없음) |
| `collection` | 전이(`down`/`up`/`unknown`/`removed`)나 상태 요약(`unsupported`/`denied`/`observed-none`) |
| `atMs`, `wall` | 전이 시각 (로그는 이벤트 시각을 경과 시간으로 환산: 측정 시작 벽시계 기준, 시각 변경 이벤트가 있으면 그 뒤 구간은 표시만 하고 판정에 쓰지 않음) |
| `code` | 실패 사유 코드 |
| `link` | `linked` / `unlinked` / `ambiguous` |

- 측정 시작 때 직접 관측의 수집 상태를 인터페이스마다 한 줄, 끝날 때 로그 경로 결과를 한 줄씩 쓴다.
- 읽기(M3 `RecordReader`)는 `link` 이벤트를 검증해 `LinkEvidence`로 돌려준다 (자료형이 틀리면 이벤트 손상).

### A6. Wi‑Fi 신호 세기 (N11, 선택) 확인

- 이 PC는 유선으로 측정하고 무선 어댑터는 내려가 있어 신호 세기·위치 권한 조건을 **실측하지 못했다**. N11은 M9 선택 기능 설계에서 무선 환경으로 확인한다고 기록한다 (추측해 넣지 않음).

## B. 판정

### B1. 입력과 원칙

- 입력: 기록 하나(머리의 대상·역할·사업자·예상 연결 유형, 회차, 공백, 경로 이벤트, 링크 근거). 측정 중에는 지금까지의 회차로 같은 분석을 한다.
- 분석 결과는 **기록에 저장하지 않고 읽을 때마다 계산**한다 (원본만 저장). 결과에 `analyzerVersion = 1`을 단다 (M3 데이터 계약 "판정 알고리즘 버전").
- 회차 번호는 응답 조합을 **관측 결과**로 보여 주고, 원인 구간은 **후보**로만 말한다. 사용자 대상 순서는 경로 증거가 아니다.

### B2. 응답 기준선

- 대상이 측정 전체(측정 중이면 지금까지)에서 성공을 **한 번이라도** 했으면 "기준선 있음".
- 기준선 없는 대상은 판정에서 뺀다. 다른 대상이 하나라도 기준선이 있으면 "응답 기준선 없음(Ping을 막는 장비일 수 있음)"으로 표시만 한다. **모든 대상이 기준선 없음**이면 판정 전체를 `판단 불가`로 두고 "끊긴 상태에서 시작했을 수 있음"을 알린다.
- 지연 기준선(B6)은 별개다.

### B3. 회차 판정

공백 회차는 판정하지 않는다 (관측 없음). 나머지 회차는 손실이 없으면 `정상`(또는 B6의 `지연 상승`), 손실이 있으면 위에서부터 처음 맞는 것:

| 순서 | 판정 | 조건 |
| --- | --- | --- |
| 1 | **로컬 링크 단절 관측** | 손실 대상 중 하나의 측정 인터페이스에 링크 다운이 관측됨. 다운 구간(다운 ~ 업, 업이 없으면 측정 끝)이 회차의 [시작 − 1초, 끝 + 1초]와 겹침 |
| 2 | **판단 불가 (경로 보류)** | 손실 대상 중 하나라도 회차 시점 경로가 실패했거나 유형이 예상 연결 유형과 다름 (예상이 "상관없음"이면 유형 비교 생략) |
| 3 | **외부 연결 단절 추정** | 기준선 있는 외부 대상이 **2개 이상, 사업자 2곳 이상**이고 그 회차에 그들이 **모두** 손실 (로컬 대상 성공·실패와 무관) |
| 4 | **판단 불가 (근거 부족)** | 기준선 있는 외부 대상이 모두 손실인데 위 다양성 조건을 못 채움, 또는 검사 오류·결과 누락 때문에 기준선 있는 외부 대상 중 유효 결과가 둘 미만 |
| 5 | **대상 응답 실패** | 그 밖의 손실 (가까운 대상 실패·먼 대상 성공 포함). 실패 대상 목록을 단다 |

- 검사 오류는 손실이 아니다 (M3 규칙). 오류만 있는 회차는 `불완전`으로 표시하고 판정하지 않는다.
- 기준선 없는 대상의 손실은 판정 조건에 들어가지 않는다.

### B4. 끊김 구간(N3)과 구간 후보

- **구간**: 손실 회차가 회차 번호로 이어지면(M3 연속 규칙: 건너뜀·공백·불완전에서 끊음) 한 구간. 길이는 M3 `LossRun`과 같은 경과 시간 범위(최소·최대, 열린 끝).
- **구간 판정** = 구간 안 회차 판정 중 우선순위가 가장 높은 것 (로컬 링크 단절 관측 > 외부 연결 단절 추정 > 대상 응답 실패 > 판단 불가). 판정이 둘 이상 섞였으면 `혼합` 표시와 회차별 판정 목록을 단다.
- **구간 후보** (개념도 PC → 공유기 → 인터넷. 실제 패킷 경로라고 하지 않음):

| 구간 판정 | 로컬 대상 상태 (기준선 있는 것) | 후보 |
| --- | --- | --- |
| 로컬 링크 단절 관측 | 무관 | "PC와 공유기 사이 링크" (관측됨) |
| 외부 연결 단절 추정 | 모두 성공 | "공유기 이후 (인터넷 쪽)" |
| 외부 연결 단절 추정 | 하나라도 손실 | "PC~공유기 구간 또는 공유기" |
| 외부 연결 단절 추정 | 로컬 기준선 없음 / 로컬 대상 없음 | 후보 없음 ("로컬 기준이 없어 구간을 좁힐 수 없음") |
| 대상 응답 실패 | — | 후보 없음 (그 대상 문제이거나 응답 제한일 수 있음) |
| 판단 불가 | — | 후보 없음, 사유 |

- 끊김 목록 통계(N3): 판정별 구간 수, 최장·평균 길이(최소 길이 기준, 열린 끝 개수 따로).
- 구간마다 상세(N1·M7용): 앞뒤 2회차 응답, 시작 시점 대상별 경로, ±3초 링크 근거 (최대 8건).

### B5. 등급 (N2)

| 등급 | 조건 (위에서부터) |
| --- | --- |
| **관측 부족** | 공백 아닌 회차 60개(1분) 미만, 또는 기준선 있는 대상 없음 |
| **판단 불가** | 판단 불가 회차가 손실 회차의 50% 이상 **이고** 3회 이상 |
| **매우 나쁨** | 로컬 링크 단절 관측 구간 1개 이상, 또는 외부 연결 단절 추정 구간 3개 이상, 또는 그 구간 하나가 최소 길이 30초 이상, 또는 외부 손실률(기준선 있는 외부 대상 평균) 5% 이상 |
| **나쁨** | 외부 연결 단절 추정 구간 1개 이상, 또는 외부 손실률 1% 이상, 또는 지연 상승 회차 10% 이상 |
| **보통** | 대상 응답 실패 회차 1% 이상, 또는 지연 상승 회차 3% 이상, 또는 외부 손실 1회 이상, 또는 **근거 조건 미충족** |
| **좋음** | 그 밖. 단 **근거 조건**: 기준선 있는 외부 대상 2개·사업자 2곳 이상, 그리고 공백 아닌 회차가 계획의 80% 이상 |

- 근거 조건을 못 채우면 좋음을 주지 않고 보통에 "근거 부족" 사유를 단다 (기획서 N2 "근거 없이 좋은 등급을 주지 않음").
- 링크 근거가 `unsupported`·`denied`이면 결론 문장에 "링크 근거를 얻지 못함"을 붙인다 (등급을 올리지도 내리지도 않음).
- **한 문장 결론**: 등급 + 가장 큰 사유 하나 (예: "외부 연결이 3번 끊겼습니다(최장 12초 이상). 공유기는 응답했습니다."). 문장 목록은 코드 상수로 두고 시험한다.

### B6. 지연 기준선과 지연 상승

- 대상별 기준선 = 그 대상 성공 지연의 중앙값. 성공이 20개 미만이면 기준선 없음 (지연 상승 판정 안 함).
- 지연 상승: 손실 없는 회차에서 어떤 대상의 지연이 `중앙값 + max(2 × 중앙값, 30 ms)` 이상. 모든 대상에 같은 고정 기준(기존 앱 50 ms)은 쓰지 않는다.
- 지연 상승 회차가 이어지면 구간으로 묶어 목록에 넣는다 (끊김과 구별).

## C. 빠른 진단 (F1)과 사이트 점검 (F2)

### C1. 검사

모든 검사에 제한시간을 둔다 (기존 앱은 어댑터·링크 검사에 없었음). 시간을 넘기면 결과를 기다리지 않고 `미측정(시간 초과)`, 늦게 끝난 작업의 예외는 관찰만 하고 버린다.

| 검사 | 하는 일 | 판정 (정상 / 확인 / 실패 / 미측정) | 제한 |
| --- | --- | --- | --- |
| 어댑터 | 외부 주소로 가는 가장 좋은 인터페이스(M3 탐지와 같은 경로)의 IPv4, 게이트웨이, DNS 서버 유무 | IPv4 없음(169.254 자동 할당 포함)·어댑터 내려감 → 실패. 게이트웨이 없음 → 확인. 경로 없음 → 작동 인터페이스 있으면 확인, 없으면 실패 | 2초 |
| 게이트웨이 | 게이트웨이에 ICMP 1회 | 응답 정상, 무응답 **확인**(Ping을 막을 수 있음), 게이트웨이 모름 미측정 | 1초 |
| 외부 TCP 443 | 기본 외부 대상 두 주소에 TCP 연결 (M3 `TcpProbe`, 거부 = 응답) | 둘 성공 정상, 하나 확인, 둘 실패 실패 | 3초 |
| DNS | 도메인 둘을 Windows 해석기로 | 같은 방식 | 3초 |
| HTTPS | 같은 두 도메인에 HEAD, 리디렉션 안 따름, 쿠키 없음, 인증서 검증 유지 | 200~499(407 제외) 성공. 둘 정상, 하나 확인, 둘 실패 | 4.5초 |
| 네트워크 로그인 | Windows 연결 확인 주소에 HTTP GET, 본문 64바이트를 예상 문자열과 비교 | 일치 정상. 200인데 다름 또는 3xx·4xx 확인. 그 밖 미측정 | 4.5초 |
| 링크 근거 | 지금 인터페이스 상태(A2 한 번 읽기) + 최근 30분 로그(A3) | 지금 다운 → 실패. 30분 안 다운 → 확인. 둘 다 근거 있고 이벤트 없음 → 정상. **로그 `unsupported`·`denied` → 미측정(사유)** (정상으로 보지 않음) | 3초 |

- 게이트웨이 검사만 어댑터 결과를 기다린다. 나머지는 동시에.
- 기본 주소·도메인(외부 대상 두 주소, `www.microsoft.com`·`www.google.com`, `http://www.msftconnecttest.com/connecttest.txt` / `Microsoft Connect Test`)은 설정 가능한 기본값이다 (설정 화면은 M9).

### C2. 결론과 안내 (N5)

기존 앱 결론 규칙 8개(명세서 1절)를 **찾은 것 → 해볼 것** 짝으로 바꾼다. 위에서부터 처음 맞는 것 하나가 주 결론이고, 맞는 나머지는 "함께 볼 것"으로 단다.

| # | 조건 | 찾은 것 | 해볼 것 (단계) |
| --- | --- | --- | --- |
| 1 | 링크 근거 실패 | 어댑터 링크가 지금 내려가 있음 | 케이블·포트 확인 → 다른 포트 → 어댑터 다시 사용 |
| 2 | HTTPS 정상, TCP 실패 | 웹은 되지만 IPv4 직접 연결이 안 됨 | IPv6·프록시·VPN 사용 여부 확인 |
| 3 | TCP 실패 아님, DNS 실패 | 이름 해석 문제 | DNS 캐시 비우기(F7, 확인 후) → 재검사 → 어댑터 DNS 설정 |
| 4 | HTTPS 정상 아님, 네트워크 로그인 확인 | 공용 Wi‑Fi 로그인이나 프록시 정책 | 브라우저로 로그인 페이지 열기 |
| 5 | 어댑터 실패, TCP 실패, HTTPS 정상 아님 | PC 연결 자체 | 케이블·Wi‑Fi 접속 확인 |
| 6 | TCP 실패, HTTPS 정상 아님 | 게이트웨이 정상이면 공유기 이후, 아니면 게이트웨이와 외부 모두 | 다른 기기도 안 되는지 → 공유기 재시작 → 통신사 |
| 7 | HTTPS 실패나 확인 | 웹 연결 추가 확인 필요 | 프록시·VPN·시계·인증서 |
| 8 | 링크 근거 확인 | 최근 30분 안에 링크가 끊긴 적 있음 | 실시간 측정으로 간헐 끊김 기록 |
| 9 | 게이트웨이나 로그인 확인 | 인터넷은 되지만 예외 관측 | (설명만) |
| 10 | 그 밖 | 기본 연결 정상 | 간헐 끊김이면 실시간 측정 |

- **일부 성공과 전체 실패 구별** (이어받을 규칙): 둘 중 하나만 성공은 `확인`이고 결론에 "일부만 성공"을 그대로 쓴다.
- **미측정이 있으면** 결론에 "확인하지 못한 검사 n개"를 붙인다. 미측정이 결론 조건에 필요한 검사면 그 규칙은 건너뛴다.
- **이전 결과 비교**: 검사마다 판정이 바뀐 것 목록 (화면은 M6).
- **텍스트 복사**: 검사 판정·결론·안내를 평문으로. 주소는 넣지 않는다 (게이트웨이·DNS 서버 주소는 화면에만, M8 가리기 규칙과 맞춤).

### C3. 사이트 점검 (F2)

- 입력 검증: 도메인 형식(점 하나 이상, 레이블 규칙, 63자 레이블·253자 전체, IP 주소·스킴·경로는 거절. 국제 도메인은 IDN 변환 뒤 검사).
- DNS 한 줄, HTTPS 한 줄 (C1과 같은 판정·제한).

### C4. 진단 결과 기록 (M3 데이터 계약)

- `diagnosis-<시작 UTC>.json`, `format: "netpulse.diagnosis"`, `version: 1`: 시작·끝 시각, 검사별 판정·사유 코드·소요 시간, **실행하지 않은 검사는 `notRun`으로 명시**, 결론 번호, 앱 버전, 연결된 측정 Id(진단을 측정 화면에서 돌렸으면). 사용자 메모는 M6.
- 저장은 M6 화면에서 부른다. M4는 형식·쓰기·읽기·손상 처리까지.
