# 기존 앱 기능 명세서

기존 NetPulse(`main` `e852c6b`, C# / WPF)가 하던 일을 기능 단위로 적는다. 새 앱은 이 문서와 `docs/loop-plan.md` 6절을 기준으로 만들고, 기존 소스를 옮겨 적지 않는다.

각 항목의 **새 앱** 칸은 이어받을지(유지), 바꿀지(변경), 버릴지(제외)를 적는다. 근거가 기획서에 있으면 절 번호를 단다.

---

## 1. 빠른 진단

**입력**: 없음. 현재 Windows 연결을 그대로 쓴다.
**실행**: 아래 일곱 검사를 동시에 돌린다. 게이트웨이 검사만 어댑터 검사 결과를 기다린다. (`QuickDiagnostics.cs:125`)

| 검사 | 하는 일 | 판정 |
| --- | --- | --- |
| Windows 어댑터 | 외부 주소로 가는 최적 인터페이스를 찾고 그 어댑터의 IPv4, 게이트웨이, DNS 서버를 읽음 | 사용 가능한 IPv4 없음(자동 할당 169.254 포함) 또는 어댑터 내려감 → 실패. 게이트웨이 없음 → 확인. 최적 경로를 못 찾으면 활성 어댑터 수로 실패/확인 |
| 기본 게이트웨이 | 게이트웨이에 Ping 1회 | 응답 → 정상. 무응답 → **확인**(장비가 Ping을 막을 수 있음). 게이트웨이 모름 → 미측정 |
| 외부 IPv4 · TCP 443 | 공용 주소 두 곳에 TCP 연결 | 둘 다 성공 → 정상, 하나 → 확인, 둘 다 실패 → 실패 |
| Windows DNS | 도메인 두 개 이름 해석 | 같은 방식 |
| HTTPS | 같은 두 도메인에 HEAD 요청. 리디렉션 따라가지 않음. 쿠키 없음. TLS 1.2·1.3. 인증서 검증 유지 | 200~499 중 407 제외 → 성공 |
| 네트워크 로그인 | Windows 연결 확인 주소에 HTTP GET, 본문 64바이트까지 읽어 예상 문자열과 비교 | 일치 → 정상. 200인데 본문 다름, 또는 3xx·4xx → 확인. 그 밖 → 미측정 |
| 최근 링크 기록 | 시스템 로그에서 최근 30분 Intel 유선 드라이버의 링크 다운 이벤트 | 없음 → 정상, 있음 → 확인, 조회 불가 → 미측정 |

**결론 문장** (`QuickDiagnostics.cs:51`). 위에서부터 처음 맞는 규칙을 쓴다.

1. HTTPS 정상인데 TCP 실패 → "웹 응답은 확인됐습니다". IPv6, 프록시, VPN, 외부 IP 접근 제한 가능성을 안내.
2. TCP 실패 아님 + DNS 실패 → DNS 문제. 캐시 비우기 후 재검사, 어댑터 DNS 설정 확인.
3. HTTPS 정상 아님 + 로그인 검사 확인 → 공용 Wi‑Fi 로그인이나 프록시 정책.
4. 어댑터 실패 + TCP 실패 + HTTPS 정상 아님 → PC 연결 자체. 케이블·Wi‑Fi 접속.
5. TCP 실패 + HTTPS 정상 아님 → 게이트웨이 정상이면 공유기 이후, 아니면 게이트웨이와 외부. 다른 기기도 안 되는지 확인 안내.
6. HTTPS 실패나 확인 → 웹 연결 추가 확인. 프록시, VPN, 시간, 인증서.
7. 게이트웨이나 로그인 검사 확인 → 인터넷은 되지만 예외 관측.
8. 그 밖 → 기본 연결 정상. 간헐 끊김은 실시간 측정 권유.

**부가 동작**

- 제한시간: TCP·DNS 3초, HTTPS·로그인 4.5초. **어댑터 검사와 링크 기록 검사에는 별도 제한시간이 없다** (`QuickDiagnostics.cs:129`, `:134`). 새 앱에서는 모든 검사에 제한시간을 둔다.
- 다시 검사하면 이전 결과와 판정이 바뀐 검사 수를 알려준다. (`QuickWindow.cs:166`)
- 결과를 텍스트로 클립보드에 복사한다.
- 제한시간이 있는 검사(TCP, DNS, HTTPS, 네트워크 로그인)는 시간을 넘기면 결과를 기다리지 않고, 늦게 끝난 작업의 예외를 흘려보낸다.

**새 앱**

| 항목 | 결정 |
| --- | --- |
| 일곱 검사와 판정 단계(정상/확인/실패/미측정) | 유지. 결론 규칙은 N5 안내형 진단으로 다시 설계 |
| 결론 1, 3, 5의 판단 | 유지. 기획서 6.3 "이어받을 판단 규칙" |
| 링크 기록 검사 | **변경**. 조회 불가와 이벤트 없음을 정상으로 보지 않음 (R2) |
| 이전 결과와 비교 | 유지. 진단 화면에서 바뀐 항목을 강조 |
| 클립보드 복사 | 유지. 리포트(N6)와 별개로 짧은 텍스트 복사 |
| 공용 주소·도메인 고정 | 변경. 설정에서 바꿀 수 있는 기본값 |

## 4. 실시간 측정

**입력**: 모드(Mesh 경유 / 직접 Wi‑Fi), 측정 시간 1~720분(기본 10분).
**대상**: 코드에 고정된 세 곳(가정망 확장기, 공유기, 공용 외부 주소). Wi‑Fi 모드는 확장기를 뺀다. (`Dashboard.cs:42`)

**동작** (`Monitor.cs:114`)

- 1초 간격의 회차. 회차마다 모든 대상에 Ping(제한 800 ms, 32바이트)을 동시에 보낸다.
- 일정이 밀리면 놓친 회차를 건너뛰고 수를 센다. 회차 번호는 시작 기준 경과 시간에서 나온다.
- 회차마다 대상별 Windows 경로를 기록하고 기록 파일을 바로 flush한다.
- 끝나는 사유: 완료 / 중지 / 오류.
- 측정 중 창을 닫으면 저장이 끝날 때까지 기다린 뒤 닫는다. (`Dashboard.cs:275`)

**집계** (`Monitor.cs:50`)

- 대상별 성공, 손실, 검사 오류 수. 손실률 = 손실 / (성공 + 손실). 검사 오류는 분모에서 뺀다.
- 평균·최대 지연은 성공 응답만으로.
- 연속 손실 구간: 회차 번호가 이어질 때만 같은 구간. 최장 연속 손실.
- 값이 없으면 "—"로 표시하고 0으로 쓰지 않는다.

**화면**: 대상별 카드(최근 응답, 손실률, 평균·최대, 최장 연속 손실, 최근 60초 미니 그래프에 손실·오류 점). 경과 시간과 진행 막대. 최근 이상 시각. 선택 모드와 Windows 경로가 다르면 경고.

**저장** (`결과/<날짜시각_모드_임의값>/`)

| 파일 | 내용 |
| --- | --- |
| `samples.csv` | 회차 × 대상의 원본: 시각, 회차, 예정 시각, 상태, 지연, 손실 여부 |
| `loss-runs.csv` | 연속 손실 구간: 대상, 첫·마지막 회차와 시각, 회차 개수(`count`), 첫·마지막 손실 표본의 시각 차(`first_to_last_seconds`). 뒤의 값은 실제 끊김 지속시간이 아니다. 끊김은 첫 손실 직전 성공과 마지막 손실 직후 성공 사이 어딘가에서 시작하고 끝난다 |
| `summary.csv` | 대상별 요약과 측정 조건(주기, 제한시간, 회차, 건너뛴 회차, 종료 사유) |
| `evidence.csv` | 경로 초기값·변경, 증상 표시, 링크 이벤트, 로그 조회 상태 |

**새 앱**

| 항목 | 결정 |
| --- | --- |
| 1초 주기, 동시 Ping, 건너뛴 회차 계산 | 유지. 주기와 제한시간은 M3에서 확정 |
| 집계 규칙 | 유지. 기획서 6.3 "이어받을 판단 규칙" |
| 고정 대상과 모드 | **제외**. 자동 탐지와 프로필 (R1) |
| 측정 시간 1~720분, 기본 10분 | 출발점. M3에서 확정 (6.3 "측정 시간과 종료 동작") |
| 창 닫기 시 저장 대기 | 변경. 창 닫기는 트레이로 숨김, 앱 종료 시 저장 후 종료 (N7) |
| 네 개 CSV 형식 | **제외**. 버전 있는 새 기록 형식 (M3). 보존할 정보는 위 표의 내용 전부 |
| 최근 60초 미니 그래프 | 변경. 겹침 타임라인(N1)과 대상별 카드로 |

## 5. 증상 표시

측정 중에만 누를 수 있다. 누른 시각을 `evidence.csv`에 기록한다. 기록하지 못하면 따로 적어 두라고 안내한다. (`Dashboard.cs:294`)

**새 앱**: 유지 (F4). 메모를 붙일 수 있게 확장 (N8).

## 6. 경로와 링크 근거

- **경로**: 회차마다 대상별로 Windows가 고른 인터페이스 번호를 조회하고, 유형(유선, Wi‑Fi, 기타)을 붙인다. 바뀐 때만 기록한다. 유형은 30회차마다 다시 조회한다. (`Evidence.cs:186`)
- **링크**: 측정이 끝난 뒤 측정 구간(시작 3초 전부터)의 시스템 로그에서 Intel 유선 드라이버의 링크 다운·업 이벤트를 읽는다. 조회 성공·실패 상태도 기록한다. (`Evidence.cs:143`)

**알려진 결함**

- 링크 이벤트에 어느 어댑터인지가 없다.
- 해당 드라이버가 없는 PC에서는 근거가 영영 0건이고, 빠른 진단은 이를 정상으로 표시한다.
- 근거 기록 파일 저장이 실패해도 측정은 계속되고, 끝에 "보조 기록 저장 실패"로만 알린다.

**새 앱**: 경로 기록 유지. 링크 근거는 R2로 다시 설계.

## 7. 끊김 분석

**입력**: 저장된 측정 목록에서 고르거나, 임의 위치의 `samples.csv`를 연다. 같은 폴더의 `evidence.csv`를 함께 읽는다. (`AnalysisWindow.cs:164`)

**읽기 검증**: 헤더, 열 수, 모드, 시각 형식, 손실·상태·지연의 조합을 엄격히 검사하고, 다른 측정이 섞이거나 같은 회차에 같은 대상이 두 번 나오면 거절한다. 근거 파일은 깨져도 Ping 분석은 계속하고 문제를 알린다. (`Analysis.cs:116`)

**회차 분류** (`Analysis.cs:22`)

| 패턴 | 조건 (Mesh 모드 기준) |
| --- | --- |
| 불완전 | 기대 대상이 빠졌거나 검사 오류 |
| PC–확장기 | 셋 다 손실 |
| 확장기 이후 | 확장기 응답, 공유기·외부 손실 |
| 공유기 이후 | 외부만 손실 |
| 혼합 | 그 밖의 손실 조합(가까운 쪽 실패·먼 쪽 성공 포함) |
| 지연 상승 | 손실 없고 어느 대상이든 50 ms 이상 |
| 경로 불일치 | 손실 회차인데 대상 경로의 유형이 모드와 다름 → 구간 판단 보류 |

**이상 목록** (`Analysis.cs:208-222`)

- 회차를 세 종류로 나눈다: 손실(대상 하나라도 손실), 불완전(손실 없이 검사 오류·누락), 지연 상승(그 밖에 50 ms 이상).
- 회차 번호가 이어지고 **종류가 같으면** 한 항목으로 묶는다. 패턴(PC–확장기, 확장기 이후 등)이 회차마다 달라도 같은 손실 항목에 들어가고, 항목은 나온 패턴을 모두 보관한다. 패턴이 둘 이상이면 제목이 "회차별 손실 패턴 변화"가 된다.
- 손실이 있으면서 검사 오류도 있는 회차는 손실로 묶되 불완전 횟수에도 센다.
- 증상 표시, 링크 이벤트, 경로 변경을 별도 항목으로 끼워 시작 시각순으로 정렬한다.

**상세**: 항목을 고르면 패턴별 우선 확인 안내, ±3초 링크 기록(최대 8건), 시작 시각의 대상별 경로, 앞뒤 2회차를 포함한 주변 회차의 대상별 응답(길면 가운데 생략). 상세 텍스트를 복사할 수 있다.

**새 앱**

| 항목 | 결정 |
| --- | --- |
| 불완전, 혼합, 경로 불일치의 처리 | 유지. 기획서 6.2 구간 판단 원칙 |
| 3단 구성 전제의 패턴 | **제외**. 역할 기반 판정 네 가지로 (6.2 "끊김 판정의 구분") |
| 모든 대상에 같은 50 ms 기준 | **제외**. 대상별 기준선 대비로 M4에서 설계 |
| 이상 항목 묶기, 증상·링크·경로 변경 끼워 넣기 | 유지. 겹침 타임라인(N1)과 끊김 목록(N3)으로 |
| 주변 회차, 당시 경로, 전후 링크 근거 상세 | 유지. 끊김을 고르면 펼쳐지는 상세로 |
| 임의 위치 파일 열기 | 유지. 새 형식 파일에 한함 |
| 상세 복사 | 유지 |
| 기존 CSV 읽기 | **제외** (기획서 6.3 "넣지 않는 것") |

## 8. 결과 비교

결과 폴더의 `summary.csv`를 모두 읽어 Mesh 측정 하나와 Wi‑Fi 측정 하나를 고르게 한다. **두 모드에 공통인 대상(공유기, 외부)만** 비교하고, 확장기는 비교하지 않는다 (`Comparison.cs:162`). 대상별 유효 측정 수, 손실률, 평균·최대 지연, 최장 연속 손실, 검사 오류를 나란히 보여준다. 읽지 못한 파일 수를 알린다.

**새 앱**: 변경. 모드 대신 아무 두 측정을 고른다. 비교할 수 있는 조건(대상, 주기)이 다르면 알린다 (F6, M3 데이터 계약).

## 9. 창과 화면

- 사용자 지정 제목 표시줄, 최소화·최대화·닫기. 둥근 모서리.
- 빠른 진단, 분석, 비교는 각각 모달 창.
- 내장 글꼴 Pretendard(SIL OFL).
- 키보드 초점 테두리, 주요 컨트롤의 접근성 이름.
