## 3. 설계

### A. 상주와 알림

#### A1. 닫기 동작

창 닫기(X, Alt+F4, 작업 표시줄 닫기)는 `CloseWindow`, 트레이 "종료"·`--exit`·두 번째 경로는 `ExitAsync`, 세션 종료는 `SessionEndFlush`(A6)다.

| 지금 상태 | CloseWindow | ExitAsync |
| --- | --- | --- |
| 측정 중·시작 중, 설정 "트레이에서 계속" 켬(기본), 트레이 사용 가능 | 처음이면 안내 대화상자(A2), 아니면 **숨김** | 저장 후 종료 |
| 측정 중·시작 중, 설정 끔 또는 트레이 사용 불가 | 저장 후 종료 (M5와 같음, 확인 없음) | 저장 후 종료 |
| 멈추는 중 | 종료 (진행 중인 중지에 합류해 끝까지 기다림) [1-3] | 같음 |
| 측정하지 않음 | 종료 | 종료 |
| 진단 중·리포트 내보내는 중 (측정 아님) | 종료 (지금처럼 진단 멈춤·내보내기 취소 후) | 같음 |
| 기록 옮기는 중 | 종료: 옮기기에 멈춤을 보내고 지금 기록 하나를 끝내거나 되돌린 뒤(B3) 종료 | 같음 |
| 앱 대화상자(확인 등)가 열린 채, 숨김 대상 | 숨김. 대화상자와 입력 초안은 그대로 남고 다시 열면 그대로 보인다 [1-12] | 대화상자는 취소로 닫고 종료 |
| 숨긴 채 측정이 끝남 | — (앱은 트레이에 남음, 측정 끝 풍선) | 종료 |

**종료 합류** [1-3]: `MeasurementHost.ShutdownAsync`를 바꾼다. 먼저 새 시작을 막고(`BlockStarts`), 시작 중이면 그 시작 작업이 끝나기를 기다린 뒤 측정 중이면 중지하고, 멈추는 중이면 진행 중인 중지가 끝나기를 기다린다. 지금 `StopAsync`가 시작 중·멈추는 중에 바로 돌아오는 것은 종료에서 쓰지 않는다. G2: 시작 중 종료, 중지 중 종료, 종료 뒤 시작 거부.

**숨긴 채 시작이 실패**: 측정 화면의 시작 오류 상태 그대로 + 풍선 "측정을 시작하지 못했습니다"(누르면 열기).

**숨김/다시 열기 계약** [1-4]:
- 숨김: `AppWindow.Hide()` → `ScreenHost.Suspend()`가 모든 준비된 화면에 전달. 화면은 프레임 구독(`FramePacer`)·자체 프레임 큐(기록 화면)·모션을 멈추고, 쌓인 프레임 작업은 버린다. 테마(`Theme`)의 프레임 구독도 끊는다. 앱 틀의 `Render`는 숨긴 동안 그리지 않는다.
- **관측·알림 처리는 렌더와 떼어 낸다**: 지금 `AppShell.Render` 안의 관측 전환·저장 실패 감지를 `ResidentController`가 `host.Changed`에서 직접 하고(UI 스레드 큐, 화면 요소를 건드리지 않음), 앱 안 알림·배경 빛·알약은 보일 때만 그린다.
- 숨긴 동안 테마가 바뀌면(시스템 테마 따르기) 전환 없이 최신 값만 기억하고, 다시 열 때 전환 없이 적용한다.
- 다시 열기: `Resume()` → 지금 장면으로 한 번 그림 → `AppWindow.Show()` + 앞으로 + 최소화였으면 복원. **화면은 그대로**(강제 이동 없음). 풍선 클릭만 측정 화면(또는 그 결과)으로 간다.
- 숨긴 동안 앱 안 알림은 쌓지 않고, 다시 열 때 "숨긴 동안 끊김 관측 n번" 요약 알림 하나(있을 때만).
- 확인: 진단 값 `resident.suspended`, 숨긴 동안 `shell.render` 0회·활성 모션 0·프레임 구독 0. WinUI가 숨긴 창에서 합성·타이머를 어떻게 하는지는 구현 첫 단계에서 실제로 확인하고 DECISIONS에 적는다(가정하지 않음).

#### A2. 처음 숨을 때 안내 [1-11]

- 측정 중 첫 `CloseWindow`에 앱 안 대화상자: 제목 "창을 닫아도 측정을 계속할 수 있습니다", 본문 "트레이(작업 표시줄 오른쪽 아이콘)에서 측정을 계속합니다. 아이콘을 누르면 다시 열고, 끝내려면 트레이 메뉴의 종료를 고르세요. 설정에서 바꿀 수 있습니다." 단추 [트레이에서 계속](기본) [측정 멈추고 종료] [취소].
- 앞의 두 단추를 누르면 `trayHintShown = true` 저장(설정 저장이 막힌 실행이면 이번 실행에만). [취소]·Esc는 아무것도 바꾸지 않음.
- 숨긴 뒤 풍선은 보내지 않는다(대화상자가 이미 안내함). 풍선 호출 성공과 실제 표시는 구분해 기록한다(`notifyCalled`, 표시 여부는 알 수 없음).

#### A3. 트레이 (`TrayWindow`, `TrayIcon`) [1-1, 1-10]

- **수신 창**: UI 스레드에서 만드는 숨은 최상위 창(`WS_POPUP`, `WS_EX_TOOLWINDOW`, 보이지 않음, 클래스 이름 `NetPulse.Tray`, 창 제목 `NetPulse.Tray.{pid}`). 메시지 전용 창(`HWND_MESSAGE`)은 방송 메시지(`TaskbarCreated`)를 받지 못해 쓰지 않는다. 이 창이 트레이 콜백, `TaskbarCreated`, `WM_QUERYENDSESSION`·`WM_ENDSESSION`을 받는다. 창 프로시저 대리자는 필드로 붙잡고, 앱 종료 때 아이콘 삭제(`NIM_DELETE`) 뒤 창을 없앤다.
- **등록**: `NIM_ADD`(`NIF_MESSAGE | NIF_ICON | NIF_TIP | NIF_SHOWTIP`, `uID` = 1, 콜백 메시지 `WM_APP+1`) → `NIM_SETVERSION`(`NOTIFYICON_VERSION_4`). 탐색기가 다시 뜨면(`TaskbarCreated`) 다시 `NIM_ADD` + `NIM_SETVERSION`. GUID 식별은 쓰지 않는다(실행 파일 경로에 묶임).
- **콜백 해석** (v4): `LOWORD(lParam)` = 사건(`NIN_SELECT`, `NIN_KEYSELECT`, `WM_CONTEXTMENU`, `NIN_BALLOONUSERCLICK`, `NIN_BALLOONTIMEOUT`), `HIWORD(lParam)` = 아이콘 Id, `wParam` = 메뉴를 띄울 화면 좌표(x, y).
- **메뉴**: `CreatePopupMenu` — 열기(기본 항목) / 증상 표시(측정 중만 켜짐) / 구분선 / 종료. 띄우기 전 `SetForegroundWindow(수신 창)`, `TrackPopupMenuEx(TPM_RETURNCMD | TPM_RIGHTBUTTON | 정렬)` → 고른 명령 Id(0 = 취소)를 받아 처리, 뒤에 `PostMessage(WM_NULL)`. 하위 메뉴는 없다. 메뉴가 닫힌 뒤 초점은 원래 앞 창으로(Windows 기본).
- **도움말 글**(127자 이하): "NetPulse · 측정 중 12:04 경과" / "NetPulse · 링크 끊김 관측 중" / "NetPulse · 측정하지 않음". 상태가 바뀔 때와 측정 중 1초에 한 번까지 `NIM_MODIFY`.
- **트레이를 못 쓸 때**: 처음 `NIM_ADD`가 실패하면 이번 실행은 "트레이 사용 불가" — 닫기는 종료(A1 표), 설정 카드에 표시. **이미 숨긴 상태에서** `TaskbarCreated` 뒤 다시 넣기가 실패하면 창을 다시 보여 주고(숨은 실행을 구제) 트레이 사용 불가로 바꾼다. 다시 넣기를 기다리는 동안(탐색기 재시작 중) 숨은 상태는 유지한다.
- 아이콘은 `Assets/NetPulse.ico`(실행 파일 아이콘과 같음, `ApplicationIcon`). 상태를 아이콘 색으로 말하지 않고 도움말 글로 말한다(7.6).

#### A4. 알림 규칙 (`ResidentNotifier`, Core) [1-12]

창 상태는 셋: **앞**(보임 + 앞 창), **뒤**(보임, 다른 앱이 앞), **숨김**(숨김 또는 최소화).

| 사건 | 앞 | 뒤 | 숨김 |
| --- | --- | --- | --- |
| 알림 구간 시작 (관측 None → 외부 응답 없음/링크 끊김) | 앱 안 (지금 규칙) | 앱 안 + 풍선 | 풍선 |
| 같은 구간 안 종류 바뀜·다시 시작 | 앱 안 (지금 규칙) | 앱 안만 | 없음 |
| 알림 구간 닫힘 | 앱 안 "관측이 끝났습니다" (지금 규칙) | 앱 안 + 풍선(설정 "끝났을 때도", 기본 끔) | 풍선(같은 설정) |
| 측정 끝 | 앱 안 | 앱 안 + 풍선(설정 "측정 끝", 기본 켬) | 풍선(같은 설정) |
| 저장 실패 시작 | 앱 안 | 앱 안 + 풍선 | 풍선 (**끌 수 없음**) |
| 숨긴 채 시작 실패 | — | — | 풍선 (끌 수 없음) |

- 풍선은 설정 "끊김이 관측되면 알림"(기본 켬)이 꺼져 있으면 구간 시작·닫힘 풍선을 내지 않는다. 설정이 바뀌면 다음 사건부터.
- **알림 구간**(분석의 끊김 구간과 다르다 — 풍선을 묶는 단위일 뿐): 관측이 None이 된 시각부터 **측정 경과 30,000 ms 이상** None이면 구간이 닫힌다. 30,000 ms 미만에 다시 관측되면 같은 구간. 경과 시간은 회차 시간(측정 경과 ms)으로 잰다 — 절전 공백 동안은 회차가 없어 None 시간이 늘지 않으므로, 복귀 뒤 첫 관측에서 공백 직전의 None 시작부터 공백 뒤 첫 회차까지를 경과로 본다(공백이 30초를 넘으면 새 구간). 측정이 끝나면 열린 구간은 닫힌 것으로 하고 닫힘 풍선 대신 측정 끝 풍선 하나.
- 닫힘 풍선의 "n초" = 구간 첫 관측 시작부터 마지막 관측 끝까지(측정 경과 ms, 초 내림).
- 풍선 글은 관측이지 판정이 아니다: "링크 끊김 관측 · 이 PC의 네트워크 연결이 끊긴 상태가 관측되었습니다". 대상 이름·주소는 넣지 않는다(잠금 화면·화면 공유).
- 플래그: 경고 `NIIF_WARNING`, 그 밖 `NIIF_INFO`, 모두 `NIIF_RESPECT_QUIET_TIME`. 설정 설명 글은 "Windows 알림 설정·방해 금지·정책에 따라 나타나지 않을 수 있습니다" [1-11].
- G2 경계: 정확히 29,999·30,000 ms, 절전 공백 10초·40초, 창 상태가 구간 중간에 바뀜, 설정 변경, 측정 끝에 열린 구간, 저장 실패 설정 무시.

#### A5. 단일 실행 (`SingleInstance`) [1-5]

- **열쇠**: 사용자 폴더를 만든 뒤 그 폴더 핸들의 최종 경로(`GetFinalPathNameByHandle` — 짧은 이름·정션·대소문자를 푼 실제 경로)를 소문자로, SHA-256 앞 16자. 최종 경로를 못 얻으면 `GetFullPath` + 끝 구분자 제거로 대신하고 기록.
- **첫 실행**: 전용 스레드가 `Local\NetPulse-{열쇠}` Mutex를 얻어 프로세스가 끝날 때까지 쥔다(해제도 그 스레드). `AbandonedMutexException`은 얻은 것으로 본다. 얻은 뒤 파이프 서버(`NetPulse-{열쇠}`, 현재 사용자만)를 열고 **준비됨**. 종료가 시작되면 서버는 요청에 `closing`으로 답한다.
- **두 번째 실행**: Mutex를 바로 얻지 못하면 파이프에 연결(2초) → `open` 또는 `exit` 보냄 → 답:
  - `ok` → 종료 코드 0.
  - `closing` 또는 연결 실패(첫 실행이 준비 전·종료 중) → 0.5초 간격으로 최대 10초 동안 Mutex 얻기·파이프 연결을 번갈아 다시 시도. Mutex를 얻으면 **자기가 첫 실행**으로 이어 간다(`--exit`면 할 일이 없으니 종료).
  - 10초 안에 둘 다 안 되면 종료 코드 3 + `startup` 기록 "instanceBusy".
- `--exit`인데 실행 중인 것이 없으면 종료 코드 2(창을 띄우지 않음).
- 첫 실행은 파이프 요청을 UI 스레드로 넘긴다: `open` → 다시 열기, `exit` → `ExitAsync`.
- 시험·데모·실측은 사용자 폴더가 달라 서로 막지 않는다. 부품 전시 화면은 단일 실행을 쓰지 않는다.
- 같은 기록 위치를 쓰는 두 사용자 폴더는 지원하지 않는다(문서에 적음).
- G2: 열쇠(짧은 이름·정션·끝 구분자·대소문자 → 같은 열쇠), 프로토콜(가짜 파이프). G3: 동시에 두 실행, 첫 실행 종료 중 두 번째 실행.

#### A6. 세션 종료 (로그오프·시스템 종료) [1-2]

- `WM_QUERYENDSESSION`: 거부하지 않는다(TRUE). 새 시작·옮기기 시작을 막고 메모 초안을 넣기 시작한다.
- `WM_ENDSESSION(wParam = TRUE)`: **이 메시지 처리 안에서** `SessionEndFlush`를 동기로 끝낸다: 테마 정리·화면 정리는 건너뛰고 ① 측정 종료 합류(A1) ② 메모 비우기 ③ 리포트 내보내기 취소와 임시 파일 정리 ④ 옮기기 멈춤(지금 기록 되돌림) 순서로, 전체 한도 4초(Windows가 주는 시간 안). Core 쪽 대기는 UI 스레드가 필요 없게 `ConfigureAwait(false)` 경로만 탄다(구현 때 확인 시험). 한도를 넘으면 기록 후 반환 — 봉인 못 한 측정은 다음 실행의 M3 "중간에 끊긴 기록" 복구가 맡는다.
- `WM_ENDSESSION(FALSE)`(종료 취소): 막았던 시작을 다시 허용, 아무것도 끝내지 않는다.
- 평소 종료(`ExitAsync`)는 지금 `BeginClose` 순서를 그대로 쓴다. 1판의 "한도 3×CloseWrites"는 측정·메모에만 맞고, 리포트 내보내기는 지금처럼 끝까지 기다린다(1판의 잘못된 설명 고침).
- G3: 시험이 수신 창에 `WM_QUERYENDSESSION`·`WM_ENDSESSION(TRUE)`을 보내고 → 기록 봉인 확인. `WM_ENDSESSION(FALSE)` → 계속 측정.

#### A7. 시험과 진단 값 [1-10, 1-16]

- `diag.state`에 `resident`: `trayState`(added/unavailable/readding), `hidden`, `suspended`, `hintShown`, `tooltip`, `notifications`(이번 실행에 부른 풍선: 종류·제목·시각·`called` 성공 여부, 최근 20개), `lastMenu`(항목·켜짐), `windowState`(front/back/hidden). 숨긴 동안은 같은 내용을 `app-log.jsonl`의 `resident` 사건으로도 쓴다.
- **두 단계로 나눠 시험한다**:
  1. *처리기 시험*(G3, 자동): 시험이 `FindWindow("NetPulse.Tray", "NetPulse.Tray.{pid}")`로 수신 창을 찾아 v4 형식의 콜백(`WM_APP+1`, `lParam = MAKELPARAM(사건, 1)`, `wParam = 좌표`)을 보낸다. 이것은 **Shell을 거치지 않은 처리기 검사**임을 시험 이름과 보고에 적는다. 메뉴는 데스크톱 UIA에서 `Menu`를 찾되 **그 창의 프로세스 Id가 앱인지 확인**하고 항목을 누른다(`TPM_RETURNCMD` 경로 그대로 탐).
  2. *Shell 경로 확인*(실측 `M9LiveRunTests`, 로컬): 작업 표시줄 알림 영역(`Shell_TrayWnd` 아래, 넘침 영역 포함)에서 UIA로 "NetPulse" 단추를 찾아 Invoke·오른쪽 클릭 → 창 열림·메뉴. 아이콘이 넘침 영역에 숨어 찾지 못하면 그 사실을 기록하고 사용자 눈 확인 항목으로 넘긴다.
- 기존 UI 시험 약 110곳의 닫기: `AppDriver.Close()`는 이름을 `CloseWindow()`로 두고 동작을 지키기 위해 기본 실행에 `--close-to-tray off`를 넘긴다. 새로 `Exit()`(두 번째 실행 `--exit`로 종료, 종료 코드 확인)를 둔다. **기본값 검증**: M9 시험 하나는 인수 주입을 끈 새 사용자 폴더 실행(`AppDriver.Start(raw: true)`)으로 측정 중 닫기 → 숨김(대화상자 거쳐)을 확인한다.

### B. 설정

#### B1. 설정 파일 2판 [1-17]

```
{ version: 2,
  look: { theme, aurora, reduceEffects, reduceMotion },
  resident: { closeToTray: true, notifyDropout: true, notifyRecovered: false, notifyFinished: true, trayHintShown: false },
  records: { folder: null, extraFolders: [], move: null },
  diagnosis: { tcpTargets: null, domains: null } }
```

- 1판 → `look`으로 옮기고 나머지 기본값. 저장은 사용자가 무엇을 바꿀 때.
- **항목별 복구**: 칸 하나 단위로 — 없음·자료형 다름·알 수 없는 enum → 그 칸만 기본값. 진단 `tcpTargets`·`domains`는 **쌍 단위**: 하나라도 검증 실패·중복이면 그 쌍 전체 기본값. `records.folder`가 상대 경로·형식 오류면 null. `extraFolders`는 원소 단위로 버림. 복구한 칸 이름은 `settings` 기록에(값은 남기지 않음).
- **알 수 없는(더 새) 판**: 기본값으로 시작, 이 실행은 **설정을 저장하지 않는다**. 설정 화면 위 띠 "설정 파일을 읽지 못해 이번 실행의 변경은 저장되지 않습니다". 저장이 꼭 필요한 **파괴적 동작(기록 옮기기)은 막는다** [1-6]. 손상 파일은 지금처럼 다음 저장이 새로 쓴다(손상 원본은 `settings.json.corrupt`로 한 번 남김).
- `records.move`: 옮기기 진행 일지(B3). null이면 진행 중인 옮기기 없음.
- 쓰기: 임시 파일 → `File.Move(overwrite)` + 쓰기 뒤 다시 읽어 확인. 저장은 UI 스레드에서 직렬. 저장 실패는 화면 카드에 알림(지금은 기록만 함).

#### B2. 설정 화면

카드 넷 + 측정 구성 열기. 기존 부품만.

1. **보기**: 지금 그대로.
2. **상주와 알림**: "측정 중 창을 닫으면 트레이에서 계속" / "끊김이 관측되면 알림" / "끊김 관측이 끝났을 때도 알림" / "측정이 끝났을 때 알림". 설명: "창이 앞에 있으면 앱 안에서, 숨겨져 있거나 다른 창 뒤에 있으면 Windows 알림으로도 알립니다. Windows 알림 설정·방해 금지·정책에 따라 나타나지 않을 수 있습니다." 트레이 사용 불가면 첫 토글 꺼짐 + 이유.
3. **기록 저장 위치**: 지금 위치(표시 규칙), [폴더 바꾸기], [기본 위치로], 옛 위치가 남아 있으면 "옛 위치 n곳의 기록도 목록에 보입니다" + [다시 옮기기]. 상태는 4절.
4. **진단 기본값**: TCP 주소 2칸, 도메인 2칸, [저장] [기본값으로], 칸 오류, "진행 중인 진단은 시작할 때의 값으로 끝까지 돕니다" [1-14].
5. **측정 구성 열기** (지금 측정 카드, "다음 단계에서" 문장 삭제).

**경로 표시** [1-13]: 두 가지를 나눈다.
- *로컬 화면 표시*(사용자 눈에만): `%LOCALAPPDATA%`·`%USERPROFILE%`·`%TEMP%` 앞부분을 이름으로 줄인다. 그 밖(다른 드라이브·UNC)은 그대로 보인다 — 사용자 자신의 화면이다.
- *기록·진단 값·공개 산출물*: 경로를 쓰지 않는다. 위치는 `default`/`custom`/`extra:n`/`fallback` 종류만. 데모 모드의 설정 화면은 실제 경로 대신 **고정 합성 경로** `%LOCALAPPDATA%\NetPulse\records`(데모 표시용, 실제 폴더와 무관)를 보인다. G5는 데모 캡처의 UIA 글 전체에 대해 공개 전 검사 패턴(사용자 이름·호스트 이름·드라이브 문자로 시작하는 절대 경로·UNC)을 돌린다.

#### B3. 저장 위치 바꾸기와 옮기기 [1-6, 1-7, 1-8, 1-9]

**위치 순서와 정본 규칙** (`RecordRoots`) [1-7]: 위치 목록은 [기본(설정 folder), extraFolders…, 대체]. 같은 (측정 Id, 조각 번호)가 여러 위치에 있으면 **앞 위치의 것이 정본**이다. 이 규칙 하나를 `RecordCatalog`(목록·요약 선택), `RecordReader.FindSegments`/조각 고르기, `RecordMemos`(메모 쓸 조각), `RecordLocator`가 함께 쓴다(지금 각자 순서에 기대는 곳을 이 함수로 바꿈). 기록 화면에서 따로 연 외부 기록은 이 규칙 밖(지금처럼 별도 항목).

**검사** (`RecordFolderRules.Check`) [1-9]: 고른 폴더를 실제 경로(`GetFinalPathNameByHandle`)로 풀고:
- 존재·폴더, 쓰기 가능(임시 파일 만들고 지움), 경로 길이 여유(새 위치 + 옮길 기록 중 가장 긴 상대 경로가 **260자 미만** — 긴 경로를 켜지 않은 PC를 위해).
- 경로 위나 자신이 재분석 지점(정션·심볼릭 링크)이면 거부.
- **모든 알려진 위치**(지금 기본, extraFolders, 대체 `%TEMP%\NetPulse\records`, 앱 사용자 폴더 전체)와 같거나, 그 안이거나, 그것을 품으면 거부.
- 새 위치에 지금 기록과 **같은 측정 Id가 있고 내용(파일 목록·크기·SHA-256)이 다르면** 바꾸기를 막는다(이유: "새 위치에 같은 이름의 다른 기록이 있습니다"). 같으면 "이미 옮겨진 기록"으로 본다.
- 새 위치에 우리 표시(`.netpulse-moving` 파일)가 없는 `*.moving` 폴더가 있으면 건드리지 않고 그 이름과 겹치는 기록은 옮기기에서 뺀다.

**흐름**:
1. [폴더 바꾸기] → `FolderPicker`(`InitializeWithWindow`) / 시험은 `--pick-folder`. 검사.
2. 확인 대화상자: "기록 n개(약 x MB)를 새 위치로 옮깁니다. 옮기는 동안 측정·메모·리포트 내보내기를 할 수 없습니다." [옮기고 바꾸기] [취소]. 0개면 묻지 않고 3·6만.
3. **출입문 잠그기** [1-8]: `RecordWorkGate.EnterExclusiveAsync` — 먼저 문을 닫아 새 측정 시작·메모 저장·리포트 내보내기·기록 도서관의 새 읽기(목록 갱신·분석)를 막고, 그다음 진행 중인 것(메모 큐·`NotesWriter`·도서관 작업자·내보내기)이 **실제로 끝났는지** 기다린다(10초). 시간 안에 안 끝나면 문을 다시 열고 "지금은 옮길 수 없습니다 (진행 중인 작업)"로 끝, 아무것도 바꾸지 않음. 측정 중이면 3단계 전에 이미 단추가 꺼져 있다.
4. **먼저 위치를 확정** [1-6]: 설정에 `folder = 새`, `extraFolders = [옛, …기존]`, `move = { from: 옛, to: 새, ids: [...], step: "copying" }`을 **저장하고 다시 읽어 확인**. 저장 실패면 문 열고 중단(아무 파일도 안 건드림). 이때부터 두 위치가 모두 알려진 위치이므로 어느 순간 끊겨도 기록을 찾을 수 있다. 새 위치가 앞이라 정본이 된다.
5. **기록마다** (한 측정 Id = 그 Id의 모든 조각 폴더 `id`, `id~n` — 옛 기본 위치에 있는 것만. 대체 위치·다른 extra 위치의 조각은 그대로 두고 규칙으로 합쳐 읽힌다):
   - 같은 볼륨: 조각 폴더마다 `Directory.Move(옛\id, 새\id)`. 원자적 이름 바꾸기라 사본이 둘이 되지 않는다.
   - 다른 볼륨: `새\id.moving`(안에 `.netpulse-moving` 표시)에 복사 → 파일 목록·크기·SHA-256 대조 → `새\id`로 이름 바꾸기 → 옛 조각 삭제. 대조·복사 실패면 `.moving` 지우고 옛 것은 그대로(그 기록은 "못 옮김").
   - 옛 조각 삭제가 중간에 실패(일부 파일 잠김)하면: 새 위치 사본이 이미 정본(앞 위치)이고 대조를 통과했으므로, 남은 옛 조각은 이름을 `id.moved`로 바꿔 목록에서 빠지게 한다. 이름 바꾸기도 실패하면 그대로 둔다 — 정본 규칙상 새 위치의 같은 조각 번호가 이기므로 목록·상세·요약·메모가 모두 새 사본을 쓴다(G2로 확인). 남은 것은 "정리하지 못한 옛 파일"로 보고.
   - 기록 사이에 멈춤·종료 요청을 확인한다. 기록 하나의 복사 중 종료가 오면 `.moving`을 지우고 멈춘다.
   - 진행: `move.step`·`move.done`을 기록 하나마다 저장.
6. **끝**: 옛 위치에 측정 Id 폴더가 하나도 안 남았으면 `extraFolders`에서 뺀다. 남았으면 그대로(목록에 계속 보임). `move = null`. 문 열기 → 도서관을 처음부터 다시 읽기 → 열려 있던 기록 상세·리포트 선택은 같은 Id로 다시 연다(없으면 목록).
7. **다음 실행 복구**: 시작 때 `records.move`가 남아 있으면(끊긴 옮기기) 새 위치의 우리 `.moving` 폴더를 지우고, 결과 상태를 "옮기기가 중간에 끊겼습니다 — 옛 위치의 기록도 계속 보입니다. [다시 옮기기]"로 설정 카드에 보인다. 위치 설정은 이미 둘 다 알므로 기록은 사라지지 않는다.
8. [기본 위치로]·[다시 옮기기]도 같은 흐름.

**설정 저장이 막힌 실행**(B1 새 판): [폴더 바꾸기]·[다시 옮기기]는 꺼지고 이유 글.

#### B4. 진단 기본값 [1-14]

- `DiagnosisDefaults.Validate`: TCP 주소는 IPv4 점 넷, 둘이 다름. 도메인은 ASCII 호스트 이름(라벨 1~63자, 전체 253자, 점 하나 이상, 마지막 라벨이 숫자만이 아님), 둘이 다름. 포털 주소·기대 글·제한시간은 바꾸지 않는다.
- 진단은 **시작할 때 설정 사본**을 잡아 끝까지 쓴다. 저장한 값은 다음 진단부터.
- 진단 기록 형식은 바꾸지 않는다(주소·도메인을 일부러 저장하지 않음, M6). 시험은 검사기 경계에서 확인: 데모 진단 세계의 검사기가 받은 TCP 주소·도메인을 진단 값 `diagnosis.lastProbeTargets`(데모 모드에서만)로 보인다.

#### B5. N10 TCP 측정 대상 편집 [1-17]

- 프로필 편집기 대상 줄: 측정 방식 `SegmentedChoice`(ICMP / TCP) + TCP일 때 포트 칸(기본 443). 포트 범위 검사는 기존 `ProfileValidator`를 그대로 쓰고 칸 오류 글로 보인다. 측정 중 읽기 전용(지금 규칙).
- 안내 글: "Ping에 응답하지 않는 대상은 TCP 연결로 잴 수 있습니다. 연결 거부도 응답으로 셉니다."
- 엔진·기록·분석은 바꾸지 않는다. 확인: (1) 편집기 저장 → 재실행 → 프로필에 방식·포트 보존 → 데모 측정 → 기록 머리의 대상 방식·포트, 측정 화면 카드·기록 상세·리포트 측정 조건 "TCP 443"(G3). (2) **실제 TCP 동작의 증거는 데모가 아니라** 기존 Platform 통합 시험(`TcpProbe` 루프백, G2에서 돎)이다 — 보고에서 둘을 구분한다.
- 데모 시나리오 `steady-tcp.json`(TCP 대상 섞임)을 더한다.

## 8. 위험

1. **WinUI 창과 Win32 수신 창이 한 스레드**: 콜백에서 오래 걸리는 일을 하지 않고 디스패처 큐로 넘긴다(세션 종료만 예외: 동기로 끝내야 함, 한도 4초). 메뉴 모달 루프 중 렌더 지연은 받아들인다.
2. **숨긴 창의 WinUI 동작**: 구현 첫 단계에서 실측하고 DECISIONS에 적는다. 가정과 다르면 숨김 계약을 고친다.
3. **풍선이 안 보일 수 있음**: 호출 성공까지만 보장, 설명 글에 적음. 첫 안내는 앱 안 대화상자라 영향 없음.
4. **숨긴 채 측정이 끝난 앱이 남음**: 의도한 상주. 다음 실행은 단일 실행으로 이 창을 연다.
5. **기록 옮기기**: 위치 확정 → 복사·대조 → 삭제 순서, 일지와 다음 실행 복구, 정본 규칙 하나. 남는 위험: 사용자가 옮기는 중 다른 프로그램으로 파일을 바꾸는 경우(대조가 잡으면 못 옮김으로).
6. **세션 종료 한도**: Windows가 프로세스를 먼저 끝내면 봉인 못 한 측정은 M3 복구가 맡는다.
7. **단일 실행 열쇠**: 실제 경로로 풀지만 네트워크 드라이브의 사용자 폴더 등은 지원 범위 밖.
8. **시험의 기존 닫기 의존**: `--close-to-tray off` 기본 + 기본값 전용 시험.
9. **아이콘 제작**: 생성 스크립트, 16 px 가독성은 시각 검토와 사용자 확인.
10. **합성 콜백 시험의 한계**: Shell을 거치지 않음 — 실측 시험과 사용자 확인으로 보완하고 보고에 구분.

## 9. 대안

| 대안 | 판단 |
| --- | --- |
| 트레이 패키지(H.NotifyIcon 등) | 새 런타임 의존성(사용자 확인 필요). Win32 직접 호출이 작다 |
| WinAppSDK 앱 알림 | 사용자가 풍선으로 결정 |
| 메시지 전용 창 | 방송 메시지를 못 받아 버림 [1-1] |
| 첫 안내를 풍선으로 | 표시 보장이 없어 버림 [1-11] |
| 단일 실행에 WinAppSDK `AppInstance` | 사용자 정의 `Main` 필요. Mutex + 파이프가 응답 확인까지 작다 |
| 단일 실행에 이름 있는 이벤트만 | 신호를 받았는지 알 수 없어 버림 [1-5] |
| 옮긴 뒤 위치 저장 | 끊기면 기록을 못 찾음, 버림 [1-6] |
| 최소화하면 트레이로 | 기획서는 "닫기"만. 최소화는 Windows 기본대로 |
