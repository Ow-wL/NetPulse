# M9 설계 — 상주와 설정

1판 · 2026-11-18 · 브랜치 `loop/m9-resident-settings` (`main` `5029c7f` = M8 병합 위)

기획서 8절 M9 행: "트레이, 알림, 설정 화면(테마, 알림, 저장 위치), R5의 남은 항목과 통합 점검, 선택 기능(N10~N12). 설계안 안에서 상주·알림 / 설정 / 선택 기능 세 단위로 나눠 검토". 끝났다는 증거: G3, G5. 기준은 `docs/loop-plan.md` 6.2(R5), 6.3(N7, N10), "필수 기능의 최소 범위"(N7: 창 닫기와 앱 종료 구분, 다시 열기, 같은 끊김에 알림 반복 없음), "측정 시간과 종료 동작"(측정 중 창을 닫으면 트레이로 숨고 측정은 계속, 처음 한 번 안내, 트레이 "종료"는 기록을 저장한 뒤 끝냄), 4.5(새 런타임 의존성·관리자 권한·네트워크 설정 변경 없음), 7.5·7.6·7.8.

| 쟁점 | 결정 |
| --- | --- |

## 3. 설계

### A. 상주와 알림

#### A1. 닫기 동작

| 상황 | 창 닫기(X, Alt+F4) | 트레이 "종료" |
| --- | --- | --- |
| 측정 중(시작 중·측정 중), 설정 "측정 중 창을 닫으면 트레이에서 계속" 켬(기본) | **숨김**: 창만 숨기고 측정·진단·리포트 내보내기는 계속. 화면 요소는 살려 둔다(다시 열 때 그대로) | 저장 후 종료 (지금 `BeginClose`) |
| 측정 중, 위 설정 끔 | 저장 후 종료 (M5와 같음, 확인 묻지 않음) | 저장 후 종료 |
| 측정하지 않음 (멈추는 중 포함) | 종료 | 종료 |
| 숨긴 채 측정이 끝남 | — | 앱은 트레이에 남는다. "측정이 끝났습니다" 풍선(설정 켬). 풍선·메뉴 "열기"로 결과 화면 |

- 숨길 때: `AppWindow.Hide()`. 모션·프레임 구독은 화면이 보이지 않으면 멈춘다(기존 `Visible` 처리 확인, 없으면 숨길 때 `ui.Motion` 일시 정지, 다시 열 때 재개). 숨긴 동안 그리기는 큐에 쌓지 않고, 다시 열 때 지금 장면으로 한 번 그린다.
- 다시 열기: `AppWindow.Show()` + 앞으로 가져오기 + 측정 중이면 측정 화면. 최소화 상태였으면 복원.
- 숨김 중 시스템 종료·로그오프(`WM_QUERYENDSESSION`/`WM_ENDSESSION`): 저장 후 종료 경로를 탄다(메시지 전용 창이 받음). 저장 한도는 지금 닫기와 같은 `3×CloseWrites`.
- 처음 숨을 때 한 번: 풍선 "NetPulse가 트레이에서 측정을 계속합니다 · 아이콘을 누르면 다시 엽니다. 끝내려면 트레이 메뉴의 종료를 고르세요." 보였는지는 설정 파일 `trayHintShown`에 저장(풍선을 끈 설정이어도 이 안내는 낸다).

#### A2. 트레이 아이콘 (`TrayIcon`)

- 앱이 뜨는 동안 항상 있다(측정 여부와 무관). 아이콘은 `Assets/NetPulse.ico`(실행 파일 아이콘과 같음). 측정 중 끊김이 관측되면 아이콘을 바꾸지 않고 **도움말 글**로 알린다(색만으로 상태를 말하지 않음, 7.6).
- 도움말 글(최대 127자): "NetPulse · 측정 중 12:04 경과" / "NetPulse · 링크 끊김 관측 중" / "NetPulse · 측정하지 않음". 갱신은 상태가 바뀔 때와 측정 중 1초에 한 번까지.
- 메뉴(`TrackPopupMenuEx`, 키보드로 다룰 수 있는 Win32 메뉴): **열기**(기본 항목, 굵게) / **증상 표시**(측정 중만 켜짐, Ctrl+M과 같은 호스트 경로) / 구분선 / **종료**. 왼쪽 클릭·키보드 선택(`NIN_SELECT`/`NIN_KEYSELECT`)은 열기, 오른쪽 클릭·메뉴 키(`WM_CONTEXTMENU`)는 메뉴.
- 구현: UI 스레드에서 메시지 전용 창(`HWND_MESSAGE`, 클래스 이름 `NetPulse.Tray.{pid}`)을 만들어 콜백도 UI 스레드에서 받는다. `NOTIFYICON_VERSION_4`, 아이콘 식별은 `uID`(GUID는 실행 파일 경로에 묶여 단일 파일 배포에서 깨질 수 있어 쓰지 않음). 창 프로시저 대리자는 필드로 붙잡는다. 탐색기가 다시 시작되면(`TaskbarCreated` 등록 메시지) 아이콘을 다시 넣는다. `Shell_NotifyIcon` 실패는 기록하고 앱은 계속(그때 닫기는 숨김 대신 종료 — 다시 열 길이 없으므로).
- 메뉴를 띄우기 전 `SetForegroundWindow(메시지 창)`, 닫은 뒤 `WM_NULL`(알려진 Win32 메뉴 닫힘 문제).

#### A3. 알림 규칙 (`DropoutNotifier`, Core)

입력: 장면마다의 관측 종류(`ObservationWatch.Of`, 측정 중만), 측정 끝, 저장 실패 시작, 창 상태(보임·앞 / 보임·뒤 / 숨김·최소화), 설정. 출력: 앱 안 알림(지금 그대로) 또는 풍선.

| 사건 | 앱 안 알림 (창이 보이면) | 풍선 (창이 숨김·최소화·앞이 아님) |
| --- | --- | --- |
| 관측 시작 (None → 외부 응답 없음/링크 끊김) | 지금처럼 | **끊김 구간 시작에 한 번** (설정 "끊김 알림" 켬, 기본 켬) |
| 종류 바뀜 (외부 응답 없음 ↔ 링크 끊김) | 지금처럼 | 같은 구간이면 내지 않음 |
| 관측 끝 (→ None) | 지금처럼 | 구간이 닫힐 때 "끊김 관측이 끝났습니다 (n초)" (설정 "끝났을 때도 알림", 기본 끔) |
| 측정 끝 | 지금처럼 | 한 번 (설정 "측정이 끝났을 때 알림", 기본 켬) |
| 저장 실패 시작 | 지금처럼 | 한 번 (끌 수 없음: 기록 유실 위험) |

- **끊김 구간**: 관측이 None이 된 뒤 **30초** 안에 다시 시작되면 같은 구간이다(짧게 끊겼다 이어지는 간헐 끊김에 풍선이 쏟아지지 않게). 30초 넘게 None이면 구간을 닫는다. 측정이 끝나면 열린 구간도 닫는다(끝 알림은 내지 않음, 측정 끝 알림이 대신).
- 구간 판단은 시계(회차 경과 ms)로 하고, 창 상태와 무관하다: 창이 보이다가 숨겨져도 같은 구간이면 풍선을 새로 내지 않는다.
- 풍선 글은 관측이지 판정이 아니다(`ObservationWatch.Message`와 같은 원칙): "링크 끊김 관측 · 이 PC의 네트워크 연결이 끊긴 상태가 관측되었습니다". 대상 이름·주소는 넣지 않는다(잠금 화면·화면 공유에 보일 수 있음).
- 풍선 플래그: 경고는 `NIIF_WARNING`, 그 밖은 `NIIF_INFO`, 모두 `NIIF_RESPECT_QUIET_TIME`(방해 금지 존중). Windows가 보여 주지 않을 수 있음은 받아들인다(위험 3).
- 풍선을 누르면(`NIN_BALLOONUSERCLICK`) 창을 열고 측정(끝났으면 그 결과) 화면.

#### A4. 단일 실행 (`SingleInstance`)

- 열쇠: 사용자 폴더 전체 경로(정규화·소문자)의 SHA-256 앞 16자. `Local\NetPulse-{열쇠}` Mutex, 이벤트 `-open`·`-exit`.
- 첫 실행이 Mutex를 가진다. 두 번째 실행은 창을 만들기 전에 `-open`(또는 `--exit`면 `-exit`)을 신호하고 종료 코드 0으로 끝난다. 첫 실행은 백그라운드 대기에서 받아 UI 스레드로: open → 다시 열기, exit → 트레이 "종료"와 같은 경로.
- 시험은 시험마다 새 사용자 폴더라 서로 막지 않는다. 데모·실측도 폴더가 달라 따로다. 부품 전시 화면(`--showcase`)은 단일 실행을 쓰지 않는다.
- 첫 실행이 비정상 종료해 Mutex가 버려지면(`AbandonedMutexException`) 새 실행이 가진다.

#### A5. 시험과 진단 값

- `diag.state`에 `resident` 묶음: `trayAdded`, `hidden`, `hintShown`, `tooltip`, `notifications`(이번 실행에 낸 풍선 목록: 종류·제목·시각, 최근 20개), `menu`(마지막으로 띄운 메뉴 항목과 켜짐). 창이 숨어 UIA로 `diag.state`를 못 읽는 동안은 `app-log.jsonl`에 `resident` 사건으로도 남긴다.
- 시험은 메시지 전용 창을 `FindWindowEx(HWND_MESSAGE, …, "NetPulse.Tray.{pid}")`로 찾아 실제 콜백 메시지(`NIN_SELECT`, `WM_CONTEXTMENU`, `NIN_BALLOONUSERCLICK`)를 보낸다 → 실제 처리 경로를 탄다. 메뉴는 Win32 팝업 메뉴라 UIA `Menu`/`MenuItem`으로 찾아 누른다.
- 기존 UI 시험(약 110곳이 측정 중에 닫음)은 지금 동작을 기대한다 → `AppDriver`가 기본으로 `--close-to-tray off`를 넘긴다(이번 실행만, 저장 안 함). M9 시험만 켠다. 기본값(켬)은 `M9` 시험이 인수 없이 실행해 확인한다.

### B. 설정

#### B1. 설정 파일 2판

`settings.json` `version: 2`:

```
{ version, look: { theme, aurora, reduceEffects, reduceMotion },
  resident: { closeToTray: true, notifyDropout: true, notifyRecovered: false, notifyFinished: true, trayHintShown: false },
  records: { folder: null, extraFolders: [] },
  diagnosis: { tcpTargets: null, domains: null } }
```

- 1판을 읽으면 `look`으로 옮기고 나머지는 기본값(저장은 사용자가 무엇을 바꿀 때, 지금 원칙 그대로).
- 알 수 없는 판·손상: 기본값으로 시작, 파일은 그대로. **단, 알 수 없는(더 새) 판일 때는 이 실행에서 설정을 저장하지 않는다**(새 판 파일을 낡은 판으로 덮지 않게) — 설정 화면에 "설정 파일을 읽지 못해 이번 실행의 변경은 저장되지 않습니다" 띠. 손상은 지금처럼 다음 저장이 새로 쓴다.
- `records.folder`가 null이면 기본 위치. 값이 있는데 시작 때 없거나 쓸 수 없으면 측정 시작은 지금 대체 위치 규칙을 따르고, 설정 화면·측정 화면 띠가 알린다(경로를 자동으로 바꾸지 않는다).
- `diagnosis` 값이 null이면 Core 기본값(`DiagnosisSettings`). 읽은 값이 검증에 실패하면 그 항목만 기본값 + 기록.
- 쓰기는 지금처럼 임시 파일 → 바꾸기. 설정 저장은 UI 스레드에서 직렬(마지막 값이 이김).

#### B3. 저장 위치 바꾸기와 옮기기

흐름:

1. [폴더 바꾸기] → `FolderPicker`(`InitializeWithWindow(hwnd)`, 패키지 없는 앱). 시험은 `--pick-folder <경로>`가 고르기를 대신한다.
2. 검사(`RecordFolderRules.Check`): 존재·폴더임, 쓰기 가능(임시 파일 만들고 지움), 지금 위치와 같지 않음, 지금 위치의 안·바깥 포함 관계가 아님, 대체 위치(`%TEMP%\NetPulse\records`)가 아님, 앱 사용자 폴더의 다른 하위 폴더(`diagnoses` 등)가 아님. 실패하면 이유 글, 아무것도 바꾸지 않음.
3. 확인 대화상자: "기록 n개(약 x MB)를 새 위치로 옮깁니다. 옮기는 동안 측정을 시작할 수 없습니다." [옮기고 바꾸기] [취소]. 옮길 기록이 0개면 묻지 않고 바꾼다.
4. 옮기기(`RecordMover`, 백그라운드, 진행 n/전체, [멈추기]는 기록 사이에서 멈춤):
   - 대상: 지금 기본 위치의 측정 폴더(이름이 측정 Id 형식인 폴더)만. 대체 위치·`extraFolders`의 것은 옮기지 않는다(읽기는 계속).
   - 같은 볼륨: 폴더 단위 `Directory.Move`.
   - 다른 볼륨: `{새 위치}\{id}.moving`에 복사 → 파일 수·크기·SHA-256 대조 → `{id}`로 이름 바꾸기 → 원본 삭제. 대조 실패·복사 실패면 `.moving`을 지우고 원본은 그대로.
   - 새 위치에 같은 이름이 있으면 그 기록은 옮기지 않음(충돌로 보고).
   - 원본 삭제 실패(파일 잠김 등)면 새 위치의 사본을 정본으로 두고 원본 폴더 이름을 `{id}.moved`로 바꿔 목록에서 겹치지 않게 한다. 이름 바꾸기도 실패하면 그 기록은 두 곳에 있게 되므로 목록이 같은 Id를 하나로 보이게 한다(도서관이 이미 Id로 합친다 — 구현 전 확인, 아니면 새 위치를 우선).
5. 끝: 설정 `records.folder` = 새 위치. 옮기지 못한 기록이 남은 옛 위치는 `extraFolders`에 넣어 계속 목록에 보인다(사라지지 않음). 결과 상태: 다 옮김 / 일부 옮김(n개 남음, 이유별 수) / 멈춤 / 실패(하나도 못 옮김 → 위치는 바꾸되 옛 위치를 `extraFolders`에).
6. [기본 위치로]도 같은 흐름(목적지가 기본 위치).

동시성:
- 시작 조건: 측정하지 않음, 리포트 내보내기 중 아님. 옮기는 동안 측정 시작·리포트 내보내기 단추는 꺼지고 이유 글("기록을 옮기는 중").
- 시작 전에 메모 쓰기(`RecordMemos.DrainAsync`, `NotesWriter`)를 비우고, 옮기는 동안 새 메모 저장은 막는다(기록 화면 메모 칸 읽기 전용 + 글).
- `RecordLibrary`의 분석 작업자는 옮기는 동안 멈추고(새 시험 훅이 아닌 제품 기능: `PauseAsync`/`Resume`), 끝나면 위치 목록을 바꾼 뒤 처음부터 다시 읽는다. 열려 있던 기록 상세·리포트 선택은 같은 Id로 다시 연다(못 찾으면 목록으로).
- 옮기는 중 창 닫기: 진행 중인 기록 하나를 끝내고(또는 되돌리고) 멈춘 뒤 닫는다. 숨김 대상 아님(측정 중이 아니므로).
- 옮긴 기록을 연 리포트 HTML·진단 기록은 경로를 담지 않으므로 영향 없음(진단 기록은 측정 Id로 연결).

#### B4. 진단 기본값

- `DiagnosisDefaults.Validate`: TCP 주소는 IPv4 점 넷(문서 예: `192.0.2.1`), 둘이 서로 다름. 도메인은 ASCII 호스트 이름(라벨 1~63, 전체 253, 점 하나 이상, 마지막 라벨 숫자만 아님), 둘이 서로 다름. 포털 주소·기대 글·제한시간은 바꾸지 않는다(범위를 작게).
- 저장하면 `DiagnosisWorld`의 설정을 바꾸고 다음 진단부터 쓴다. 진단 기록에는 이미 쓴 대상이 저장된다(M6) — 그대로.

#### B5. N10 TCP 측정 대상 편집

- 프로필 편집기의 대상 줄에 측정 방식 `SegmentedChoice`(ICMP / TCP) + TCP일 때 포트 칸(1~65535, 기본 443). 측정 중에는 읽기 전용(지금 규칙).
- `ProfileValidator`가 이미 TCP를 받는지 확인하고, 포트 범위 검사를 더한다. 기록·분석·리포트는 이미 방식을 담는다(M3) — 표시만 확인: 측정 화면 대상 카드·기록 상세·리포트 측정 조건에 "TCP 443".
- 안내 글: "Ping에 응답하지 않는 대상은 TCP 연결로 잴 수 있습니다. 연결 거부도 응답으로 셉니다." (M3 판정: 거부 = 성공).
- 엔진은 바꾸지 않는다 → M3·M4 시험과 통합 시나리오는 G2에서 그대로 돈다(바꾸지 않았음을 diff로 확인). 데모 시나리오 하나(`steady-tcp.json`)를 더해 TCP 대상이 섞인 측정을 G3에서 돌린다.

## 5. 성능

- 트레이 도움말 갱신: 1초에 한 번까지, UI 스레드에서 `Shell_NotifyIcon(NIM_MODIFY)` 한 번. bench `idle-live`가 지금 기준(p95, 33 ms 초과 수)을 지켜야 한다.

- 옮기기는 백그라운드. 진행 갱신은 기록 하나마다. bench 없음(입출력 시간).

- M5 닫기 결정("측정 중이면 멈추고 저장한 뒤 닫는다, 트레이는 M9")을 바꾼다. 종료 경로의 순서·한도(테마 정리 → 진단 멈춤 → 측정·메모·리포트 정리 → 닫기)는 그대로 `ExitAsync`로 이름만 나눈다.

## 8. 위험

1. **WinUI 창과 Win32 메시지 창이 한 스레드**: 콜백 안에서 오래 걸리는 일을 하지 않고 디스패처 큐로 넘긴다. 메뉴 모달 루프 중 렌더 지연은 받아들인다(메뉴가 떠 있는 동안).
2. **숨긴 창의 WinUI 동작**: `AppWindow.Hide` 동안 합성·타이머가 어떻게 되는지 구현 초기에 확인한다(모션 정지·그리기 0을 진단 값으로 검사). 다시 열 때 테마가 바뀌어 있으면(시스템 테마 따르기) 한 번 다시 적용.
3. **풍선이 안 보일 수 있음**: 방해 금지·알림 끔·Windows 정책. 앱은 호출 성공까지만 보장하고, 설정 설명 글에 적는다. 사용자가 끈 Windows 알림을 앱이 켜지 않는다(시스템 설정).
4. **숨긴 채 측정이 끝난 앱이 남음**: 의도한 상주. 도움말 글이 "측정하지 않음"이 되고, 사용자가 종료할 수 있다. 다음 실행은 단일 실행으로 이 창을 연다.
5. **기록 옮기기는 되돌리기 어렵다**: 확인 대화상자, 복사 후 대조, 원본은 대조 뒤에만 삭제, 실패 시 원본 보존. 옛 위치를 목록에서 잃지 않음.
6. **단일 실행 열쇠**: 사용자 폴더 경로가 달라지면(대소문자·짧은 이름) 두 실행이 될 수 있다 → 전체 경로 정규화. 같은 기록 위치를 쓰는 두 사용자 폴더는 지원하지 않는다.
7. **시험의 기존 닫기 의존**: `AppDriver` 기본 `--close-to-tray off`로 막는다. 이 인수가 실제 기본값 확인을 가리지 않게 M9 시험 하나는 인수 없이 돈다.
8. **아이콘 제작**: 그림 도구 없이 생성 스크립트로 만든다. 16 px 가독성은 시각 검토로만 판단 — 사용자 보고에 아이콘 캡처를 넣는다.

## 9. 대안

| 대안 | 판단 |
| --- | --- |
| 트레이 패키지(H.NotifyIcon 등) | 새 런타임 의존성(사용자 확인 필요) + 우리 테마·키보드 규칙과 맞추는 비용. Win32 직접 호출이 작다 |
| WinAppSDK 앱 알림 | 사용자가 풍선으로 결정 (등록·레지스트리 없음) |
| 최소화하면 트레이로 | 기획서는 "닫기"만 말한다. 최소화는 Windows 기본대로 작업 표시줄 |
| 옮기지 않고 위치만 바꾸기 | 사용자가 "확인 후 옮기기"로 결정 |
| 단일 실행에 WinAppSDK `AppInstance` | 사용자 정의 `Main`(XAML 생성 Main 끄기)이 필요하다. 이름 있는 Mutex·이벤트가 작고 시험이 쉽다 |
