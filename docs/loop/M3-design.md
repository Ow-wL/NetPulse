# M3 설계: 측정 엔진 (2판)

기준: `docs/loop-plan.md` 6절(F3, R1, R5, N3, N9, N10 구조), 6.3 "이어받을 판단 규칙", 8절 M3 행. 기존 앱 동작은 `docs/loop/feature-inventory.md` 4~7절.
화면은 없다. G3은 **화면 없는 통합 시나리오**로 대신한다 (기획서 4.2, 4.3).
1판에 대한 Codex 설계 검토 1라운드 지적 9건을 반영했다 ([지적 n]). 2라운드(마지막) 지적 4건도 Claude 판정으로 모두 수용했다 ([2-n]).

## 1. 목표와 끝났다는 증거

| 범위 (기획서 8절 M3) | 끝났다는 증거 |
| --- | --- |
| 대상·프로필 모델 (대상 역할 포함) | 모델·검증의 로직 테스트, 저장·손상·버전 테스트 |
| 자동 탐지 | 가짜 네트워크 정보로 경우별 테스트 (4절의 상태 전부). 이 PC 실제 탐지는 통합 테스트 (주소를 출력하지 않음) |
| 측정 (Ping, 측정 방식 교체 구조) | ICMP·TCP 공급자가 같은 인터페이스. TCP는 루프백 리스너로 통합 테스트 |

| 통계, 연속 실패 | 이어받을 판단 규칙과 경계 사례를 합성 데이터로 테스트 |
| R5: 저장 실패, 중간에 끊긴 기록, 절전 공백 | 부분 쓰기·flush 실패 주입, 잘린 파일, 시계 공백 주입 테스트 |
| G3 대체 | 실제 시계·ICMP·경로 관측·파일로 측정 → 중지 → 다시 읽기를 대조 (10절) [지적 9] |

  Measurement/MeasurementSession.cs                    한 측정의 수명
  Measurement/GapTracker.cs                            공백·시각 변경 판정

- 측정 로직은 시계, 측정 공급자, 경로 관측, 저장, 절전 알림을 모두 바꿔 끼울 수 있다. 시험용 시계는 **경과 시간과 벽시계를 따로 움직인다** [지적 5].
- 새 제품 런타임 의존성은 없다.

임시 파일에 쓴 뒤 바꾸기. 읽지 못하면 파일을 지우지 않고 `profiles.json.unreadable-<UTC 시각>`으로 옮겨 두고 탐지 제안으로 시작, 상태를 돌려준다.

## 4. 자동 탐지 [지적 7]

**실제 경로 선택 기준**: Windows 경로표에 "공용 주소로 가는 가장 좋은 경로"를 묻는다 (`GetBestRoute2`, 경로표 조회일 뿐 패킷을 보내지 않음). 질의 주소는 제안할 외부 대상 주소다. 경로 우선순위·동률은 Windows가 정한 결과를 그대로 쓴다 (앱이 다시 고르지 않음).

| 상태 | 조건 | 제안 |
| --- | --- | --- |
| `Ok` | 가장 좋은 경로가 있고 다음 홉(게이트웨이)이 있음 | 그 게이트웨이를 `Local` "공유기", 예상 연결 유형 = 그 인터페이스 유형 |
| `NoGateway` | 경로는 있으나 다음 홉이 없음 (같은 링크, VPN·터널에서 흔함) | 외부 대상만. "게이트웨이를 찾지 못했습니다. VPN이나 터널을 쓰는 중일 수 있습니다" |
| `NoIpv4Route` | IPv4 가장 좋은 경로가 없음 | 외부 대상만. "IPv4 인터넷 경로가 없습니다. IPv6만 쓰는 망이거나 연결되지 않은 상태일 수 있습니다" (R5) |
| `NoNetwork` | 작동 중인 인터페이스가 없음 | 제안 없음 |
| `Unknown` | 조회 실패 | 외부 대상만, 실패 사유 |

- 인터페이스 정보: 유형(유선 / 무선 / 터널·PPP / 기타), **가상·터널 여부**(`Yes`/`No`/`Unknown`: 유형이 터널·PPP이거나 알려진 가상 어댑터 설명이면 `Yes`, 판별 근거가 없으면 `Unknown`).
- 다른 인터페이스에도 게이트웨이가 있으면 "다른 경로도 있음"으로 개수만 알린다.
- 외부 대상 제안: 서로 다른 사업자의 공개 DNS 둘 (Cloudflare `1.1.1.1`, Google `8.8.8.8`). 사용자가 바꿀 수 있다.
- 탐지 결과는 로그·테스트 출력에 주소·어댑터 이름을 남기지 않는다. 공개 기록 검사는 `privacy-scan`의 전체 항목(IP, MAC, 어댑터 이름, 호스트명, 사용자명, 로컬 경로, SSID, DNS 서버)을 그대로 쓴다.

## 5. 측정 방식

- `IProbe`(M1). `ProbeFactory`가 대상의 `Method`로 고른다.
- `TcpProbe`: 포트 연결을 맺었다 끊는 시간이 지연. 연결 거부(RST) = 성공(장비가 응답함), 시간 초과 = 손실, 그 밖의 소켓 오류 = 검사 오류. 화면 연결은 M9 선택.

## 6. 회차 전달과 기록

### 6.1 회차 전달 [지적 1]

- 엔진의 상태 구독(M1)은 화면용으로 최신 상태만 준다. 기록·통계는 이것을 쓰지 않는다.
- 엔진에 **회차 출력**을 더한다: 회차가 끝날 때마다 결과를 순서대로 **제한 큐**(`System.Threading.Channels`, 3600회차 = 1시간)에 넣는다. 세션의 처리 작업 하나가 순서대로 꺼내 통계에 더하고 기록에 쓴다. 측정은 큐를 기다리지 않는다.
- 큐가 가득 차면(처리가 1시간 넘게 밀림) 새 회차를 큐에 넣지 못한 것으로 세고(`unprocessed`), 그 범위를 기록 이벤트로 남긴다. 조용히 버리지 않는다.
- 종료: 엔진을 멈춘 뒤 큐를 닫고, 처리 작업이 남은 회차를 다 처리할 때까지 기다린다 (제한 10초). [2-3]
  - 제한을 넘기면 세션이 **기록을 마감**한다: 아직 큐에 남은 회차는 `unprocessed` 범위로 확정하고, 처리 작업에 중단을 요청한다. 진행 중이던 쓰기 하나는 끝나게 두되, 마감 뒤에 끝난 결과는 통계·요약에 넣지 않는다 (처리 작업은 매 회차 전에 마감 여부를 확인한다).
  - 요약은 세션만 쓴다. 처리 작업이 3초 안에 멈추지 않으면 요약을 쓰지 않고 결과에 "기록 마감 실패"를 돌려준다 (읽을 때 원본으로 다시 계산되므로 기록은 잃지 않는다).
  - 수용 기준: 취소를 무시하고 늦게 끝나는 가짜 저장소에서도 종료 결과가 바뀌지 않는다.
- 수용 기준: 느린 가짜 저장소(쓰기마다 지연)와 10배속 데모에서 관측한 회차가 통계·기록에 정확히 한 번씩 들어간다.

### 6.2 파일과 형식

측정 한 회분 = 폴더 하나 (`<저장 위치>/<시작 UTC 시각>_<임의 6자>/`).

| 파일 | 쓰는 시점 | 내용 |
| --- | --- | --- |
| `measurement.json` | 시작 | `format: "netpulse.measurement"`, `version: 1`, 측정 Id(폴더 이름과 같음), 앱 버전, 시작 시각(UTC + 지역 오프셋), 프로필 스냅숏(켠 대상 전부), 주기, 제한시간, 계획 시간 |
| `rounds.jsonl` | 회차마다 한 줄 | `id`(측정 Id), `r`(회차), `due`·`at`(예정·실제 경과 ms), `wall`(UTC), `skipped`, `results: [{t: 대상Id, s: ok/lost/error, ms?: 지연, e?: 오류 사유}]` |
| `events.jsonl` | 일이 생길 때 | 공통: `id`, `type`, `round`(관련 회차, 없으면 생략), `at`(경과 ms), `wall`(UTC). 종류는 6.3 |
| `summary.json` | 끝날 때 | 종료 사유, 끝 시각, 회차 수(관측·확정·대기·폐기·미처리), 건너뜀·공백 수, 대상별 통계, 저장 실패 수, `committedRounds`(확정된 마지막 회차) |

### 6.3 이벤트 종류 (M4가 쓸 계약까지) [지적 8]

| `type` | 내용 |
| --- | --- |
| `route` | 대상, 인터페이스 번호, 유형, `status: ok/failed`, 실패 코드. 측정 시작 때 전부, 이후 바뀔 때만 |
| `gap` | `from`·`to`(경계: 경과 ms와 UTC), `lastRoundBefore`, `firstRoundAfter`, `reason: suspend/stall` |
| `clock` | 벽시계 변경: `deltaMs` |
| `storage` | `writeFailed`(사유, 대기 수), `recovered`, `dropped`(회차 범위), `relocated`(이전·새 위치 종류, 사유) |
| `queue` | `unprocessed`(회차 범위) |
| `symptom` | 증상 표시(M5가 씀): 메모 |
| `link` | 링크 근거(M4가 씀): 어댑터 식별(측정 인터페이스 번호와 연결), `collection: unsupported/denied/observed-none/down/up`, 출처 |

- `link`의 `unsupported`·`denied`는 "근거 없음"을 보존하기 위한 값이다 (기획서 6.2 R2). M3은 이 형식만 정하고 M4가 채운다.

### 6.4 경로 관측 [지적 8, 2-4]

기존 앱과 같이 **인터페이스 번호는 매 회차**, 유형은 30회차마다 다시 조회한다. 조회 실패는 `route` 이벤트의 `status: failed`로 남긴다 (정상으로 꾸미지 않는다).
- **관측 시점**: 엔진의 회차 안에서, 측정 공급자 결과를 받은 직후 같은 회차의 경로를 조회해 **회차 결과와 함께** 큐에 넣는다. 저장이 밀려도 회차에 붙는 경로는 측정 순간의 것이다. 경로 이벤트는 처리 작업이 회차 순서대로 비교해 만들며, 그 경로가 바뀐 **첫 회차**를 `round`로 단다 (그 회차부터 다음 `route` 이벤트 전까지 유효).
- 수용 기준: 저장을 지연시킨 상태에서 경로를 바꾸는 합성 시험에서 바뀐 첫 회차가 정확하다.

### 6.5 쓰기 보장 [지적 2]

- 한 줄을 쓰고 **`Flush(flushToDisk: true)`**까지 성공해야 그 회차가 **확정**이다. 쓰기 전에 파일 길이를 기억해 둔다 (마지막 확정 위치).
- 쓰기나 flush가 실패하면 파일을 **마지막 확정 위치로 잘라 되돌린 뒤** 다시 쓴다 (`SetLength`). 그래서 부분 쓰기 뒤에 재시도 줄이 붙지 않는다.
- 되돌리기마저 실패하면 그 파일을 닫고 `rounds-2.jsonl`처럼 다음 조각 파일로 이어 쓴다 (읽는 쪽은 조각을 차례로 읽는다).
- 같은 회차가 두 번 들어간 경우(flush는 실패로 보고됐지만 실제로는 기록됨) 읽는 쪽이 회차 번호로 첫 줄만 쓰고 중복 수를 센다.
- 앱이 죽으면 확정된 회차까지는 남는다. 전원이 꺼져도 flush를 디스크까지 하므로 마지막 확정 회차까지 남는다 (1초에 한 번 디스크 flush. 비용은 통합 테스트로 잰다).

### 6.6 저장 실패와 대체 [지적 3]

회차의 상태를 넷으로 나눈다: **관측**(측정됨) → **확정**(파일에 씀) / **대기**(쓰기 실패, 메모리에서 재시도 중) / **폐기**(대기가 300회차를 넘어 오래된 것부터 버림).

- 통계는 관측 기준으로 계산하고, 요약에 확정·대기·폐기 수와 폐기 범위를 함께 적는다.
- 끝날 때 대기 회차를 최대 3초 동안 다시 쓰고, 그래도 못 쓴 것은 세션 결과로 돌려준다 (화면이 알림).
- 다시 읽을 때 요약의 `committedRounds`와 원본 회차가 다르면 **원본 기준 통계**를 보여 주고 "기록 일부 누락: 요약은 관측 전체 기준, 원본에는 n회차 없음"을 함께 표시한다.
- **대체 위치**: 기본 `%LOCALAPPDATA%\NetPulse\records`, 대체 `%TEMP%\NetPulse\records`. 측정 시작 때 기본에 쓸 수 없으면 대체로. 측정 중 실패가 **디스크 가득 참**이고 대체 위치가 **같은 볼륨**이면 옮기지 않는다 (효과 없음). 다른 이유(권한 등)이거나 다른 볼륨이면 대체 위치로 옮긴다. 둘 다 안 되면 측정을 시작하지 않는다.
- **조각** [2-2]: 위치를 옮기면 대체 위치에 같은 측정 Id의 폴더를 새로 만들고, `measurement.json`을 **복제**해 `segment`(조각 번호, 0부터)를 올려 적는다. 각 조각 폴더는 혼자서도 열 수 있다. `relocated` 이벤트는 새 조각에 반드시 쓰고(이전 위치·사유), 이전 위치에는 시도만 한다.
- 읽기: 측정 Id로 두 위치에서 조각 폴더를 모두 찾아 `segment` 순으로 회차를 합친다 (회차 번호 중복은 첫 것만). 조각 번호가 비면(이전 위치에 접근 불가) **누락 조각**으로 표시한다. 요약은 마지막 조각에 쓴다.

### 6.7 읽기와 손상 처리 [지적 4]

- `measurement.json`이 없거나 형식·필수 필드가 틀리면 **읽을 수 없는 기록**이다 (대상을 해석할 수 없음).
- `format`이 다르거나 `version`이 1보다 크면 "지원하지 않는 기록 형식".
- `rounds.jsonl` 줄마다 검증한다: 측정 Id 일치, 필수 필드·자료형, 회차 번호가 앞 줄보다 큼(같으면 중복, 작으면 역전), 결과의 대상 Id가 스냅숏에 있음, 결과값 조합(`ok`면 지연 있음, `lost`·`error`면 지연 없음, `error`면 사유 있음), 모르는 결과값.
  - 어긋난 줄은 **어디에 있든** 건너뛰고 종류별로 센다 (마지막 줄만이 아니다). 마지막 줄의 잘림은 `truncatedTail`로 따로 센다.
  - 손상 줄이 하나라도 있으면 기록 상태에 `damaged`를 붙이고 통계는 읽은 줄로 계산한다.
- `events.jsonl`의 손상은 측정 분석과 분리한다: 이벤트만 일부 잃었다고 표시하고 회차 통계는 그대로.
- **우선순위** [2-1]: 통계는 **언제나 원본 회차로 다시 계산**한다. 요약에서는 종료 사유와 관측 전체 수(관측·확정·대기·폐기·미처리)만 쓴다. 요약의 관측 수와 원본의 유효 회차 수가 다르면(중간 손상·폐기 포함) "기록 일부 누락: 관측 n회차 중 원본 m회차"를 표시한다. 요약이 없거나 손상되면 `endReason: interrupted`.
- 수용 기준: 마지막 회차 번호는 같고 중간 회차만 손상·폐기된 기록에서 누락이 표시된다.
- 같은 버전 안에서 필드를 더할 때는 **없을 때의 의미**를 함께 정한다 (예: `skipped` 없음 = 0). 알려진 필드의 모르는 값은 무시하지 않고 손상으로 센다.

## 7. 시간 모델 [지적 5]

- 회차 번호와 측정 시간은 **경과 시간**(단조 시계)에서 나온다. 길이·간격은 모두 경과 시간으로 계산하고, 벽시계(UTC)는 표시용이다.
- **공백**(관측 없음, 손실도 성공도 아님)은 시간 경계로 표현한다: 시작·끝의 경과 ms와 UTC, 직전·직후 회차. 회차 번호가 이어져 있어도(절전 중 단조 시계가 멈춘 경우) 공백일 수 있다.
  - `suspend`: 절전 알림부터 복귀 알림까지. 복귀가 계획 시간 뒤면 공백은 측정 끝에서 닫히고 측정은 `completed`로 끝난다 (다음 회차가 없어도).
  - `stall`: 한 번에 건너뛴 회차가 10회 이상 (앱이 멈춤). 이 회차들은 건너뜀이 아니라 공백으로만 센다 (중복 계수 없음).
  - 절전 경계에 걸친 진행 중 회차(절전 알림 전에 시작해 복귀 뒤에 끝남)는 결과를 `gap`으로 바꾼다 (손실로 세지 않음).
- **벽시계 변경**(`clock`): 벽시계와 경과 시간의 차이가 5초 넘게 바뀌면 기록만 한다. 관측은 계속되므로 공백이 아니다.

## 8. 통계 [지적 6]

- **활성 대상** = 스냅숏에서 켠 대상. 회차마다 활성 대상 전부의 결과가 있어야 완전한 회차다.

| 값 | 규칙 |
| --- | --- |
| 성공·손실·검사 오류 수 | 회차 결과 그대로. 공백·건너뜀·미처리 회차는 넣지 않는다 |
| 손실률 | 손실 ÷ (성공 + 손실). 분모 0이면 값 없음 |
| 평균·최소·최대 지연 | 성공만. 없으면 값 없음 |
| 95백분위 지연 | 성공 지연의 최근접 순위법 (정렬 후 ⌈0.95·n⌉번째) |
| 연속 손실 구간 | 그 대상의 결과가 회차 번호로 이어진 `lost`일 때만 같은 구간. 건너뜀·공백·미처리·그 대상의 `error`·그 대상 결과 없음에서 끊는다 |
| 최대 연속 실패 (N9) | 연속 손실 구간의 최대 **회차 수** (검사 오류는 실패에 넣지 않음) |
| 마지막 성공·손실·검사 오류 시각 (N9) | 각각 따로. "마지막 실패" = 마지막 손실 |
| 구간 길이 | 회차 수와 경과 시간의 범위: 최소 = 마지막 손실 − 첫 손실, 최대 = 직후 성공 − 직전 성공. 직전·직후 성공이 없거나 그 사이에 공백이 있으면 그 끝은 **열린 끝**(값 없음) |

- 측정 전체: 회차 수, 건너뜀, 공백, 미처리, **불완전 회차**(활성 대상 결과가 빠졌거나 검사 오류가 있는 회차). 손실과 오류가 함께 있는 회차는 손실 통계에 그대로 들어가고 불완전 회차로도 센다.
- 판정(끊김 구분, 구간 후보, 등급)은 M4. M3은 통계와 사실까지.

## 9. 측정 세션

1. 프로필 검증 → 저장 위치 확보 → `measurement.json` → 경로 초기값 이벤트.
2. 엔진 시작. 회차 출력(6.1)을 처리 작업이 받아 통계·기록. 회차마다 경로 번호 관측(6.4).
3. 공백·시각 변경(7절), 저장 실패(6.6).
4. 끝: 계획 완료 `completed`, 사용자 중지 `stopped`, 예외 `error`. 엔진 정지(M1 규칙) → 큐 배출 → 대기 회차 재시도 → `summary.json`. 요약 쓰기 실패는 결과로 돌려준다.
5. 세션 상태(구독, 화면·트레이용): 진행 회차, 대상별 통계, 저장 상태, 공백 상태.

앱 연결: `App`의 실시간 모드가 탐지 제안 프로필로 세션을 돌린다 (화면은 M5).

## 10. 테스트 계획

**G2 로직 (`NetPulse.Core.Tests`)**
- 프로필 검증, 저장·손상(옮겨 두기)·버전.
- 탐지: `Ok`, `NoGateway`, `NoIpv4Route`, `NoNetwork`, `Unknown`, 다른 경로 있음, 가상·터널 `Yes/No/Unknown`, 유선/무선.
- 통계 경계: 오류만 있는 대상, 성공 없음, 건너뜀·공백·오류·결과 없음에서 끊김, 처음부터 끝까지 손실(양끝 열림), 공백 사이 구간, 손실+오류 회차, 95백분위.
- 회차 전달: 느린 저장소 + 10배속 데모에서 정확히 한 번씩, 큐 포화 시 `unprocessed` 범위.
- 쓰기: 부분 쓰기 실패 → 되돌린 뒤 재시도로 손상 줄 없음, flush 실패 뒤 실제 기록됨 → 읽을 때 중복 1개, 되돌리기 실패 → 다음 조각, 300 초과 폐기 범위, 끝날 때 재시도·미저장 반환.
- 읽기: 왕복, 중간 손상 줄·역전·중복·모르는 대상·모순 조합·모르는 값, 잘린 끝, 요약 없음·손상·불일치 우선순위, 이벤트 손상 분리, 다른 형식·높은 버전.
- 시간: 경과·벽시계를 따로 움직이는 시계로 `stall`(건너뜀과 중복 계수 없음), 절전 알림(회차 번호 연속인 경우 포함), 절전 경계에 걸친 회차, 계획 시간 뒤 복귀, 벽시계 변경(공백 아님).
- 세션: 완료·중지·오류 종료 사유.

**G3 대체 (`NetPulse.Platform.Tests`, 화면 없는 통합 시나리오)** [지적 9]
- **실제 Windows 전체 경로**: 실제 시계, 실제 ICMP(루프백 대상과 문서용 주소 대상 하나), 실제 경로 관측, 실제 파일 저장소로 세션 시작 → 5초쯤 뒤 **명시적 중지** → 기록을 다시 읽어 세션이 메모리에 가진 결과와 회차별로 정확히 같은지, 종료 사유가 `stopped`인지, 경로 이벤트가 있는지(값 또는 실패 상태). 네트워크 성공 여부는 판정하지 않는다 (관측값의 정확한 보존만 본다).
- 데모 시나리오 `outage.json`을 배속으로 실제 파일까지 → 다시 읽어 손실 구간이 시나리오와 맞는지. 같은 기록의 끝을 자르고 요약을 지운 뒤 복구되는지.
- TCP 루프백: 테스트가 연 리스너(성공), 닫힌 포트(거부 = 성공), 응답 없는 주소(시간 초과 = 손실).
- 이 PC 탐지: 상태가 정의된 값 중 하나, 제안 프로필이 검증을 통과(또는 안내 상태). 주소를 출력하지 않는다.
- 회차마다 디스크 flush 비용: 300회차 쓰기 시간의 95백분위를 기록 (판정 기준은 50 ms 이하).

CI도 이 테스트들을 돈다 (루프백·문서용 주소·데모만, 외부 네트워크 응답에 의존하지 않음).
