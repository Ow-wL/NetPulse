# M3 설계: 측정 엔진

기준: `docs/loop-plan.md` 6절(F3, R1, R5, N3, N9, N10 구조), 6.3 "이어받을 판단 규칙", 8절 M3 행. 기존 앱 동작은 `docs/loop/feature-inventory.md` 4~6절.
화면은 없다. G3은 **화면 없는 통합 시나리오**로 대신한다 (기획서 4.2).

## 1. 목표와 끝났다는 증거

| 범위 (기획서 8절 M3) | 끝났다는 증거 |
| --- | --- |
| 대상·프로필 모델 (대상 역할 포함) | 모델과 검증 규칙의 로직 테스트. 저장·손상·버전 테스트 |
| 자동 탐지 | 가짜 네트워크 정보로 경우별 테스트(게이트웨이 있음/없음/여럿/IPv4 경로 없음). 이 PC 실제 탐지는 통합 테스트(식별 정보를 기록하지 않음) |
| 측정 (Ping, 측정 방식 교체 구조) | ICMP·TCP 공급자가 같은 인터페이스. TCP는 루프백 리스너로 통합 테스트 |
| 버전 있는 기록 형식 | 쓰기·읽기·중간에 끊긴 파일 복구·모르는 버전 거부 테스트 |
| 통계, 연속 실패 | 이어받을 판단 규칙과 경계 사례를 합성 데이터로 테스트 |
| R5: 저장 실패, 중간에 끊긴 기록, 절전 공백 | 쓰기 실패 주입, 잘린 파일, 시계 공백 주입 테스트 |
| G3 대체 | 데모 시나리오로 실제 파일까지 쓰는 측정 한 회분을 끝까지 돌리고 기록을 다시 읽어 통계가 맞는지 확인 |

## 2. 구조

```

  Targets/Target.cs, Profile.cs, ProfileStore.cs      대상·프로필 모델과 저장 (profiles.json 버전 1)
  Detection/DetectionPlanner.cs                        탐지 결과 → 제안 프로필 (순수 로직)
  Measurement/ (M1: 시계, 스케줄러, 엔진)
  Measurement/MeasurementSession.cs                    한 측정의 수명: 기록 열기 → 엔진 → 공백·경로 → 종료 사유 → 요약
  Measurement/GapTracker.cs                            시계 공백(절전) 판정
  Records/RecordFormat.cs, RecordWriter.cs, RecordReader.cs   기록 형식 버전 1
  Records/RecordLocation.cs                            저장 위치와 대체
  Statistics/TargetStats.cs, LossRuns.cs               통계, 연속 실패
src/NetPulse.Platform/
  IcmpProbe.cs (M1), TcpProbe.cs                       측정 방식
  NetworkInfo.cs                                        게이트웨이·인터페이스 조회 (System.Net.NetworkInformation)
  RouteObserver.cs                                      대상별 Windows 경로(인터페이스 번호, 유형)
  PowerEvents.cs                                        절전·복귀 알림
tests/NetPulse.Core.Tests/   로직 테스트 (합성 데이터, 가짜 시계·가짜 저장소)

```

- 측정 로직은 시계(`IClock`), 측정 공급자(`IProbe`), 경로 관측(`IRouteObserver`), 저장(`IRecordSink`), 절전 알림(`IPowerEvents`)을 모두 바꿔 끼울 수 있다 (기획서 6.3 "수용 기준의 원칙").
- 새 제품 런타임 의존성은 없다 (.NET 기본 API와 iphlpapi P/Invoke).

## 3. 대상과 프로필

### 3.1 대상

| 필드 | 뜻 |
| --- | --- |
| `Id` | 프로필 안에서 고유한 짧은 이름 (기록에서 대상을 가리킴) |
| `Name` | 사용자에게 보이는 이름 ("공유기", "Cloudflare DNS") |
| `Address` | IPv4 주소 (IPv6 측정은 범위 밖, 기획서 6.3) |
| `Role` | `Local`(공유기·확장기 등 로컬 장비) / `External`(외부) |
| `Provider` | 외부 대상의 사업자 이름 (서로 다른 사업자 판정용, 비울 수 있음) |
| `Method` | `Icmp` 또는 `Tcp(port)` |
| `Enabled`, 순서 | 끄기와 사용자 순서. 순서는 실제 경로를 증명하지 않는다 (기획서 6.2) |

### 3.2 프로필

| 필드 | 기본값 | 범위 |
| --- | --- | --- |
| 대상 목록 | 탐지 제안 | 1~8개 |
| 측정 주기 | 1초 | 1초 고정 (주기를 바꾸는 것은 범위 밖. 기존 앱과 같음) |
| 응답 제한시간 | 800 ms | 200~900 ms (주기보다 짧아야 함) |
| 측정 시간 | 10분 | 1~720분 (기존 앱 값. 기획서 6.3 "측정 시간과 종료 동작"에서 M3 확정) |
| 예상 연결 유형 | 탐지한 유형 | 유선 / Wi‑Fi / 상관없음 |

**검증** (저장할 때와 측정을 시작할 때):
- 오류(시작 거부): 대상 0개, 주소 형식 틀림, Id 중복, 제한시간 범위 밖, 측정 시간 범위 밖.
- 경고(시작은 함): 외부 대상이 둘 미만이거나 서로 다른 사업자가 둘 미만 ("외부 연결 단절" 판정을 할 수 없음을 알림, 기획서 6.2), 로컬 대상 없음.

### 3.3 저장 (`profiles.json`, 버전 1)

- 사용자 데이터 폴더. 프로필 여럿과 마지막으로 쓴 프로필 Id.
- M2 설정 파일과 같은 규칙: 임시 파일에 쓴 뒤 바꾸기. 읽지 못하면(손상·모르는 버전) **파일을 지우지 않고** `profiles.json.unreadable-<시각>`으로 옮겨 두고 탐지 제안으로 시작, 상태를 돌려준다 (R5 손상된 설정 처리).

## 4. 자동 탐지

- `NetworkInfo`(Platform): 작동 중인 인터페이스마다 유형(유선/무선/기타), IPv4 기본 게이트웨이, 기본 경로 여부를 읽는다.
- `DetectionPlanner`(Core, 순수 로직)가 제안을 만든다:
  - IPv4 기본 게이트웨이가 있는 인터페이스 중 기본 경로인 것 하나 → 그 게이트웨이를 `Local` 대상 "공유기"로. 예상 연결 유형은 그 인터페이스 유형.
  - 게이트웨이가 여럿이면 기본 경로 쪽을 고르고 나머지는 "다른 게이트웨이도 있음"으로 알린다.
  - 외부 대상: 서로 다른 사업자의 공개 DNS 둘 (Cloudflare `1.1.1.1`, Google `8.8.8.8`). 사용자가 바꿀 수 있다.
  - **IPv4 경로 없음**(R5): IPv4 기본 게이트웨이가 하나도 없으면 제안은 외부 대상만, 상태 `NoIpv4Route`와 안내 문구("IPv4 인터넷 경로가 없습니다. IPv6만 쓰는 망이거나 연결되지 않은 상태일 수 있습니다")를 돌려준다.
  - 작동 중인 인터페이스가 없으면 `NoNetwork`.
- 탐지 결과는 로그·테스트 출력에 주소를 남기지 않는다 (기획서 4.7). 통합 테스트는 상태와 개수만 확인한다.

## 5. 측정 방식

- `IProbe`(M1)를 그대로 쓴다. `ProbeFactory`가 대상의 `Method`로 공급자를 고른다.
- `IcmpProbe`(M1): 32바이트, 제한시간은 프로필 값.
- `TcpProbe`: 지정 포트로 연결을 맺었다 끊는 시간을 지연으로. 연결 거부(RST)는 "응답함"(장비가 살아 있음)으로 성공, 시간 초과는 손실, 그 밖의 소켓 오류는 검사 오류. N10은 선택 기능이므로 화면 연결은 M9에서, 이번에는 공급자와 테스트까지.

## 6. 기록 형식 (버전 1)

측정 한 회분 = 폴더 하나 (`<저장 위치>/<시작 시각 UTC>_<임의 6자>/`).

| 파일 | 쓰는 시점 | 내용 |
| --- | --- | --- |
| `measurement.json` | 시작 | `format: "netpulse.measurement"`, `version: 1`, 앱 버전, 시작 시각(UTC와 지역 오프셋), 프로필 스냅숏(대상 전부), 주기, 제한시간, 계획 시간 |
| `rounds.jsonl` | 회차마다 한 줄 추가 + 바로 flush | 회차 번호, 예정·실제 경과, 실제 시각, 직전에 건너뛴 회차 수, 대상별 `{결과: ok/lost/error, 지연, 오류 사유}` |
| `events.jsonl` | 일이 생길 때 | 경로 초기값·변경(대상, 인터페이스 번호, 유형), 공백 시작·끝(사유), 저장 실패·복구, 증상 표시(M5에서 씀, 형식은 지금 정함) |
| `summary.json` | 끝날 때 | 종료 사유(`completed`/`stopped`/`error`), 끝난 시각, 회차·건너뜀·공백 수, 대상별 통계, 저장 실패 수 |

- **줄 단위 JSON**이라 중간에 끊겨도 마지막 줄만 잘린다. 읽을 때 잘린 마지막 줄은 버리고 `recovered: true`, `endReason: "interrupted"`로 다룬다. `summary.json`이 없으면 `rounds.jsonl`로 통계를 다시 계산한다 (R5 중간에 끊긴 기록).
- 읽기는 `format`이 다르거나 `version`이 1보다 크면 "지원하지 않는 기록 형식"으로 거부한다 (조용히 틀리게 읽지 않음).
- 버전을 올리는 규칙: 필드 추가는 같은 버전(읽는 쪽이 모르는 필드는 무시), 의미가 바뀌거나 필드를 빼면 버전을 올린다.
- 개인 정보: 기록은 사용자 PC에만 있다. 리포트로 내보낼 때의 가리기는 M8.

### 6.1 저장 위치와 대체 (R5 저장 위치 대체)

- 기본: `%LOCALAPPDATA%\NetPulse\records`. 쓸 수 없으면(권한, 디스크 가득) `%TEMP%\NetPulse\records`로 바꾸고 기록에 대체 사유를 적는다. 둘 다 안 되면 측정을 시작하지 않고 이유를 돌려준다 (기록 없는 측정은 하지 않는다).
- 사용자 지정 위치는 설정 화면(M5)에서. 지금은 모델에 필드만.

### 6.2 저장 실패 (R5)

- 회차를 쓰다 실패하면 측정은 계속하고, 실패한 회차를 메모리에 모아 두었다가 다음 회차에서 다시 쓴다 (최대 300회차, 넘으면 오래된 것부터 버리고 버린 수를 센다). 실패·복구를 `events.jsonl`에 남기려 시도하고, 세션 상태로 알린다.
- 끝날 때 요약에 저장 실패 회차 수와 버린 회차 수를 적는다. 종료 사유와 저장 실패는 따로다 (이어받을 규칙).

## 7. 시간 모델과 절전 공백 (R5)

- 회차 번호는 측정 시작 기준 **경과 시간**에서 나온다 (M1 스케줄러).
- **공백 판정**: 다음 중 하나면 그 사이 회차는 "관측 없음"(공백)이다. 손실도 성공도 아니다.
  1. 절전·복귀 알림(`IPowerEvents`)을 받음 → 절전 시작부터 복귀까지.
  2. 한 번에 건너뛴 회차가 **10회 이상**(주기 10배) → 앱이 멈췄거나 시계가 크게 뛴 것으로 보고 공백. (주기 몇 배 정도의 늦음은 지금처럼 "건너뛴 회차"로 센다.)
  3. 벽시계와 경과 시간의 차이가 갑자기 **5초 이상** 벌어짐 → 시스템 시각 변경으로 기록하고, 회차 번호는 경과 시간을 그대로 쓴다.
- 공백은 `events.jsonl`에 `{type: gap, fromRound, toRound, reason: suspend|stall}`로 남기고, 통계에서 연속 손실을 끊는다 (이어받을 규칙: 관측 공백을 정상으로도 손실로도 그리지 않는다).
- 측정 시간은 **경과 시간** 기준이다. 절전으로 경과 시간이 흐르면(Windows의 단조 시계가 절전 중에도 흐르는지는 통합 테스트로 확인할 수 없어 두 경우 모두 처리) 계획 시간이 지나 있으면 복귀 직후 `completed`로 끝난다.

## 8. 통계 (이어받을 판단 규칙)

대상별:

| 값 | 규칙 |
| --- | --- |
| 성공·손실·검사 오류 수 | 회차 결과 그대로. 공백·건너뛴 회차는 어디에도 넣지 않는다 |
| 손실률 | 손실 ÷ (성공 + 손실). 검사 오류는 분모에서 뺀다. 분모가 0이면 값 없음 |
| 평균·최소·최대 지연, 95백분위 | 성공 응답만. 없으면 값 없음 (0이 아님) |
| 연속 손실 구간 | 회차 번호가 이어질 때만 같은 구간. 건너뛴 회차·공백·검사 오류에서 끊는다 |
| 최대 연속 실패 (N9) | 위 구간의 최대 길이 |
| 마지막 성공·실패 시각 (N9) | 실제 시각 |
| 구간의 길이 표현 | 회차 수와 **불확실 범위**: 최소 = 마지막 손실 − 첫 손실, 최대 = 직후 성공 − 직전 성공 (모르면 열린 끝). 첫·마지막 손실 표본 차이를 끊김 길이처럼 보여 주지 않는다 (이어받지 않는 표현) |

측정 전체:
- 회차 수, 건너뛴 회차 수, 공백 회차 수, **불완전 회차 수**(대상 결과가 빠졌거나 검사 오류가 있는 회차).
- 판정(끊김 구분, 구간 후보, 등급)은 **M4**다. M3은 판정이 쓸 통계와 사실만 만든다.

## 9. 측정 세션 (`MeasurementSession`)

1. 프로필 검증 → 저장 위치 확보 → `measurement.json` 쓰기 → 경로 초기값 기록.
2. 엔진(M1) 시작. 회차마다: 결과를 통계에 더하고 `rounds.jsonl`에 쓴다. 30회차마다 경로를 다시 조회해 바뀌면 이벤트(기존 앱과 같음).
3. 공백 판정(7절), 저장 실패 처리(6.2).
4. 끝: 계획 시간 완료 → `completed`, 사용자 중지 → `stopped`, 예외 → `error`. 엔진을 멈추고(M1 규칙, 제한시간 안에) `summary.json`을 쓴다. 요약 쓰기가 실패하면 그 사실을 세션 결과로 돌려준다 (읽을 때 다시 계산되므로 기록은 잃지 않는다).
5. 세션 상태(구독): 진행 회차, 대상별 통계, 저장 상태, 공백 상태. 화면(M5)과 트레이(M7)가 구독한다.

앱 연결: M3에서는 `App`의 실시간 모드가 탐지 제안 프로필로 세션을 돌리도록 바꾼다 (빈 창에 회차만 보임). 화면은 M5.

## 10. 테스트 계획

**G2 로직 (`NetPulse.Core.Tests`)**
- 프로필 검증 오류·경고, 저장·읽기·손상(옮겨 두기)·모르는 버전.
- 탐지 제안: 게이트웨이 하나, 여럿(기본 경로 선택), 없음(IPv4 경로 없음), 인터페이스 없음, 유선/무선 유형.
- 통계 경계 사례: 검사 오류만 있는 대상(손실률 값 없음), 성공 없음(지연 값 없음), 건너뛴 회차에서 연속 손실 끊김, 공백에서 끊김, 검사 오류에서 끊김, 처음부터 끝까지 손실, 열린 끝 구간 범위, 불완전 회차.
- 기록: 쓰기 → 읽기 왕복, 잘린 마지막 줄 복구, 요약 없음 → 재계산, 다른 형식·높은 버전 거부, 모르는 필드 무시.
- 저장 실패: 가짜 저장소로 회차 쓰기 실패 → 다음 회차에 재시도 성공, 300회차 넘는 실패에서 버린 수.
- 공백: 가짜 시계로 10회 이상 건너뜀 → 공백, 절전 알림 → 공백, 벽시계 점프 → 시각 변경 이벤트.
- 세션: 데모 공급자 + 메모리 저장소로 완료·중지·오류 종료 사유.

**G3 대체 (`NetPulse.Platform.Tests`, 화면 없는 통합 시나리오)**
- 데모 시나리오 `outage.json`(배속)으로 실제 임시 폴더에 측정 한 회분을 쓰고, `RecordReader`로 다시 읽어 회차 수·손실 구간·종료 사유가 시나리오와 맞는지.
- 같은 기록의 `rounds.jsonl` 마지막 줄을 자르고 `summary.json`을 지운 뒤 다시 읽어 복구되는지.
- ICMP 루프백 3회차 세션, TCP 루프백(테스트가 연 리스너, 닫힌 포트) 성공·거부·시간 초과.
- 이 PC 탐지: 결과 상태가 정의된 값 중 하나이고 제안 프로필이 검증을 통과(또는 IPv4 경로 없음 안내)하는지. 주소는 출력하지 않는다.
- 경로 관측: 루프백 대상의 인터페이스 조회가 값 또는 명시적 실패 상태를 돌려주는지.

CI도 이 테스트들을 돈다 (외부 네트워크를 쓰지 않음: 루프백과 데모만).

## 11. 위험

| 위험 | 대응 |
| --- | --- |
| 절전 중 단조 시계 동작이 PC마다 다름 | 절전 알림과 큰 건너뜀 두 경로로 공백 판정. 시계가 흐르든 멈추든 공백으로 처리 |
| 줄 단위 기록의 디스크 쓰기 비용 (회차마다 flush) | 1초에 한 줄(대상 8개 기준 1 KB 미만). 12시간 약 43,000줄. 통합 테스트로 쓰기 시간 측정 |
| 공개 DNS를 기본 외부 대상으로 쓰는 것 | 사용자가 바꿀 수 있음. 서로 다른 사업자 둘이 기획서 6.2의 최소 조건 |
| 탐지가 VPN·가상 어댑터를 고름 | 기본 경로 인터페이스를 고르고 가상 어댑터 여부를 표시. 확인은 첫 실행 화면(M5)에서 사용자가 |

## 12. 이 마일스톤에서 하지 않는 것

- 끊김 판정, 구간 후보, 등급, 링크 근거 수집: M4.
- 화면(대상 편집, 첫 실행 안내, 타임라인): M5.
- 트레이 상주: M7. 시간 제한 없는 측정(N12): M9 선택.
- TCP 측정의 화면 연결: M9 선택.
