# M2 설계: 디자인 시스템

기준: `docs/loop-plan.md` 7절(디자인), 8절 M2 행, 4.3 G5. 디자인 방향은 D2 흑요석(+ 연한 오로라 옵션, 기본 꺼짐). 기술은 D1 WinUI 3.

## 1. 목표와 끝났다는 증거

M2가 끝나면 이후 모든 화면(M5~)이 **토큰과 부품만으로** 만들어질 수 있어야 한다. 화면 코드에 색·간격·시간 값을 직접 쓰지 않는다.

| 범위 (기획서 8절) | 끝났다는 증거 |
| --- | --- |
| 토큰, 두 테마 | 다크·라이트 토큰 표가 같은 키를 가진다 (테스트). 화면 코드 정적 검사에서 토큰 밖 값 0건 |
| 유리 재질 3단계 + 차폐층 | 부품 전시 화면 캡처에서 세 두께와 차폐층이 구분된다. 대비 계산이 최악 배경 조건에서 기준 이상 |
| 기본 부품: 버튼, 카드, 탐색, 알림, 대화상자, 그래프 스타일 | 부품 전시 화면에 모든 부품과 상태가 있다. UI 테스트로 키보드 조작 |
| 모션 토큰 | 모든 애니메이션이 모션 도구를 거친다 (정적 검사). 움직임 줄이기에서 이동·크기 애니메이션 0건 (실행 기록) |
| 테마 전환 | 누른 지점에서 원형으로 퍼진다. 전환 중 최대 프레임 간격 기준 이하 (5.4) |
| 접근성 대체 | 투명 효과 끔·고대비·애니메이션 끔·배터리 절약 각각의 대체 화면 캡처 |
| R5 중 키보드 조작, 배율 150% | 탭 순서·초점 표시·대화상자 초점 가둠 UI 테스트. 150% 상당 배치에서 잘림 0건 |
| 부품 전시 화면 | `--showcase`로 열리는 전시 화면과 캡처 매트릭스 |
| (M1 이월) 지적 2건 | 4.4 |

## 2. 사전 확인 (설계 전 시험, `.loop/probe`, 커밋하지 않음)

M0에서 테마 전환 때 장면 전체를 다시 만들면서 최대 83 ms 멈칫이 있었다. 장면을 다시 만들지 않는 방식을 시험했다.

- 방식: 화면의 모든 색은 **공유하는 변경 가능 브러시**를 쓴다. 테마를 바꾸면 브러시의 색 값만 바꾼다 (요소를 다시 만들지 않는다). 원형 전환은 바꾸기 직전 화면을 `RenderTargetBitmap`으로 찍어 살아 있는 화면 **아래**에 깔고, 살아 있는 화면(새 테마)에 Composition 원형 클립을 키운다.
- 결과 (1280×800, 아크릴 카드 9장, 단일 실행):

| 항목 | 값 |
| --- | --- |
| 브러시 색 바꾸기 (색 5개 + 아크릴 9개) | 8.2 ms |
| 직전 화면 찍기 | 30~44 ms (10회) |
| 전환 10회 중 프레임 간격 | 95백분위 7.0 ms, 최대 40.3 ms, 33 ms 초과 2회 |
| 찍은 화면과 실제 화면 (라이트, 같은 순간) | 표본 6점 모두 같은 값 |

- 확인하지 못한 것: 다크의 찍은 화면과 실제 화면 비교 (캡처 도구 문제로 실패. 구현에서 창 전용 캡처로 다시 확인).
- 관측한 문제: 전환 도중 원형 안쪽의 라이트 아크릴이 회색으로 보였다 (M0에서도 "클립 경계의 회색 칩"으로 관측). → 전환하는 동안만 유리를 같은 색의 불투명 표면으로 바꾸고, 끝나면 아크릴로 되돌린다 (5.4). 효과가 없으면 위험 항목으로 남기고 사용자에게 알린다.

## 4. 토큰

### 4.1 색 (흑요석)

M0 시안(`spikes/design/home-mockups.html`, 커밋 `b772cdc`)의 흑요석 값을 출발점으로 한다.

| 토큰 | 다크 | 라이트 | 용도 |
| --- | --- | --- | --- |
| `bg` | #050507 | #f4f4f2 | 창 바탕 |
| `ink` | #f4f4f5 | #111113 | 본문 |
| `muted` | #9b9ba4 | #5d5d66 | 보조 글자 |
| `faint` | 흰색 6% | 검정 5% | 구분선, 비활성 바탕 |
| `accent` | #7dd3fc | #0369a1 | 주요 행동, 선택, 1차 그래프 계열 |
| `accentInk` | #04131c | #ffffff | 강조색 위 글자 |
| `series2` | #a1a1aa (점선) | #71717a (점선) | 2차 그래프 계열. 색과 선 모양을 함께 다르게 |
| `ok` / `warn` / `bad` | #34d399 / #fbbf24 / #fb7185 | #047857 / #a16207 / #be123c | 상태. 항상 아이콘·글자와 함께 |
| `focusOuter` / `focusInner` | `accent` / #050507 | `accent` / #ffffff | 두 겹 초점 표시 |
| `edge`, `hi` | 흰색 10%, 35% | 검정 8%, 흰색 100% | 유리 테두리, 위쪽 하이라이트 |

- `muted`처럼 대비가 빠듯한 값은 대비 계산(4.3)이 기준에 못 미치면 **값을 조정**하고 조정 내역을 DECISIONS에 남긴다. 시안 값을 지키려고 기준을 낮추지 않는다.
- 고대비 모드는 이 표를 쓰지 않고 시스템 색(`UISettings.UIElementColor`)으로 만든 팔레트를 쓴다.

### 4.2 재질

| 단계 | 쓰는 곳 | 다크 틴트·불투명도 | 라이트 | 그림자 |
| --- | --- | --- | --- | --- |
| 두꺼운 유리 `content` | 카드, 표, 그래프 | #0e0e12, 0.70 | #ffffff, 0.72 | 깊음 |
| 보통 유리 `control` | 탐색, 도구 막대, 버튼 바탕 | 0.52 | 0.55 | 중간 |
| 얇은 유리 `float` | 펼침 메뉴, 도움말 풍선 | 0.36 | 0.40 | 가장 깊음 |
| 차폐층 `scrim` + 보통 유리 | 대화상자, 알림 | 차폐층 검정 55% | 차폐층 검정 25% | — |

- WinUI `AcrylicBrush`(창 안 아크릴)로 만든다. 블러 반경은 속성이 없어 조절하지 못한다 (M0 확인, "근사"). 두께 차이는 틴트 불투명도, 테두리, 그림자로 낸다.
- **최소 불투명도**: `content`는 0.70(다크)·0.72(라이트) 아래로 내리지 않는다. 대비 계산의 전제다.
- **겹침**: 유리는 두 단까지만. 같은 단계끼리 겹치지 않는다 (전시 화면 구성으로 지키고, M5에서 화면별로 다시 본다).
- **반경**: 바깥 18, 안쪽 12, 칩 999(완전 둥긂). 안쪽 반경 = 바깥 반경 − 안쪽 여백 규칙으로 동심을 맞춘다.
- 효과 줄이기에서는 같은 틴트를 불투명도 1로 칠한 단색 표면으로 바꾼다 (구성과 색 유지).

### 4.3 대비 계산 (G2에서 자동)

- 배경 범위 토큰: 바탕(`bg`), 배경 빛 색 4개를 최대 불투명도로 바탕에 합성한 색, 끊김 상태의 빛 색, 연한 오로라를 켰을 때의 빛 색. 이 집합이 "배경 빛이 가질 수 있는 색"이다.
- 유리 표면색 = 틴트를 불투명도 α로 배경 위에 합성. 배경 범위의 각 색에 대해 계산하고 **가장 불리한 값**으로 판정한다. 블러는 배경을 평균 내므로 범위 안에 머문다고 본다 (가정. 아크릴의 잡음 질감과 광도 층은 계산에 넣지 않는다 → G5 캡처 추출로 보완).
- 판정: 본문(`ink`) 4.5:1, 보조(`muted`) 4.5:1 (본문 크기로 쓰므로), 큰 글자 3:1, 그래프 선·상태색·초점 표시 3:1, 강조색 위 글자 4.5:1.
- G5에서 캡처의 실제 색을 뽑아 같은 대비를 다시 계산한다 (글자 주변 배경 표본). 계산과 실측이 크게 다르면(대비비 0.5 이상 차이) 원인을 기록한다.

### 4.4 간격·글자·모션

- 간격: 4의 배수 단계 `s1`~`s8` (4, 8, 12, 16, 20, 24, 32, 48).
- 글자 (Pretendard): `display` 52 Bold, `title` 30 Bold, `headline` 22 SemiBold, `body` 14 Regular(줄 높이 1.5), `caption` 12.5 Regular, `label` 13 SemiBold. 한국어는 단어 단위 줄바꿈(M0의 단어 결합자 방식)을 공용 함수로.
- 모션: 기획서 7.4 표를 그대로 토큰으로. `fast` 167, `mid` 250, `slow` 333, `fade` 83 ms, 곡선 `enter (0,0,0,1)`, `move (0.55,0.55,0,1)`. 테마 전환 550 ms(`enter` 곡선).

## 5. 동작

### 5.1 테마 상태와 설정

- 선택: 다크 / 라이트 / Windows 설정 따르기. 첫 실행은 다크. 사용자 데이터 폴더의 `settings.json`(버전 1)에 저장한다. 읽기 실패나 알 수 없는 버전이면 기본값으로 시작하고 기록에 남긴다 (파일을 지우지 않는다).
- 같은 파일에 연한 오로라(기본 꺼짐), 효과 줄이기, 움직임 줄이기.
- Windows 설정 따르기: `UISettings.ColorValuesChanged`로 바뀌면 따라간다.

### 5.2 실제 적용 모드 (`Effects`)

| 입력 | 결과 |
| --- | --- |
| Windows 투명 효과 끔 (`UISettings.AdvancedEffectsEnabled`), 배터리 절약 (`PowerManager.EnergySaverStatus`), 앱의 효과 줄이기 | 유리 → 불투명 표면. 배경 빛 정지·흐리게, 오로라 숨김 |
| 고대비 (`AccessibilitySettings.HighContrast`) | 시스템 색 팔레트. 배경 빛·유리·오로라·그림자 끔. 초점 표시는 시스템 강조색 |
| Windows 애니메이션 끔 (`UISettings.AnimationsEnabled`), 앱의 움직임 줄이기 | 모션 도구가 이동·크기·반복 애니메이션을 만들지 않고 83 ms 페이드만. 테마 전환은 즉시 교체 |

- 바뀌면 다시 계산해 바로 적용한다 (이벤트 구독).
- **시험용 인수** (Windows 설정을 바꾸지 않고 같은 경로를 탄다): `--simulate-high-contrast`, `--simulate-transparency-off`, `--simulate-animations-off`, `--simulate-energy-saver`. 기록에 "시뮬레이션"으로 남는다. 실제 Windows 설정을 바꾼 동작은 시험하지 않는다 (사용자 시스템 설정, 기획서 금지 사항). → 사용자 인수 항목.

### 5.3 모션 도구 (`Motion`)

- 화면 코드는 `Motion.Enter(el)`, `Motion.Move(...)`, `Motion.Fade(...)`, `Motion.Pulse(...)`, `Motion.CountUp(...)`, `Motion.Repeat(...)`만 쓴다. `Storyboard`, `*Animation` 생성은 `Motion.cs`와 `Theme.cs`(원형 전환)만 할 수 있다 (정적 검사).
- 움직임 줄이기면 `Enter`/`Move`는 페이드로, `Pulse`/`Repeat`/`CountUp`은 최종 상태로 즉시 바뀐다.
- 진단: 모션 도구는 만든 애니메이션 수를 종류별로 센다. 전시 화면이 이 수를 시작·종료 기록과 자동화 속성으로 내보내 UI 테스트가 확인한다.
- 포인터를 따라가는 유리 하이라이트, 측정 시작 버튼의 광택, 상태 점 파동(M0 미구현 3종)을 여기서 만든다.

### 5.4 원형 테마 전환

1. 전환 중이면 새 요청은 마지막 것만 기억했다가 끝난 뒤 한 번 적용한다 (M0은 무시했음).
2. 직전 화면을 찍어 살아 있는 화면 아래에 둔다. 찍기에 실패하면 원형 없이 페이드로 바꾼다 (기록).
3. 유리를 같은 색의 불투명 표면으로 잠시 바꾼다 (회색 칩 대책).
4. 공유 브러시의 색을 새 테마로 바꾼다. 제목 표시줄 색도.
5. 살아 있는 화면에 누른 지점 중심의 원형 클립을 0 → 창 대각선까지 550 ms로 키운다.
6. 끝나면 클립을 떼고, 찍은 화면을 버리고, 유리를 아크릴로 되돌린다.
- 움직임 줄이기나 고대비면 1, 4만 (즉시 교체).
- 키보드 초점은 그대로 유지된다 (요소를 다시 만들지 않으므로).
- 화면 읽기: 찍은 화면은 자동화 트리에 넣지 않는다 (`AccessibilityView.Raw`).
- 프레임 기준 (이 PC): 전환 중 최대 프레임 간격 **50 ms 이하**, 전환 1회당 33 ms 초과 **2회 이하**. 평상시(배경 빛만 움직임) 95백분위 **16.7 ms 이하**. 프레임 간격은 `CompositionTarget.Rendering` 콜백 사이 시간이다 (실제 표시 프레임과 다를 수 있음).

### 5.5 배경 빛

- 원형 그라디언트 4개(가장자리 투명)를 Composition 애니메이션으로 천천히 이동 (UI 스레드를 쓰지 않음). 색은 토큰 브러시.
- 끊김 상태(`--state problem` 또는 전시 화면 스위치): 빛 색이 붉은 계열로 1.2초에 걸쳐 바뀐다. 회복 시 되돌아온다.
- 연한 오로라: 비스듬한 빛 띠 3개, 불투명도 토큰(다크 0.30, 라이트 0.45를 시작값으로 시안과 비교해 맞춤). 켜고 끌 때 장면을 다시 만들지 않고 투명도만 바꾼다.
- 흑요석의 미세한 결(점 질감)은 이번에 넣지 않는다 (타일 이미지가 필요하고 화면 읽기·대비에 영향 없음. M11에서 다시 본다).

### 5.6 부품

| 부품 | 상태 | 키보드·화면 읽기 |
| --- | --- | --- |
| `GlassButton` (주요, 보조, 고스트, 아이콘) | 기본, 포인터 올림, 누름, 비활성, 초점 | `Button` 기반 (호출 패턴). Enter/Space |
| `GlassCard` | 기본, 불러오는 중(윤곽이 은은하게 빛남), 빈 상태, 오류 | 제목을 이름으로 |
| `NavRail` + 항목 | 선택, 포인터 올림, 초점 | 위아래 화살표로 이동, 선택 항목 알림 |
| `ToastHost` | 정보, 성공, 주의, 오류. 자동 닫힘(시간 토큰), 닫기 버튼 | 정중한 알림(`LiveSetting.Polite`), 오류는 `Assertive` |
| `DialogHost` | 차폐층 + 보통 유리. 확인/취소 | 열 때 첫 버튼에 초점, 탭 순환을 대화상자 안에 가둠, Esc 닫기, 닫으면 연 버튼으로 초점 복귀 |
| `StatusChip` | 정상, 주의, 끊김, 알 수 없음 | 아이콘 + 글자 (색만으로 전달하지 않음) |
| `SettingToggle`, `SegmentedChoice` | 켬/끔, 다중 선택지 | `ToggleSwitch`/라디오 의미 |
| `LineChart` | 1차·2차 계열, 응답 없음 구간 띠, 격자, 축 글자 | 요약 문장을 이름으로 |

- 초점 표시: 두 겹(`focusOuter` 2 px + `focusInner` 1 px). 유리 위에서도 보이도록 최악 배경 기준 3:1 이상을 계산으로 확인.
- 기본 컨트롤(`Button`, `ToggleSwitch`)의 시각 상태는 즉시 색만 바뀌게 하고, 누름 가라앉음 같은 움직임은 모션 도구로 낸다 (움직임 줄이기 일관성).

### 5.7 부품 전시 화면 (`--showcase`)

- 왼쪽 `NavRail`로 절 이동: 색·글자, 재질, 버튼, 카드와 상태, 탐색, 알림, 대화상자, 그래프, 모션, 설정.
- 위쪽 도구 막대: 테마(다크/라이트/시스템, 원형 전환), 정상/끊김, 오로라, 효과 줄이기, 움직임 줄이기.
- 모든 요소에 `영역.요소` 자동화 ID.
- 시험 인수: `--theme`, `--state`, `--aurora`, `--section`, `--ui-scale`(5.8), `--bench`(5.9).

### 5.8 배율 150%

- Windows 배율을 바꾸는 것은 시스템 설정이라 하지 않는다. 대신 `--ui-scale 1.5`: 창 크기는 그대로 두고 내용을 논리 크기(창 ÷ 1.5)로 배치한 뒤 1.5배로 그린다 (`Viewbox`). 같은 물리 창에서 배치 공간이 150%일 때와 같아진다.
- 이 방식이 보장하는 것: 작은 논리 크기에서의 잘림·넘침·줄바꿈. 보장하지 못하는 것: 실제 DPI 변경 이벤트, 글자 래스터 품질, 제목 표시줄. → 사용자 인수 항목에 "실제 150%에서 확인"을 넣는다.
- 잘림 검사: 각 요소의 자동화 경계가 가로로 창 안에 있고, 글자가 잘림 표시 없이 다 보이는지 (`TextBlock.IsTextTrimmed`를 진단으로 내보냄). 세로는 스크롤로 닿으면 된다.

### 5.9 프레임 측정 (`--bench`)

전시 화면에서 순서대로: 정지 5초(배경 빛만), 원형 테마 전환 6회(다크↔라이트), 오로라 켜고 끄기 4회, 정지 5초. 구간마다 프레임 간격 표본을 `app-log.jsonl`에 기록하고 UI 테스트가 5.4 기준으로 판정한다. 결과 표는 `docs/loop/m2/bench.md`(생성).

## 6. 이월: M1 지적 2건

1. `MeasurementEngine.StopAsync`: 첫 호출이 취소 콜백·측정 작업을 함께 기다리는 작업을 만들어 보관한다. 두 번째 호출은 그 작업을 같은 제한시간으로 기다린다 (바로 true를 돌려주지 않음). `DisposeAsync`는 그 작업이 실제로 끝났을 때만 취소 원본을 정리하고, 끝나지 않았으면 정리하지 않고 기록할 수 있게 결과를 돌려준다. 테스트: 첫 호출 시간 초과 → 두 번째 호출도 false → 풀어 준 뒤 세 번째 호출 true.
2. `PlatformTests`: `Rounds > 0`일 때만 마지막 회차를 검사한다.

## 9. 대안과 고르지 않은 이유

- **XAML `ThemeResource` + `RequestedTheme` 전환**: 표준 방식이지만 원형 전환에 두 테마 화면이 동시에 필요해 결국 장면 복제나 화면 찍기가 필요하다. 코드로 만드는 부품과 섞기 어렵다.
- **장면 두 벌 (M0 방식)**: 83 ms 멈칫과 메모리 증가를 관측했다.
- **Win2D로 구멍 뚫린 마스크**: 새 런타임 의존성 (사용자 승인 필요). 원형 클립을 아래위만 바꿔 같은 효과를 낸다.
- **시스템 백드롭(Mica/Desktop Acrylic)**: 창 뒤 바탕화면이 비쳐 배경 빛 연출과 대비 계산을 통제할 수 없다.

## 10. 이 마일스톤에서 하지 않는 것

- 실제 화면(홈, 측정 등)과 앱 틀·제목 표시줄 확장: M5.
- 실시간 타임라인 성능: M5.
- 흑요석 미세 결 질감: M11에서 재검토.
- 실제 Windows 설정 변경 시험: 사용자 인수.
