# M2 설계: 디자인 시스템 (2판)

기준: `docs/loop-plan.md` 7절(디자인), 8절 M2 행, 4.3 G5. 디자인 방향은 D2 흑요석(+ 연한 오로라 옵션, 기본 꺼짐). 기술은 D1 WinUI 3.
1판에 대한 Codex 설계 검토 1라운드 지적 11건을 반영했다 (`DECISIONS.md` "M2 설계 검토 1라운드", 각 절 끝의 [지적 n] 표시).
2라운드(마지막) 지적 6건도 Claude 판정으로 모두 수용해 반영했다 ([2-n] 표시).

## 1. 목표와 끝났다는 증거

M2가 끝나면 이후 모든 화면(M5~)이 **토큰과 부품만으로** 만들어질 수 있어야 한다. 화면 코드에 색·간격·시간 값을 직접 쓰지 않는다.

| 범위 (기획서 8절) | 끝났다는 증거 |
| --- | --- |
| 토큰, 두 테마 | 다크·라이트·고대비 팔레트가 같은 키를 가진다 (G2). 정적 검사 규칙 위반 0건 (G2, 4.6) |
| 유리 재질 3단계 + 차폐층 | 계산 대비(4.3)와 실측 대비(7.3)가 모두 기준 이상. 캡처에서 세 두께와 차폐층 구분 (G5 시각 검토) |
| 기본 부품 | 전시 화면에 부품 × 상태 목록(5.6)이 모두 있다. 조작 UI 테스트 |
| 모션 토큰 | 모든 애니메이션이 모션 도구를 거친다 (정적 검사). 실행 중 움직임 줄이기를 켜면 활성 이동 애니메이션 0, 연속 캡처 변화 없음 (5.3) |
| 테마 전환 | 원형으로 퍼진다. 전환 실패 대체(페이드)가 시험 실행에서 0회. 찍은 화면과 실제 화면 차이 기준 이내 (5.4). 프레임 기준 이내 (5.9) |
| 접근성 대체 | 효과 줄이기·고대비(고정 팔레트 2종)·움직임 줄이기·저성능 대체 각각의 진단 값과 캡처 (5.2) |
| R5 키보드, 배율 150% | 초점 순서·가둠·초점 표시 검사 (7.2). 150% 상당 배치 검사 위반 0건 (5.8) |
| 부품 전시 화면 | `--showcase`와 캡처 매트릭스 (7.4) |
| M1 이월 지적 2건 | 6절 (이미 커밋 `ad09e59`) |

**한 마일스톤 안에서 세 단계로 나눠 커밋한다** (각 단계 끝에 로컬 게이트를 돌린다. G4는 마지막에 한 번):
- A. 토큰·대비·정적 검사·설정 저장 (`NetPulse.Design`, 테스트, 게이트 연결)
- B. 재질·부품·전시 화면·키보드·접근성 대체
- C. 원형 전환·모션·저성능 대체·성능·캡처 매트릭스·G5 묶음

## 2. 사전 확인 (설계 전 시험, `.loop/probe`, 커밋하지 않음)

M0에서 테마 전환 때 장면 전체를 다시 만들면서 최대 83 ms 멈칫이 있었다. 장면을 다시 만들지 않는 방식을 시험했다.

- 방식: 화면의 모든 색은 **공유하는 변경 가능 브러시**를 쓴다. 테마를 바꾸면 브러시의 색 값만 바꾼다. 원형 전환은 바꾸기 직전 화면을 `RenderTargetBitmap`으로 찍어 살아 있는 화면 **아래**에 깔고, 살아 있는 화면(새 테마)에 Composition 원형 클립을 키운다.
- 결과 (1280×800, 아크릴 카드 9장, 단일 실행):

| 항목 | 값 |
| --- | --- |
| 브러시 색 바꾸기 (색 5개 + 아크릴 9개) | 8.2 ms |
| 직전 화면 찍기 | 30~44 ms (10회) |
| 전환 10회 중 프레임 간격 (원형 애니메이션 시작부터. 찍기 시간은 빠짐) | 95백분위 7.0 ms, 최대 40.3 ms, 33 ms 초과 2회 |
| 찍은 화면과 실제 화면 (라이트, 같은 순간) | 표본 6점 모두 같은 값 |

- 확인하지 못한 것: 다크의 찍은 화면과 실제 화면 비교. 이 비교가 실패한 이유는 화면 영역 캡처가 앞에 있던 다른 앱을 찍었기 때문이다 (그 이미지는 바로 지웠다). → 앞으로 캡처는 창 전용만 쓴다 (7.1).
- 관측한 문제: 전환 도중 원형 안쪽의 라이트 아크릴이 회색으로 보였다 (M0에서도 관측). → 5.4의 불투명 대체.
- 이 결과는 방향을 고르는 근거일 뿐 G5 증거가 아니다. G5 증거는 5.4·5.9의 시험으로 다시 만든다. [지적 3]

### 4.3 대비 계산 (G2) [지적 1]

**배경 층의 정의** (그리는 순서대로, 이 밖의 것은 유리 뒤에 오지 않는다):

1. 바탕 `bg` (불투명)
2. 배경 빛 원 4개: 토큰 색, 각 불투명도 상한 (다크 0.6, 라이트 0.9). 움직이므로 **모두 한 점에서 겹칠 수 있다고** 본다.
3. 연한 오로라 띠 3개 (켰을 때): 토큰 색, 불투명도 상한. 역시 모두 겹칠 수 있다고 본다.
4. 끊김 상태는 2의 색을 끊김 색으로 바꾼 별도 집합.
5. `control` 뒤에는 추가로 `content` 유리 표면이 올 수 있다 (카드 안 버튼). **스크롤 콘텐츠는 `control` 유리 밑으로 지나가지 않는다** (배치 규칙: 도구 막대·탐색은 스크롤 영역 밖. 구현 판정). `float` 뒤에는 `content` 표면과 그래프 계열색·상태색·글자색이 올 수 있다.
6. 대화상자·알림은 차폐층을 1~5 위에 합성한 뒤 그 위의 보통 유리로 계산한다.

**계산** [2-1]:
1. 층 2·3의 모든 부분집합(최대 2⁷ = 128가지)을 그리는 순서대로 바탕에 합성해 꼭짓점 색을 만든다. 각 층의 불투명도가 0~상한 사이 어느 값이든 결과는 이 꼭짓점들의 볼록결합이다.
2. 블러는 색의 가중 평균이므로 결과의 각 채널은 꼭짓점의 **채널별 최솟값~최댓값** 사이에 있다. 이 두 경계색을 `Low`, `High`라 한다.
3. 알파 합성과 sRGB 선형화는 채널마다 **단조 증가**이고 휘도 가중치는 양수다. 그래서 그 위에 틴트를 합성한 표면의 휘도는 L(틴트⊕`Low`) ~ L(틴트⊕`High`) 구간 안에 있다. (볼록성이 아니라 단조성이 근거다. 평균색의 휘도는 꼭짓점 휘도보다 낮을 수 있지만 `Low`의 휘도보다 낮을 수는 없다.)
4. `control`: `content` 표면 범위를 배경 범위와 합친 위에 틴트를 합성한다. `float`: 여기에 5의 불투명 색(그래프·상태색, 글자색)까지 채널별로 합쳐 넓힌 범위 위에 틴트를 합성한다.
5. `dialog`: `control` 표면 범위와 배경 범위를 합친 범위 위에 차폐층을, 그 위에 대화상자 틴트를 차례로 합성한다.
6. 판정: 표면 휘도 구간 [Lmin, Lmax]에서 전경과의 대비가 가장 낮은 값 (전경 휘도가 구간 안이면 1:1로 실패). 구현은 `BackgroundRange.WorstRatio`다. 색 목록만 열거하는 `Contrast.Worst`는 최종 판정에 쓰지 않는다.

**기준**: 본문(`ink`)·보조(`muted`) 4.5:1, 큰 글자(18.66 px 굵게 또는 24 px 이상) 3:1, 그래프 선·상태색·초점 표시·비활성 아닌 컨트롤 경계 3:1, 강조색 위 글자 4.5:1.

**한계**: 아크릴은 단순 알파 합성이 아니다 (광도 층, 잡음). 그래서 계산 통과만으로 끝내지 않고 7.3의 실측도 **같은 기준으로 실패 조건**으로 둔다. [지적 2]

### 4.4 간격·글자·모션

- 간격: `s1`~`s8` (4, 8, 12, 16, 20, 24, 32, 48). 크기: 아이콘 16·18·20, 컨트롤 높이 32·40·48.
- 글자 (Pretendard): `display` 52 Bold, `title` 30 Bold, `headline` 22 SemiBold, `body` 14 Regular(줄 높이 1.5), `caption` 12.5 Regular, `label` 13 SemiBold. 한국어는 단어 단위 줄바꿈 공용 함수.
- 모션 시간: `fast` 167, `mid` 250, `slow` 333, `fade` 83 ms, 테마 전환 550 ms, 차례 등장 시차 40 ms. 곡선 `enter (0,0,0,1)`, `move (0.55,0.55,0,1)`.

### 4.5 기획서 7.4 모션과 M2 도구의 대응 [지적 11]

| 7.4 모션 | M2 도구 | 전시 화면 예 | 실제 적용 |
| --- | --- | --- | --- |
| 화면 전환 (공통 요소 이동 + 교차 페이드) | `Motion.SharedMove(from, to)` (Composition 이동, 크기, 투명도) + `Motion.CrossFade` | 카드를 누르면 상세 패널로 커지며 이동 | M5 탐색 |

## 5. 동작

### 5.1 설정

- 사용자 데이터 폴더의 `settings.json` (버전 1): 테마(다크/라이트/시스템, 기본 다크), 연한 오로라(기본 끔), 효과 줄이기(끔), 움직임 줄이기(끔).
- 읽기 실패·모르는 버전이면 기본값으로 시작하고 기록에 남긴다. 파일을 지우거나 덮어쓰지 않는다 (사용자가 설정을 바꿀 때 새로 쓴다). 쓰기는 임시 파일 → 바꾸기.

### 5.2 적용 모드 (`Effects`) [지적 4, 5]

입력은 둘로 나뉜다: **OS 상태 공급자**(투명 효과, 애니메이션, 고대비, 배터리 절약, 시스템 색)와 **앱 설정**. 시뮬레이션 인수는 OS 상태 공급자를 고정값 공급자로 바꾼다.

| 우선순위 | 조건 | 재질 | 배경 빛·오로라 | 색 |
| --- | --- | --- | --- | --- |
| 1 | 고대비 | 단색 (시스템 색) | 끔 | 시스템 색 매핑 |
| 2 | 투명 효과 끔, 배터리 절약, 앱 효과 줄이기, 저성능 대체 | 불투명 표면 (4.2) | 정지, 오로라 숨김 | 테마 |
| 3 | 평상시 | 아크릴 | 움직임 | 테마 |

움직임 줄이기(OS 애니메이션 끔 또는 앱 설정)는 위 표와 독립이다.

**고대비 매핑** (시스템 색 이름 → 용도): `Window`→바탕·표면, `WindowText`→본문·테두리, `GrayText`→보조·비활성, `Highlight`/`HighlightText`→선택·주요 행동, `Hotlight`→링크·초점, `ButtonFace`/`ButtonText`→버튼. 상태는 색 대신 아이콘·글자만으로 구분한다.
**시뮬레이션** (`--simulate-high-contrast dark|light`): Windows 고대비 테마 "Aquatic"(어두운)과 "Desert"(밝은)에 해당하는 고정 팔레트를 주입한다. 이 시험이 보장하는 것은 **앱의 매핑과 분기**뿐이다. 실제 OS 이벤트, 프레임워크의 고대비 자동 보정(`HighContrastAdjustment`), 화면 읽기 사용성은 검증하지 않는다 → 사용자 인수 항목.
**그 밖의 시뮬레이션**: `--simulate-transparency-off`, `--simulate-animations-off`, `--simulate-energy-saver`, `--simulate-low-performance`. 기록에 "시뮬레이션"으로 남는다. 실제 Windows 설정은 바꾸지 않는다.

**저성능 대체** [2-3]: `FramePacer`는 `CompositionTarget.Rendering` 콜백 사이 간격을 잰다 (실제 표시 프레임과 같지 않을 수 있다). 시작 후 처음 정지 2초의 중앙값을 기준 간격 T로 둔다 (60 Hz면 약 16.7 ms). 2초 창의 95백분위가 max(25 ms, 1.5T)를 넘는 창이 2번 연속이면 우선순위 2로 내린다 (블러 반경을 낮출 수 없으므로 불투명 표면 + 배경 정지). 95백분위가 1.25T 이하로 10초 이어지면 되돌린다. 1분에 한 번 넘게 오가지 않는다. 전환·창 크기 조절 중의 표본은 넣지 않는다.

**바뀔 때**: 이벤트를 받으면 모드를 다시 계산해 바로 적용한다. 원형 전환 중이면 끝난 뒤 최신 입력으로 다시 계산한다.

### 5.3 모션 도구 (`Motion`) [지적 4]

- 화면 코드는 `Motion`의 함수만 쓴다 (4.5 표). 다른 곳에서 애니메이션을 만들면 정적 검사가 막는다.
- **소유와 해제**: 모든 모션은 `Motion`이 돌려준 핸들로 등록된다. 핸들은 소유 요소가 화면에서 떨어지면(`Unloaded`) 멈추고 해제된다.
- **움직임 줄이기를 켜는 순간**: 활성 핸들을 모두 멈추고 최종 상태(반복형은 쉬는 상태)로 맞춘다. 포인터 하이라이트는 숨긴다. 배경 빛·오로라는 현재 위치에서 멈춘다. 이후 새 요청은 83 ms 페이드 또는 즉시 변경.
- **끄는 순간**: 반복형(배경 빛, 펄스, 상태 점)만 다시 시작한다.
- **진단**: 활성 핸들 수를 종류별로 (`move`, `scale`, `repeat`, `fade`), 누적 생성 수, 현재 모드. 자동화 속성(`diag.motion`)과 기록으로 낸다.
- **검사**: 실행 중 움직임 줄이기를 켠 뒤 (1) 활성 `move`·`scale`·`repeat` = 0, (2) 500 ms 간격 캡처 두 장의 채널별 평균 절대 차이 1.0 이하, 99백분위 4 이하 [2-6], (3) 버튼을 눌러도 `move`·`scale`이 생기지 않음.
- 기본 컨트롤의 시각 상태 전환은 즉시 색만 바뀌게 템플릿을 둔다 (시각 상태 Storyboard 없음).

### 5.4 원형 테마 전환 [지적 3]

**순서** (2의 찍기가 끝난 뒤 3~5를 **중간에 양보 없이** 이어서 실행한다. 이것이 새 색이 클립 없이 보이는 프레임을 막는다는 것은 보장이 아니라 **검증 대상**이다 [2-4]: XAML 브러시 갱신, 아크릴 교체, Composition 클립, 제목 표시줄이 한 표시 시점에 묶인다는 근거를 문서에서 확인하지 못했다. 검증은 7.3의 경계 프레임 시험):

1. 요청 받음 (시각 기록). 전환 중이면 마지막 요청만 기억했다가 끝난 뒤 한 번 적용한다.
2. 직전 화면을 찍는다 (`RenderTargetBitmap`, 비동기). 찍기를 기다리는 동안에는 아무것도 바꾸지 않는다.
3. 찍은 화면을 살아 있는 화면 아래에 넣고, 살아 있는 화면에 반경 0의 원형 클립을 건다.
4. 유리를 불투명 표면으로 바꾸고, 공유 브러시를 새 테마로 바꾼다. 제목 표시줄 색도.
5. 원형 클립을 0 → 창 대각선까지 550 ms로 키운다.
6. 끝나면: 클립 해제, 찍은 화면 제거, 유리를 현재 적용 모드대로(아크릴 또는 불투명) 되돌림, 적용 모드 재계산, 대기 요청 처리.

**중단과 정리**: 6은 `finally`에서 반드시 실행한다. 창 크기가 바뀌면 애니메이션을 끝으로 건너뛴다. 창을 닫거나 예외가 나면 바로 6으로. **움직임 줄이기나 고대비가 켜지면 진행 중인 전환을 바로 최종 상태로 끝내고 6을 실행한 뒤 최신 모드를 적용한다** [2-4]. 효과 줄이기 등 다른 설정 변경은 6 뒤 최신 입력으로 다시 계산한다.

**대체**: 2가 실패하거나 시간 제한(200 ms)을 넘으면 원형 없이 83 ms 페이드로 바꾸고 기록한다. 이는 실행 중 복구책이며 **G5 통과 증거가 아니다**: G5의 전환 시험에서 대체가 한 번이라도 일어나면 실패다.
**즉시 교체**: 움직임 줄이기·고대비면 2·3·5 없이 4·6만.

**찍은 화면의 충실도** (G5): 다크·라이트 양방향, 배경 빛·오로라 켬·그래프·열린 알림을 포함한 전시 장면에서, 배경 움직임을 멈춘 진단 모드(`--freeze-motion`)로 찍은 화면과 같은 순간의 창 캡처(`PrintWindow`)를 비교한다. 기준: 채널별 평균 절대 차이 3 이하, 99백분위 12 이하.
**자동화**: 찍은 화면은 이름 없는 `Image`라 컨트롤·콘텐츠 보기에는 없다 (Raw 보기에는 있음). 전환 동안에만 있다. 키보드 초점은 요소를 다시 만들지 않으므로 유지된다.

### 5.8 배율 150% [지적 9]

- Windows 배율은 시스템 설정이라 바꾸지 않는다. 시험은 이 PC의 현재 배율에서 돌고, 그 값을 결과에 적는다.
- `--ui-scale 1.5`: 창의 물리 크기는 그대로, 내용을 `Viewbox` 안에서 논리 크기(창 ÷ 1.5)로 배치해 1.5배로 그린다. 오버레이도 같은 `Viewbox` 안에 있다 (3절, `Popup` 없음).
- **검사** (`Diagnostics`가 이름 있는 요소마다 내보냄): 요소 경계, 조상들의 클립·스크롤 보기와 교차한 실제 보이는 영역, `TextBlock.IsTextTrimmed`, 같은 부모 안 상호작용 요소끼리의 겹침.
  - 스크롤 영역 밖: 보이는 영역 = 경계 (잘림 0).
  - 스크롤 영역 안: 가로 범위가 보기 안에 있고, 세로는 스크롤로 닿음.
  - 글자 잘림 0, 상호작용 요소 겹침 0.
- 보장하지 못하는 것: 실제 DPI 변경 이벤트, 글자 래스터 품질, 제목 표시줄 → 사용자 인수 항목.

### 5.9 프레임과 자원 측정 (`--bench`, 캡처 시험과 별도 실행) [지적 8]

- 구간 정의: 전환 1회 = 요청 시각부터 6의 끝 + 200 ms까지 (찍기, 색 변경, 클립 해제, 아크릴 복귀 포함).
- 순서: 준비 전환 2회(버림) → 정지 5초 → 전환 6회(1.5초 간격) → 오로라 켜고 끄기 4회 → 정지 5초 → 전환 14회 더(메모리용) → 정지 5초.
- 기준 (이 PC 한 대. 60 fps 체감을 증명하지 않는다):
  - 정지 구간 95백분위 16.7 ms 이하.
  - 전환 구간 최대 50 ms 이하, 전환 1회당 33 ms 초과 2회 이하.
  - 표본이 구간 길이 × 30개보다 적으면 측정 무효로 1회 다시 돌리고, 또 무효면 실패.
- 자원: 남은 찍은 화면 0, 반복 모션 수가 시작 때와 같음, 테마 이벤트 구독 수 불변. 전용 메모리는 **전환 20회 뒤와 60회 뒤 차이 20 MB 이하, 60회 뒤 400 MB 이하** (강제 가비지 수집 뒤). (구현 판정: 처음 20회쯤은 WinUI 내부 캐시로 크게 늘고 멈춘다. DECISIONS "M2 구현 B·C단계")
- 원본 표본은 비공개 산출물(`artifacts/<SHA>/ui/bench/`)에. 공개하는 `docs/loop/m2/bench.md`는 요약 수치와 측정 조건만 (식별 정보 없음).

## 7. 테스트 계획

### 7.1 UI 테스트의 안전과 결정성 [지적 7]

- 캡처는 창 전용(`PrintWindow`)만. 캡처할 때 전경 전환(`SetForegroundWindow`)을 하지 않는다 (M1 코드에서 뺀다).
- 일반 조작은 대상 프로세스의 UI Automation 패턴(호출, 토글, 선택, 값)만 쓴다. 키 입력을 보내지 않는다.
- UI 테스트 어셈블리 전체를 직렬로 돈다 (병렬 끔).
- **실제 키 입력 시험**(Tab, Esc, 화살표)은 따로 묶는다 (`KeyboardTests`). 키를 하나 보낼 때마다 직전에 전경 창이 대상 프로세스인지 확인하고, 아니면 즉시 중단해 **실패(미완료)**로 남긴다 (통과로 세지 않는다). 사용자가 PC를 쓰는 중이면 이 시험은 돌지 않으므로, 그때는 사용자에게 잠시 PC를 비워 달라고 요청한다.
- 키 입력 없이 확인할 수 있는 것은 앱 안에서 확인한다: 대화상자를 열 때 첫 버튼 초점, Esc 경로, 닫은 뒤 초점 복귀. (구현 판정: WinUI 데스크톱에서는 `FocusManager.FindNextElement`로 다음 초점 요소를 계산할 수 없어 탭 순서·가둠은 `KeyboardTests`로만 확인한다.)

- 전시 화면이 뜨고 모든 절로 이동. 테마 전환 뒤 재실행 시 설정 유지.
- **실측 대비** [2-2]: 대비 시험 장면을 같은 상태로 두 번 찍는다. 한 번은 글자를 보이게, 한 번은 **측정 대상 글자 요소만** 투명하게 (`--hide-measured-text`: 대비 시험 장면 맨 위 유리의 글자만 개별 투명 브러시로 바꾼다. 공유 브러시를 바꾸지 않아 그 뒤의 글자·그래프는 그대로 있다). 글자 없는 캡처에서 각 측정 글자 요소의 경계 + 4 px 영역을 본다:
  - 픽셀마다 (토큰 글자색, 그 픽셀)의 대비비를 구한다.
  - **칸 검사**: 영역을 글자 높이 크기의 정사각 칸으로 나누고, 칸마다 10백분위가 기준 이상이어야 한다 (칸마다 10%까지는 아크릴 잡음으로 허용).
  - **연결 영역 검사**: 기준 미달 픽셀이 4방향으로 이어진 덩어리 중 12 px를 넘는 것이 있으면 실패 (좁은 그래프 선 같은 연속된 저대비 띠).
  - 영역 전체의 1백분위는 보조 지표로 기록한다. 계산값과 0.5 넘게 다르면 원인을 기록한다.

- **효과 줄이기 표면**: 대비 시험 장면의 배경 무늬를 바꿔 두 번 찍었을 때 유리 표면 안쪽 픽셀이 채널 차이 2 이내.

## 9. 대안

- **XAML `ThemeResource` + `RequestedTheme`**: 같은 찍기·클립 방식과 조합할 수는 있다. 고르지 않은 이유는 성능보다 **연결 비용**이다: 이 앱은 화면을 코드로 만들고, 재질(아크릴 틴트)과 그래프 색까지 한 곳에서 바꿔야 하는데, 테마 사전은 코드에서 만든 브러시·Composition 객체를 다시 찾아 갱신하는 경로가 따로 필요하다. 공유 브러시 하나로 XAML 템플릿(`{StaticResource}`로 같은 브러시 참조)과 코드 양쪽을 덮는다.
- **장면 두 벌 (M0 방식)**: 83 ms 멈칫과 메모리 증가를 관측했다.
- **Win2D로 구멍 뚫린 마스크**: 새 런타임 의존성 (사용자 승인 필요). 원형 클립의 위아래를 바꿔 같은 효과를 낸다.
- **시스템 백드롭(Mica, 바탕화면 아크릴)**: 창 뒤 바탕화면이 비쳐 배경 범위를 통제할 수 없다 (4.3 계산이 성립하지 않음).
